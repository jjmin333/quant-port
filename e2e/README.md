# quant-port 테스트 스위트

API 계층 테스트 + **브라우저를 반드시 거쳐야 하는** 시나리오의 E2E. 둘 다
Playwright로 돌지만 목적이 다르다.

| 프로젝트 | 위치 | 브라우저 | 무엇을 검증하나 |
|---|---|---|---|
| `api` | `tests/api/` | 안 씀 | 인가 경계, 소유권, 회계 규칙, 동결 계약, 응답 형태 |
| `ui` | `tests/ui/` | Chromium | HttpOnly 쿠키 세션, 클라이언트 분기, 자동완성 폼 |

**같은 것을 두 번 돌지 않는다.** 예를 들어 "관리자 API는 403" 은 `api`에서만,
"관리자 메뉴가 안 보인다" 는 `ui`에서만 본다. UI 테스트도 저장 결과는 화면이
아니라 API로 확인한다 — "추가했습니다" 문구는 저장의 증거가 아니다.

## 돌리기

스택이 떠 있어야 한다. 이 스위트는 서버를 직접 띄우지 않는다 (BE는 Docker로만
올리고, dev 서버는 켠 사람 모르게 죽이지 않는다는 프로젝트 규칙 때문).

```bash
cd be && ./scripts/restart.ps1 -Background
```

```bash
cd fe && npm run dev
```

```bash
cd e2e && npm install && npx playwright install chromium
```

```bash
cd e2e && npm test
```

| 명령 | 하는 일 |
|---|---|
| `npm test` | 전부 |
| `npm run test:api` | API 계층만 (FE 없이도 됨) |
| `npm run test:ui` | 브라우저 시나리오만 |
| `npm run test:headed` | 브라우저를 보면서 |
| `npm run report` | 마지막 실행의 HTML 리포트 |

### 환경변수

| 이름 | 기본값 | 용도 |
|---|---|---|
| `E2E_API_URL` | `http://localhost:8080` | BE 오리진 |
| `E2E_FE_URL` | `http://localhost:3000` | FE 오리진 |
| `E2E_WORKERS` | `2` | 병렬 워커 (아래 레이트 리밋 항목 참고) |

| `E2E_ALLOW_BATCH_TRIGGER` | 없음 | `1`이면 **실제 배치를 한 번 돌린다** |

## 설계 결정

### 테스트 1개 = 계정 1개

격리 때문만이 아니다. 이 도메인의 규칙 상당수가 **계정 단위 쿨다운·상한**이다 —
리서치 콜은 하루 5건에 같은 심볼 30일, 스탬프는 심볼당 5분. 계정을 재사용하면
두 번째 실행부터 "규칙 때문에" 실패하고, 그건 회귀가 아니라 픽스처 문제다.

대가는 아래 **정리 전략**에 적었다.

### 정리 전략

각 테스트가 끝나면 `TestUser.cleanup()`이 자기가 만든 것을 되돌린다.

| 자원 | 처리 |
|---|---|
| 스탬프 · 목표가 · 메모 · 관심종목 · 매매 · 보유 | DELETE API로 삭제 |
| 현금 잔고 | 0으로 되돌림 |
| 리서치 콜 | **비공개로 전환** — 콜은 설계상 삭제할 수 없다 |
| 세션 | 로그아웃 (refresh 토큰 행 제거) |
| **계정** | **지울 수 없다** — 아래 참고 |

계정 삭제 API가 없고, 관리자 DB 콘솔에서도 `users`는 read-only다. 그래서 테스트
계정은 쌓인다. 회수는 `scripts/cleanup.sql`로 한다 (이메일 접두사
`qa-e2e-…@quant-port.test` 기준).

```bash
mysql -u quantport -p quantport < e2e/scripts/cleanup.sql
```

정리 실패는 던지지 않고 경고만 남긴다. 정리 중 오류로 테스트가 빨개지면 진짜
실패와 구분이 안 된다.

### 임의의 대기를 쓰지 않는다

`waitForTimeout`이 한 군데도 없다. 대신:

- **하이드레이션 대기** (`src/ui.ts`) — 로그인 폼은 SSR 마크업이 먼저 눌리면
  React가 붙기 전이라 `preventDefault`가 없고, 브라우저가 폼을 그대로 GET
  전송해 버린다(실측: `/login` → `/login?`, 입력값 소실). 그래서 "React가 이
  폼에 props를 붙였는가"를 `waitForFunction`으로 기다린다. 기다리는 조건이
  정확히 무엇인지 알고 있으므로 sleep이 아니다.
- **요소 가시성** — 클라이언트에서만 그려지는 영역(보유 화면의 사이드 레일)은
  요소가 보인다는 사실 자체가 "React도 붙었고 데이터도 왔다"는 뜻이라
  `expect(...).toBeVisible()`로 충분하다.
- **429 백오프** (`src/api-client.ts`) — 서버가 보낸 신호에 따르는 것이지
  시간을 어림잡는 것이 아니다. 상한을 넘기면 그대로 실패로 드러난다.

`networkidle`은 쓰지 않는다 — 이 앱은 시세를 계속 폴링해서 그 상태가 오지 않는다.

### 결정적 데이터

- 수량·단가·날짜는 `src/data.ts`에 모아 두고 기대값을 손으로 검산해 주석에 남겼다.
  (매수 10@100 → 매수 10@200 → 평단 150 → 20주 매도 시 실현 3000)
- 계정 이메일은 UUID를 붙인다. 타임스탬프만 쓰면 같은 초에 시작한 두 워커가
  충돌한다.
- 날짜를 테스트가 계산하지 않는다. 매수일은 **화면이 들고 있는 값을 읽어**
  기대값으로 쓴다 — 자정 경계에서 어긋나지 않고, 덤으로 "화면에 보인 날짜로
  저장된다"까지 검증된다.

## flaky 가능성이 있는 곳

정직하게 적어 둔다. 지금은 통과하지만 조건이 바뀌면 흔들릴 수 있는 지점들이다.

| # | 위치 | 왜 흔들릴 수 있나 | 완화 |
|---|---|---|---|
| 0 | **스택 재기동 직후** | API가 방금 뜨면 `/health`는 바로 200인데 캐시는 비어 있다. 실측: 컨테이너가 08:25:50 KST에 재기동한 직후 회차에서 **8건 무더기 실패**, 같은 창에서 `/indices/scores`·`/news/domestic/briefing`이 500. 워밍업 뒤 12회 연속 통과 | `global-setup`이 `/health`가 아니라 **`/ready`(MySQL·Redis 실검사)** 까지 확인하고, 안 되면 "아직 준비되지 않았습니다"로 죽는다 |
| 1 | 계정 생성 전반 | BE 레이트 리밋이 **비로그인 요청을 IP당 30 req/s(버스트 60)** 로 센다. `/auth/*`는 언제나 IP 버킷이다. 실측: 2워커 = 429 0건 / 6워커 = `/auth/signup`·`/auth/me`·`/auth/logout`에서 다수 발생(전부 첫 250ms 재시도로 회복) | 워커 기본 2, `Api.send`의 429 백오프 + **재시도할 때마다 경고 로그**. 그래도 나면 `E2E_WORKERS=1` |
| 2 | 스탬프 · 리서치 발행 | 발행 시점에 **실서비스 시세·점수·뉴스 스냅샷**을 모은다. 외부 시세가 느리면 타임아웃 | 테스트 타임아웃 60초, 하루 한도 테스트는 180초 |
| 3 | `global-setup` 종목 확인 | 카탈로그·시세가 비면 스탬프/발행이 "가격 없음"으로 실패 | 부팅 시 6종목 시세를 먼저 확인하고 명확한 메시지로 죽는다 |
| 4 | `LLM 지출 경계` (admin) | 조회 전후로 LLM 사용량을 비교하는데, 그 사이에 **스케줄 배치가 돌면** 카운터가 오른다 | 확률은 낮다. 실패하면 배치 이력(`/admin/batch/jobs`)을 먼저 확인할 것 |
| 5 | 샘플 데이터 비교 | 응답에 실시간 시세 파생 필드가 섞여 있어 전체 비교는 항상 깨진다 | 픽스처 소유 필드만 골라 비교 (`SAMPLE_STABLE_FIELDS`) |
| 6 | `src/ui.ts`의 `__reactProps$` | React 내부 속성 이름에 기댄다. React가 바꾸면 깨진다 | 깨지면 이 함수 하나만 고치면 된다 |
| 7 | 반응형 중복 마크업 | 모바일/데스크톱 변형이 같은 이름의 버튼을 2~4개 만든다. `.first()`는 숨은 쪽을 집을 수 있다 | `.filter({ visible: true })` 또는 `main` 스코프 |
| 8 | `next dev` 첫 진입 | 라우트를 요청 시점에 컴파일해 첫 `goto`가 수 초 걸린다 | 네비게이션 타임아웃 30초. 프로덕션 빌드에는 없는 문제 |

| 항목 | 이유 |
|---|---|
| **관리자 콘솔 스펙 11개** | `E2E_ADMIN_EMAIL`/`PASSWORD` 없이는 skip된다. 테스트가 관리자 계정을 만들지 않는 것은 의도다 — BE는 `model.DefaultAdminEmail`과 같은 이메일로 가입하면 그 계정을 관리자로 만들기 때문에, 테스트가 가입을 시도하면 실제 관리자 계정을 만들어 버린다. **자격증명이 있는 환경에서 최초 1회 확인이 필요하다.** |
| 스탬프 예측 **잠금**(생성 5분 후) | 5분을 기다려야 한다. sleep 금지 원칙과 충돌하므로 여기서는 안 다룬다 — Go 단위 테스트(시계 주입)가 맞는 자리다 |
| 리서치 **판정** 전이 | 저장된 일별 종가가 있어야 하고 배치를 돌려야 한다. `internal/service/research_performance_test.go`가 이미 규칙을 검증한다 |
| 공개 발행 **시총 하한** | 시총 미달 종목이 카탈로그에 있다는 보장이 없어 데이터 의존이 너무 크다 |
| 스크린샷 임포트(OCR) | Tesseract와 실제 이미지가 필요하다. 파싱은 `internal/import/**` 테스트가 두텁게 덮고 있다 |

## 고쳐진 결함 (2026-08-23) — 지금은 전부 정상 회귀 테스트

아래 넷은 이 스위트가 찾아낸 제품 결함이고, **전부 수정됐다.** 당시에는
`test.fail()`(당위) + 「현상 고정」 짝으로 열어 두었고, 고친 뒤 짝을 걷어내고
정상 통과 테스트로 뒤집었다. 지금 스위트에 `test.fail()`은 하나도 없다.

| # | 결함 | 고친 곳 | 지키는 테스트 |
|---|---|---|---|
| 1 | 예시를 꺼도 예시 데이터가 화면에 남음 | `common/sample-mode.tsx`, `holdings/holdings-page-client.tsx` | `ui/logged-out-sample.spec.ts`, `ui/sample-mode-screens.spec.ts` |
| 2 | 예시 화면이 `/user/price-targets` 호출 (401) | `lib/price-targets.ts`, `holdings/holdings-side-rail.tsx` | 위 두 파일의 "사용자 데이터 API를 부르지 않는다" |
| 3 | 표시명 상한이 글자가 아니라 바이트 | `service/auth.go` | `api/auth-session.spec.ts` |
| 4 | 검증 실패 4곳이 502 | `service/invalid_input.go` 외 | `api/contract.spec.ts` |

`ui/sample-mode-screens.spec.ts`는 **결함 2가 홀딩스만이 아니라 `/journal`·
`/targets`에도 있었다는 것을 잡아낸 파일**이다. 예시 모드 훅을 다섯 화면이
공유하므로, 한 화면만 고치고 넘어가면 나머지가 조용히 남는다.

## 이전 문서: 알려진 결함을 여는 방식

둘 다 `tests/ui/logged-out-sample.spec.ts`에 있고, 각각 **두 개의 테스트**로
표현했다.

| 테스트 | 지금 상태 | 언제 알려 주나 |
|---|---|---|
| **당위** (`test.fail()`) | 실패해야 통과 | 결함이 고쳐지면 "통과해 버려서" 빨개진다 |
| **[현상 고정]** (통과) | 지금의 잘못된 사실을 못 박음 | 증상의 **모양이 바뀌면** 빨개진다 |

짝으로 두는 이유: `test.fail()`은 "실패했다"만 보고 **왜** 실패했는지는 보지
않는다. 엉뚱한 이유로 깨져도 계속 초록으로 남는 구멍이 있어서, 현상 고정
테스트가 그 구멍을 막는다. **당위 테스트의 단언은 절대 약화하지 않는다** — 그게
회귀 테스트의 본체다. 고칠 때는 두 테스트를 함께 지우거나 뒤집으면 된다.

1. **예시를 꺼도 예시 데이터가 화면에 남는다.**
   비로그인으로 「예시 끄기」를 누르면 `?sample=1`과 「예시 데이터를 보고
   있습니다」 띠는 사라지는데 본문은 예시 포트폴리오를 계속 그린다. 방문자가 남의
   숫자를 아무 표시 없이 자기 것으로 읽게 된다.
   계측해 보면 토글 직후 `/user/holdings`·`/user/cash-balances`·
   `/user/holdings/valuation`을 실제로 다시 부르고 전부 401을 받는데, **실패한
   응답이 기존 상태를 지우지 않아** 직전 예시 데이터가 남는다.
2. **예시 화면이 `/user/price-targets`를 부른다.**
   사이드 레일 목표가 카드가 쓰는 `usePriceTargets()`가 모듈 싱글턴 스토어라
   (`lib/price-targets.ts`) 구독하는 순간 조건 없이 서버를 읽는다 — 예시 모드도
   세션도 보지 않는다. **같은 기능의 올바른 구현이 이미 있다**:
   `targets-client.tsx`는 `/sample/price-targets` 픽스처로 갈라 읽고 실데이터
   fetch를 `if (sample || !session) return;`으로 막는다.

3. **표시명 길이 상한이 글자가 아니라 바이트다.** — `tests/api/auth-session.spec.ts`.
   `service.validateDisplayName`이 하한은 `len([]rune(name)) < 2`(글자), 상한은
   `len(name) > 100`(바이트)로 잰다. 한글은 3바이트라 실질 상한이 33자인데,
   에러 메시지는 "2-100 characters"라 하고 가입 폼은 `maxLength={100}`으로 100자를
   받는다. 실측 경계: 한글 33자(99B) 통과 / 34자(102B) 거부 / ASCII 100자 통과.
4. **일부 검증 실패가 4xx가 아니라 502로 나간다.** — `tests/api/contract.spec.ts`.
   `writeServiceError`가 못 알아본 에러가 `writeTossError`의 기본 분기(502)로
   떨어진다. 검증 실패 6곳 중 2곳(`PUT /user/cash-balances` 음수,
   `POST /research/calls` 빈 심볼)이 여기 해당한다. 사용자 오타가 5xx 알람을
   울리고, 클라이언트는 재시도할 문제와 고쳐 보낼 문제를 구분하지 못한다.

결함 4번 옆에는 **상태코드와 무관한 진짜 불변식**("거부됐으면 상태가 안 바뀐다")을
따로 두었다. 502가 400으로 고쳐져도 그 단언은 그대로 성립한다.
