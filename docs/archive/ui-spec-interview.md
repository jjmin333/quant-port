## 인터뷰 이전에 이미 확정돼 있던 것

설계 인터뷰에서 **다시 묻지 않는다**. 바꾸려면 명시적으로 뒤집어야 한다.

- **shadcn/ui 기반 리디자인**, 최종 목표는 shadcn 기본 스타일(neutral 팔레트 · 기본 여백) — 2026-08-10 결정
- **손익 색은 한국식**: 상승 빨강(`--profit`), 하락 파랑(`--loss`). shadcn 팔레트에 흡수하지 않는다
- **브랜드 색 토큰은 `--brand`** (옛 `--accent`. shadcn의 `--accent`는 hover 표면이라 의미가 다름)
- 교체하지 않는 영역: lightweight-charts 터미널, recharts, 자체 마크다운 파서/렌더러/에디터
- 폰트: 본문 Pretendard Variable / 숫자 Geist Mono

## 결정 기록

### D1. 앱 셸 = 좌측 사이드바 유지

**결정**: 좌측 세로 사이드바 + 우측 본문 구조를 유지한다. (대안이던 상단 가로 메뉴, 아이콘 레일+2차 사이드바는 채택하지 않음)

**근거**: 메뉴가 7그룹 22항목이라 상단 가로 메뉴로는 한 번에 하나의 그룹만 보이게 되고, 매일 여러 화면을 오가는 도구에서 이동 비용이 커진다. 아이콘 레일 방식은 관리자 메뉴를 숨기기엔 좋으나 2클릭 메뉴가 생기고 구현 비용이 가장 크다.

**영향**: `components/layout/app-shell.tsx`·`sidebar.tsx`의 골격 유지. 3단계에서 shadcn sidebar 블록으로 교체할 때 `--sidebar-width` 이름 충돌 정리 필요.

### D2. 헤더는 화면 전체 폭 — 사이드바는 그 아래에서 시작

**결정**: 현재 구조 유지. 헤더가 화면 맨 위를 가로지르고(`h-16`), 사이드바는 헤더 아래에서 시작한다. 로고는 헤더 왼쪽. (대안이던 "세로 관통 사이드바 + 본문 위에만 헤더" 방식은 채택하지 않음)

**근거**: 검색·알림·계정이 사이드바 상태나 화면 폭과 무관하게 **항상 같은 좌표**에 있는 것을 우선했다. 매일 여러 화면을 오가는 도구에서 근육 기억의 값어치가 크다.

**미해결**: 이 배치에서 터미널형 화면의 세로 공간을 어떻게 확보할지는 영역 5에서 다시 다룬다.

**대가(감수하기로 한 것)**:
- 사이드바를 접어도 상단 64px은 그대로 소모된다 — 터미널형 화면의 세로 공간 압박은 남는다
- shadcn sidebar 블록을 그대로 쓸 수 없다. 블록에서 사이드바 부분만 취하고 헤더는 셸 바깥에 유지해야 하므로 3단계 구현량이 늘어난다. **블록의 접기 상태 관리·모바일 Sheet·단축키는 살리되 배치만 현재 구조에 맞춘다**

## 영역 2 — Header

### D3. 검색은 헤더 입력창 + 인라인 자동완성만 — 커맨드 팔레트는 넣지 않는다

**결정**: 현재의 헤더 검색 입력창과 인라인 자동완성 드롭다운을 유지한다. 내부 구현만 shadcn `Command`로 다시 만들어 키보드 이동·하이라이트·접근성(`role="listbox"`/`aria-activedescendant`)을 정식으로 갖춘다. **⌘K 커맨드 팔레트는 도입하지 않는다.**

**근거 — 처음 제시한 근거가 사실과 달라 뒤집은 결정이다**:
초안에서 "사이드바에 없는 화면 6종의 진입 경로를 팔레트가 메운다"고 했으나, 실제로는 그 화면들이 **숨겨진 기능이 아니라 아직 없는 기능**이었다.
- `/quotes`·`/financials`·`/calendar`·`/disclosures`·`/ai-analysis` → `lib/page-stubs.tsx`의 "준비 중" 안내 페이지
- `/onboarding/link-broker`·`/transactions`·`/portfolio`·`/risk`·`/backtest` → `ACCOUNT_FEATURES_VISIBLE = false`로 의도적으로 꺼둔 기능. URL 직접 진입도 미들웨어가 리다이렉트
- 검색으로만 도달하는 실제 화면은 **종목 상세 하나**이며, 그것은 원래 그렇게 설계된 것

따라서 팔레트의 IA 보완재 역할이 성립하지 않는다. 남는 이득은 "종목을 자주 오갈 때 마우스를 안 써도 된다" 하나인데, **사용 패턴을 아직 확인하지 못했다**(영역 5 이전에 확인할 것).

**보류이지 폐기가 아니다**: shadcn `Command`는 나중에 붙여도 비용이 거의 같다. 종목 이동 빈도가 높다는 게 확인되면 그때 `⌘K`를 얹는다.

**같이 경계할 것**: 팔레트는 IA 문제를 덮는 도구로 쓰이기 쉽다. "메뉴가 복잡해도 ⌘K로 가면 된다"가 되는 순간 메뉴 정리를 안 하게 된다.

### D4. 헤더 우측은 계정 아바타 드롭다운 하나로 통합

**결정**: 헤더 우측의 아이콘 3개(알림 🔔 · 설정 ⚙ · 계정)를 **계정 아바타 하나**로 합친다. 드롭다운(shadcn `DropdownMenu`) 안에 사용자 이름/이메일 · 설정 · 로그아웃을 넣는다.

**근거**:
- 알림 버튼은 **미구현**이다. 배지 숫자 `3`이 `header.tsx`에 하드코딩돼 있고 클릭해도 아무 동작이 없다. 동작하지 않는 버튼을 상시 노출하면 "미완성"이라는 신호를 계속 보낸다 → **실제로 만들 때 다시 넣는다**
- 설정 진입점이 헤더 ⚙ 와 사이드바 하단 두 곳으로 중복돼 있었다. 사이드바 쪽을 정식 진입점으로 두고 헤더에서는 드롭다운 안으로 넣는다
- 부수 효과로 검색 입력창이 쓸 수 있는 가로 폭이 늘어난다

**구현 메모**: 현재 계정 메뉴는 `group-hover` + `invisible/opacity` CSS로 열린다 — 키보드로 열 수 없고 포커스 트랩도 없다. shadcn `DropdownMenu`로 바꾸면 이 문제가 함께 해소된다.

### D5. 헤더 높이 56px, 모든 화면 동일

**결정**: 헤더 높이를 `h-16`(64px) → **56px**로 줄이고, 화면 종류와 무관하게 항상 같은 높이를 유지한다.

**근거**: shadcn 기본 컨트롤 높이가 36px이라 64px 헤더 안이 헐거워진다. 화면별로 높이를 다르게 하는 안(터미널 48px)은 얻는 8~16px보다 **화면 전환 시 헤더가 출렁이는 불편**이 커서 채택하지 않았다.

**헤더 최종 구성**:

```
[☰]  ◆ QUANT PORT   [🔍 종목 검색 ─────────]                    Ⓙ▾
 56px 고정 · 전체 폭 · 하단 border · 본문만 스크롤되므로 항상 고정
```

**영역 2에서 미뤄둔 것**: 모바일에서의 헤더 구성(로고 축약·검색 접기)은 영역 10(반응형)에서, 로고 표현은 영역 12(디자인 시스템)에서 다룬다.

## 영역 3 — Sidebar / Navigation

### D6. 메뉴 그룹은 현행 유지 (핵심 · 계좌 · 분석 · 뉴스 · 리포트 · 기록 · 관리)

**결정**: 그룹 구성과 라벨을 지금 그대로 둔다. (대안이던 "투자 / 내 기록 2그룹 축약", "라벨 없이 구분선"은 채택하지 않음)

**감수하기로 한 것**: 일반 사용자에게는 「리포트」가 항목 1개, 「뉴스」가 2개짜리 그룹으로 보인다. 기능 게이팅이 풀려 계좌·분석·백테스트가 켜지면 그룹당 항목 수가 고르게 차므로, **현행 구조는 기능이 모두 켜진 상태를 기준으로 한 것**이라고 이해한다.

### D7. 접으면 48px 아이콘 레일이 남고, 접힘 상태를 기억한다

**결정**: 펼침 220px ↔ 접힘 **48px 아이콘 레일**. 접힌 상태에서도 아이콘 클릭으로 이동할 수 있고, hover 시 메뉴 이름을 툴팁으로 보여준다. (대안이던 "완전히 숨김"은 화면 이동 시 클릭이 한 번 더 드는 비용이 커서 채택하지 않음)

**44px → 48px로 넓히는 이유**: shadcn 아이콘 버튼이 36px이라 44px 안에서는 좌우 여백이 4px씩밖에 남지 않는다.

**접힘 상태 저장 (신규)**: 현재는 `app-shell.tsx`가 `matchMedia("(min-width: 1024px)")` 결과로 매번 초기화해서 **새로고침하면 접어둔 게 풀린다**. 앞으로는 사용자가 직접 토글한 값을 저장하고(쿠키 또는 기존 `quant-port-preferences`), 저장값이 없을 때만 화면 폭으로 판단한다.

### D8. 사이드바는 본문보다 한 단 물러난 색 + 활성 표시는 중립 강조

**결정**
- **배경**: shadcn `--sidebar` 토큰 기본값을 그대로 쓴다. 라이트에서는 본문보다 살짝 어둡고(#F5F5F5 vs #FFFFFF), 다크에서는 살짝 밝다(#343434 vs #252525). 사이드바가 틀로 물러나고 본문이 앞으로 나온다
- **활성 메뉴**: 브랜드 파랑 배경(`--brand-muted` + `--brand` 글자) → **중립 강조**(`--sidebar-accent` 배경 + 진한 글자)로 바꾼다

**활성 표시를 중립으로 바꾸는 이유**: 이 앱에서 **파랑은 하락을 뜻한다**(`--loss`). 네비게이션이 상시 파란 블록을 띄우면 손익 색과 의미가 겹친다. 화면에서 색이 튀는 곳을 **숫자(손익)로 한정**하는 것이 금융 화면의 기본이다.

**실측 메모**: 라이트 모드에서 A(물러남)와 C(같은 색+선)는 shadcn 기본값 차이가 미세해서 육안 구분이 거의 안 된다. 차이는 **다크 계열 테마에서 드러난다** — 이 앱은 어두운 테마가 2종(dark·midnight)이라 그쪽에서 의미가 있다.

## 영역 4 — 페이지 헤더 & 컨텐츠 컬럼

### (재확인) 컬럼 폭 아케타입은 변경하지 않는다

`reading` = `min(72rem, max(42rem, 68%))` / `wide` = `100%`. 2026-08-09 세션에서 폭 통일을 두 번 시도했다가 모두 되돌린 끝에 확정된 사항이라 이번 인터뷰에서 다시 묻지 않았다. `PageHeader`와 페이지 본문이 **같은 아케타입 값을 넘겨야 한다**는 제약도 그대로다.

### D9. 페이지 헤더에 우측 동작 영역을 만든다

**결정**: `PageHeader`를 `제목 + 부제` (좌) / `동작 버튼` (우) 한 줄 구조로 확장한다. 좁은 화면에서는 버튼이 아랫줄로 내려가되 우측 정렬을 유지한다.

**근거**: 지금 `PageHeader`는 `title` / `subtitle`만 받아서 동작 버튼을 둘 자리가 없다. 그래서 각 페이지가 본문 최상단에 제각기 버튼 줄을 만들고 있고 — 리포트 목록의 필터·정렬, 관심종목 추가, 관리자 실행 버튼이 서로 다른 위치에 있다. 고정 자리를 주면 이 편차가 사라진다.

**탭은 헤더에 붙이지 않는다**: 뉴스(국내/해외)·리포트(전체/내 리포트)처럼 탭이 필요한 화면이 2~3개뿐이라, 탭 유무로 헤더 높이가 갈리는 비용이 더 크다. 탭은 본문 최상단에 둔다. 탭 화면이 늘어나면 그때 헤더로 승격을 재검토한다.

## 밀도 (전 화면 공통)

### D10. 촘촘한 밀도로 간다 — shadcn 기본값보다 조밀하게

**결정**: 목업(`docs/mockups/shadcn-shell-v2.html`)의 **「촘촘」** 쪽을 채택한다. 화면 성격별로 밀도를 나누는 절충안은 채택하지 않고 **전 화면 동일**하게 간다.

| 항목 | 값 | shadcn 기본 |
|---|---|---|
| 리스트/표 행 높이 | **30px** | 40px |
| 본문 기본 글자 | **12px** | 14px |
| 보조 글자 | **11px** | 12px |
| 카드 패딩 | **10px** | 16px |
| 요소 간격 | **8px** | 12px |

**효과**: 마켓 레이더 한 화면에 약 20종목(여유 밀도는 14종목).

**구현 방식**: shadcn 컴포넌트를 복사한 뒤 기본 size 변형의 값을 이 표에 맞춰 **한 번만** 조정한다. 호출부마다 `className`으로 조이지 않는다 — 그렇게 하면 밀도가 컴포넌트가 아니라 호출부에 흩어져 다음에 바꿀 수 없게 된다.

**한 가지 예외 가정 (거부 가능)**: 투자 리포트 **본문 마크다운**처럼 긴 산문을 읽는 영역은 12px로 두면 읽기가 어렵다. UI 밀도(행·버튼·간격)는 촘촘하게 가되, **긴 산문 본문의 글자 크기와 행간만** 읽기용으로 유지하는 것을 전제로 진행한다. 이 가정이 틀리면 영역 6에서 바로잡는다.

## 영역 5 — 터미널형 화면 (마켓 레이더 · 종목 워크스페이스)

> 참고: 「실시간 시세」(`/quotes`)는 아직 `page-stubs`의 준비 중 화면이다. 실제로 존재하는 터미널형 화면은 **마켓 레이더**와 **종목 워크스페이스** 둘이다.

### D11. 리스트 폭은 좁게 / 보통 / 넓게 3단 전환

**결정**: 리스트와 작업 영역 사이의 폭을 **버튼으로 3단계** 오간다. 드래그 리사이즈는 도입하지 않는다.

| 단계 | 리스트에 보이는 것 |
|---|---|
| 좁게 | 종목명 · 등락률 |
| 보통 | + 현재가 |
| 넓게 | + 거래대금 · 점수 |

**근거**: 밀도를 촘촘(D10)으로 잡으면 리스트에 컬럼을 더 넣고 싶어지고, 그러면 폭 조절 요구가 실제로 생긴다. 드래그(대안 B)는 자유롭지만 "매번 폭을 맞추는 일"을 사용자에게 떠넘기고, 화면이 여럿이라 저장·복원 대상도 그만큼 늘어난다. 3단은 그 이득의 대부분을 가져가면서 **어느 폭이 쓸모있는지 우리가 미리 정해둘 수 있다.**

**유지**: 기존 접기 토글은 「좁게」보다 더 접는 상태로 남긴다. 선택한 단계는 화면별로 기억한다.

### D12. 종목 워크스페이스 탭 9개는 한 줄 가로 스크롤 유지 + 스크롤 신호 추가

**결정**: 현재의 `overflow-x-auto` 한 줄 탭 바를 그대로 둔다. 데스크탑에서는 9개가 한 줄에 다 보이고, 좁은 화면에서는 지금처럼 가로 스크롤한다. (「주요 탭 + 더보기」, 「좌측 세로 탭」은 채택하지 않음)

**근거**: 9개 탭은 **같은 종목을 여러 각도로 보는 것**이라 위계를 매기기 어렵다 — 「주요 5개」를 고르는 순간 나머지는 사용이 급감하는데, 그 5개를 정당화할 근거가 없다. 좌측 세로 탭은 이 화면에 이미 있는 지표 레일 위에 세로 띠를 하나 더 얹는다(사이드바 + 지표 레일 + 탭 = 3개).

**추가할 것 — 스크롤 신호**: 지금은 좁은 화면에서 오른쪽에 탭이 더 있다는 걸 알 방법이 없다(스크롤바가 `scrollbar-thin`이라 눈에 띄지 않는다). **가장자리 페이드 + 화살표 버튼**을 넣는다. 활성 탭 자동 스크롤(`tab-bar` 의 기존 `useEffect`)은 유지한다.

### D12-a. 활성 표시는 전 화면 공통으로 중립 (규칙)

D8에서 사이드바에 정한 규칙을 **탭·칩·세그먼트 등 모든 선택 상태에 동일 적용**한다. 현재 탭 바는 브랜드 파랑 밑줄 + 파란 글씨인데 → **진한 글자 + 중립 밑줄**로 바꾼다. 이유는 D8과 같다: 파랑은 이 앱에서 하락을 뜻하므로, 색이 튀는 곳을 숫자로 한정한다.

## 영역 6 — 문서형 화면 (뉴스 · 투자 리포트)

### D13. 목록 형태는 콘텐츠 성격을 따른다 — 뉴스는 행, 리포트는 카드

**결정**: 겉보기 통일을 위해 목록 형태를 맞추지 않는다.
- **뉴스** = 한 줄 행(제목 + 매체 배지 + 시각). 뉴스 제목은 그 자체로 완결된 정보라 발췌가 불필요하다
- **투자 리포트** = 발췌가 있는 카드. 제목("현대차 — 실적은 좋은데 사지 않는 이유")만으로는 읽을지 판단할 수 없고, 논거를 보고 고르는 글이다

**촘촘 밀도 적용**: 리포트 카드의 발췌를 **2줄 → 1줄**로 줄인다. 한 화면에 3개 → 5개.

## 영역 11 — 테마

### D14. 테마는 라이트 + 다크 2종만

**결정**: `light` / `dark` 두 벌만 유지한다. **`midnight`(푸른 남색 계열)을 없앤다.** 시스템 설정 자동 감지는 넣지 않고 사용자가 직접 고른다.

**근거**: 미드나잇은 shadcn 팔레트에 없는 색이라 토큰 30개를 손으로 조율하고 계속 따로 관리해야 한다. 무엇보다 **앞으로 모든 색 결정을 세 번씩 검증**해야 하는데, 화면 수를 생각하면 이 비용이 계속 붙는다.

**같이 바뀌는 것 — 다크의 정체성**: 현재 다크는 `#000000` 순검정인데 shadcn 다크는 중성 회색 `#252525`다. 2종으로 줄이면서 **shadcn 값을 따른다** — 순검정은 사라진다.

**마이그레이션 필요**: `lib/preferences.ts`의 `ColorMode` 타입에서 `midnight` 제거, `normalizeColorMode`가 저장된 `midnight`/`general` 값을 **`dark`로 매핑**해야 한다. 그러지 않으면 기존 사용자의 `localStorage`에 남은 값 때문에 테마가 적용되지 않는다. `globals.css`의 `[data-theme="midnight"]`·`[data-theme="general"]` 블록, 설정 화면의 테마 카드 3장 중 미드나잇 1장, `@custom-variant dark`의 선택자도 함께 정리한다.

## 영역 9 — Modal / Sheet / Toast

### D15. 짧은 것은 가운데 모달, 긴 것은 우측 시트

**결정**

| 용도 | 형태 | shadcn |
|---|---|---|
| 종목 추가 · 목표가 설정 · 스탬프 남기기 | 가운데 모달 | `Dialog` |
| 삭제·실행 확인 | 가운데 모달 (작게) | `AlertDialog` |
| 뉴스 원문 · 긴 상세 | **우측 시트** | `Sheet` |
| 저장됨 / 실패 알림 | 우측 하단 토스트 | `Sonner` |

**시트를 쓰는 이유**: 뉴스는 "하나 읽고 목록으로, 또 하나 읽고 목록으로"가 기본 동선이다. 시트는 **뒤의 목록이 계속 보여서** 다음 기사로 넘어가기 쉽다. 모바일에서는 아래에서 올라오는 형태로 바뀐다.

**토스트는 대안을 두지 않았다** — 우측 하단 짧은 알림 외에 고를 게 없어 인터뷰 항목에서 제외했다.

## 영역 10 — 반응형

### D16. 모바일 표는 중요 3열 + 행 펼치기

**결정**: 좁은 화면에서 표는 **컬럼 3개만 보이고**, 행을 누르면 나머지가 아래로 펼쳐진다. 가로 스크롤(A)·카드 변환(B)은 채택하지 않는다.

**근거 (샘플 실측)**

| 방식 | 한 화면 종목 수 | 종목끼리 비교 |
|---|---|---|
| A 가로 스크롤 | 12개 | 보이는 열만. 밀면 종목명이 잘림 |
| B 카드 | 4개 | 어려움 — 숫자가 세로로 흩어짐 |
| **C 3열 + 펼치기** | **12개** | **쉬움 — 숫자가 세로 정렬됨** |

모바일에서 표를 보는 목적은 대개 **여러 종목을 훑는 것**인데 B는 그 목적을 깨뜨리고, A는 훑을 수는 있어도 "밀었다 돌아왔다"를 반복하게 된다.

**표별 3열 (제안 — 구현 시 확인)**

| 표 | 남길 3열 |
|---|---|
| 관심종목 | 종목 · 현재가 · 등락률 |
| 보유종목 | 종목 · 평가금액 · 수익률 |
| 마켓 레이더 | 종목 · 거래대금 · 등락률 |

펼친 영역은 `라벨 — 값` 두 줄 정렬로, 표의 나머지 컬럼을 순서대로 보여준다.

## 영역 8 — 관리자 화면

### D17. 관리자 화면은 데스크탑 전용

**결정**: 관리자 메뉴 7종(뉴스·API·LLM·점수·배치·캐시·DB 관리)은 **반응형 대상에서 제외**한다. 좁은 화면에서는 "데스크탑에서 열어주세요" 안내를 띄운다.

**근거**: 관리자 표 7종에 각각 3열을 정하고 긴 폼을 모바일용으로 다듬는 작업이 통째로 빠져 **2~4단계 구현량이 눈에 띄게 줄어든다**. 사용자는 사실상 운영자 한 명이고, 표가 크고 위험한 버튼(배치 실행·캐시 삭제·DB 조작)이 있는 화면이다.

**감수하는 것**: 밖에서 배치 결과를 확인하는 것도 안 된다. (절충안이던 "보기는 허용, 조작은 데스크탑"은 채택하지 않음 — 필요해지면 그때 C로 승격한다.)

**적용 방식**: 기존 `data-shell="mobile"`/`"webview"` 감지를 그대로 쓰고, `/admin/*` 라우트에서 안내 화면으로 대체한다.

> ⚠️ **D1의 근거 일부도 같이 정정한다.** "7그룹 22항목"은 관리자 기준이고, 위 기능 게이팅 때문에 **일반 사용자에게 실제로 보이는 메뉴는 10개**다(마켓 레이더·종목 분석·보유종목·관심종목 / 국내·해외 뉴스 / 투자 리포트 / 스탬프·메모장·목표가). 좌측 사이드바라는 결론은 유지하되, "22개라서 상단 메뉴가 불가능하다"는 근거는 더 이상 쓰지 않는다.

## 현재 구현 상태 (설계의 출발점)

인터뷰 중 참고용. 결정이 아니라 **지금 그렇게 돼 있다**는 사실 기록.

```
┌───────────────────────────────────────────────┐  h-16 (64px), full-width
│ [☰] QUANT PORT      [종목 검색]   🔔 ⚙ 계정   │  border-b, bg=--background
├────────┬──────────────────────────────────────┤
│ 핵심   │  PageHeader (page-shell 컬럼)         │
│  마켓  ├──────────────────────────────────────┤
│  분석  │                                      │
│ 계좌   │   본문                                │
│  ...   │   reading = min(72rem, max(42rem,68%))│
│        │   wide    = 100%                     │
│ [설정] │                                      │
└────────┴──────────────────────────────────────┘
 220px / 접으면 44px (아이콘만)
```

- Header는 **전체 폭**을 차지하고 사이드바는 그 아래에서 시작한다
- 사이드바: 열림 220px / 접힘 44px(아이콘). `<1024px`에서는 오버레이 방식으로 전환
- 웹뷰 모드(`data-shell="webview"`)에서는 사이드바를 렌더하지 않는다
- 컨텐츠 컬럼은 아케타입 2종(`reading` / `wide`)이며 헤더와 본문이 같은 클래스를 공유해야 한다

## 영역 14 — 숫자 표현

### D18. 등락은 색 + 부호로만 표시한다

**결정**: `+1,200 / +1.64%` 형태. 화살표(`▲▼`)와 배경 칩은 쓰지 않는다. **부호를 항상 표기한다.**

**근거**: 색맹 사용자에게는 색만으로 방향이 전달되지 않는다 — 한국식 배색(상승 빨강/하락 파랑)은 특히 그렇다. 부호는 색과 무관하게 방향을 알려주면서 화살표보다 폭을 덜 먹어 촘촘 밀도와도 맞는다. 화살표 + 부호를 같이 쓰면 같은 정보가 두 번 들어간다.
