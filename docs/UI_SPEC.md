## 1. Product / Page 목적

여러 증권사 계좌를 하나로 합쳐 보는 **개인 투자 관리 플랫폼**. 단일 목적의 도구가 아니라 성격이 다른 네 덩어리가 한 앱에 들어있고, 이 문서의 규칙 대부분은 그 차이를 어떻게 다룰지에 대한 것이다.

| 성격 | 화면 | 이 화면이 해야 하는 일 |
|---|---|---|
| **터미널형** | 마켓 레이더, 종목 워크스페이스 | 많은 종목을 훑고 변화를 알아채기. **밀도가 곧 기능** |
| **문서형** | 뉴스, 투자 리포트 | 읽을지 말지 고르고, 골랐으면 편히 읽기 |
| **기록형** | 스탬프, 메모장, 목표가 | 남기는 마찰을 낮추고 나중에 결과와 함께 보기 |
| **관리자** | 뉴스·API·LLM·점수·배치·캐시·DB 관리 | 운영자 1인이 데스크탑에서 상태를 보고 조작하기 |

**UI 원칙 세 줄**
1. 화면에서 **색이 튀는 곳은 숫자(손익)뿐**이다. 네비게이션·탭·선택 상태는 전부 중립색을 쓴다
2. **밀도는 컴포넌트가 소유한다.** 호출부에서 `className`으로 조이지 않는다
3. 겉보기 통일보다 **콘텐츠 성격**이 우선이다 (뉴스는 행, 리포트는 카드)

## 2. Information Architecture

사이드바 7그룹. **기능 게이팅(`ACCOUNT_FEATURES_VISIBLE = false`)이 걸린 항목은 일반 사용자에게 보이지 않는다** — 지금 실제로 보이는 것은 10개다.

```
핵심    마켓 레이더 · 종목 분석 · 보유종목 · 관심종목
계좌    계좌 연동🔒 · 거래내역🔒
분석    포트폴리오 분석🔒 · 리스크 분석🔒
뉴스    국내 주식 · 해외 주식
리포트  투자 리포트
기록    스탬프 · 메모장 · 목표가 관리 · 백테스트🔒
관리    뉴스·API·LLM·점수·배치·캐시·DB 관리 (관리자만)
                                          🔒 = 현재 비활성
하단 고정  설정
```

**사이드바에 없는 화면**
- `종목 상세`(`/stocks/[symbol]`) — 검색·목록 링크로만 진입. **의도된 설계**
- `실시간 시세`·`재무제표`·`실적 캘린더`·`공시`·`AI 분석` — `lib/page-stubs.tsx`의 준비 중 화면. 기능이 생기면 사이드바에 넣는다

**커맨드 팔레트(⌘K)는 도입하지 않는다.** 메뉴 10개는 사이드바로 충분하고, 팔레트로 메워야 할 진입 경로 공백이 없다. 종목 이동 빈도가 높다는 게 확인되면 그때 얹는다.

## 3. 전체 Layout

```
┌────────────────────────────────────────────────────────┐
│ ☰  ◆ QUANT PORT   [🔍 종목 검색 ────]              Ⓙ▾ │  56px · 전체 폭
├──────────┬─────────────────────────────────────────────┤
│  핵심     │  페이지 제목                    [동작][동작] │  페이지 헤더
│  ▣ 마켓   │  부제                                       │
│  ▤ 분석   ├─────────────────────────────────────────────┤
│  ...      │                                             │
│           │   본문                                       │
│  [설정]   │   reading = min(72rem, max(42rem, 68%))     │
│           │   wide    = 100%                            │
└──────────┴─────────────────────────────────────────────┘
   220px ↔ 48px
```

- **헤더가 전체 폭을 가로지르고 사이드바는 그 아래에서 시작한다.** 검색·계정이 사이드바 상태나 화면 폭과 무관하게 항상 같은 좌표에 있는 것을 우선했다
- 본문만 스크롤한다(`h-[100dvh]` flex). 헤더·사이드바는 고정
- 컨텐츠 컬럼 아케타입 2종. **`PageHeader`(관리자 화면 전용)와 페이지 본문이 반드시 같은 값을 넘겨야 한다** — 어긋나면 제목 컬럼과 본문 컬럼의 좌우 경계가 달라진다
- ⚠️ 위 그림의 「페이지 제목 / 부제」 줄은 **사용자 화면에는 없다**(2026-09-02, §7). 관리자 화면에만 남아 있다

### ⚠️ 2026-08-11 변경 — 기본 아케타입이 `wide`가 되었다

사용자 결정: **모바일 반응형이 따로 만들어져 있으므로, 데스크탑에서 중앙 컬럼만 쓰던 것을 그만두고 화면 폭을 다 써서 데이터를 더 보여준다.**

- `PageScrollShell` / `PageHeader`의 기본값이 `reading` → **`wide`**
- 거터는 `.page-shell-wide`가 `padding-inline: 0.75rem`으로 가진다. **`PageHeader`가 따로 `px-3`을 얹던 특례는 제거했다** — 거터가 두 겹이 되면 헤더와 본문 경계가 다시 어긋난다
- `reading`은 **긴 산문을 읽는 화면에만 명시적으로** 남긴다: 리포트 상세(`research-detail-client`), 리포트 작성(`research-compose`)
- 실측(1280px): 홈 본문 컬럼 **714px → 1050px**

이 변경으로 이 문서의 "reading이 기본"이라는 전제(아래 §7 포함)는 무효다.

## 4. Header

```
[☰]  ◆ QUANT PORT   [🔍 종목 검색 ─────────]                    Ⓙ▾
```

| 요소 | 규격 |
|---|---|
| 높이 | **56px 고정** (화면 종류와 무관) |
| 사이드바 토글 ☰ | 좌측 끝. 웹뷰 모드에서는 숨김 |
| 로고 | `◆` + `QUANT PORT`. 홈(`/`) 링크 |
| 검색 | 최대 380px, 높이 36px. 인라인 자동완성 |
| 우측 | **계정 아바타 하나** — 드롭다운에 이름/이메일 · 설정 · 로그아웃 |

**알림 🔔 버튼과 설정 ⚙ 아이콘을 제거한다.** 알림은 미구현이고(배지 `3`이 하드코딩), 설정은 사이드바 하단에 이미 있다. 알림은 실제로 만들 때 다시 넣는다.

**계정 메뉴는 shadcn `DropdownMenu`로 교체한다** — 현재는 `group-hover` CSS라 키보드로 열 수 없다.

### ⚠️ 2026-09-02 예외 — 종목 상세에서는 검색 입력줄을 접는다 (v1.2.0)

「화면 종류와 무관하게 같은 헤더」의 **유일한 예외**다. 좁은 화면(`isCompact`)의 헤더는
브랜드 줄 56px 아래에 검색 입력줄 43px을 두는데, 종목 상세는 그 아래에 종목 헤더와
탭바까지 얹혀 본문이 265px(33%)에서 시작했다.

- `HeaderSearchConfig.collapsible`이 켜진 경로에서만 접는다. 지금은 `/stocks/**` 하나
- 입력줄 대신 **돋보기 아이콘**이 서고, 그 자리는 **색상 모드 버튼의 왼쪽**이다 — 색상 모드를 대체하지 않는다
- 펼침 상태도 선택 상태이므로 **중립색**을 쓴다 (§5)
- 화면을 옮기면 다시 접는다. 종목 A에서 펼쳐 둔 줄이 종목 B에서도 펼쳐져 있으면 되찾은 43px이 안 돌아온다
- 「검색은 화면의 기능이 아니라 앱의 기능」이라는 원칙(`lib/header-search-config.ts`)은 그대로다 — **감추는 것이 아니라 접는 것**이다

## 5. Navigation

**검색 (헤더 인라인)**
- 종목 검색 전용. 타이핑하면 아래에 자동완성 목록
- 내부를 shadcn `Command`로 재구현해 키보드 위/아래 이동·하이라이트·`role="listbox"`/`aria-activedescendant`를 정식으로 갖춘다

**활성 상태 규칙 (전 화면 공통)**
> 사이드바 메뉴 · 탭 · 칩 · 세그먼트 등 **모든 선택 상태는 중립색**을 쓴다.
> 배경 `--sidebar-accent` / `--accent` + 진한 글자. **브랜드 파랑을 쓰지 않는다** — 파랑은 이 앱에서 하락(`--loss`)을 뜻한다.

## 6. Sidebar

| 항목 | 값 |
|---|---|
| 펼침 폭 | 220px |
| 접힘 폭 | **48px 아이콘 레일** (기존 44px에서 확대 — shadcn 아이콘 버튼 36px + 좌우 여백) |
| 접힘 상태 | 아이콘 클릭으로 이동 가능, hover 시 이름 툴팁 |
| 배경 | `--sidebar` — 라이트에서 본문보다 어둡고, 다크에서 본문보다 밝다 |
| 그룹 라벨 | 현행 유지 (핵심·계좌·분석·뉴스·리포트·기록·관리) |
| < 1024px | 오버레이(Sheet)로 전환 |
| 웹뷰 모드 | 렌더하지 않음 |

**접힘 상태를 저장한다.** 현재는 `matchMedia`로 매번 초기화돼 새로고침하면 풀린다. 사용자가 직접 토글한 값을 저장하고, 저장값이 없을 때만 화면 폭으로 판단한다.

shadcn sidebar 블록은 **통째로 쓰지 못한다**(블록은 세로 관통 사이드바 전제). 상태 관리·모바일 Sheet·단축키는 가져오되 배치는 위 3절 구조에 맞춘다. 블록이 쓰는 `--sidebar-width`(16rem)와 이 앱의 동명 레이아웃 변수(220px) **이름 충돌을 정리해야 한다.**

## 7. 페이지 헤더 & 컨텐츠

### ⚠️ 2026-09-02 변경 — 사용자 화면에는 페이지 제목 블록을 두지 않는다 (v1.2.0)

제목+부제 블록은 375×812에서 **72~92px**을 썼다. 앱 헤더 99px과 합쳐 홈은 171px(21%),
관심 종목은 191px(24%)이 지나야 본문이 시작됐다. 사용자 결정으로 사용자 화면 15곳에서
걷어냈다. **관리자 화면(`components/admin/*`)은 `PageHeader`를 그대로 쓴다** — 도구 화면이라
세로 여유가 덜 비싸고, 무엇을 관리하는 화면인지 이름이 필요하다.

- 화면 이름은 사이드바의 활성 항목이 말한다. 뉴스·실시간 차트가 v1.1.0부터 이미 그렇게 돌고 있었다
- **제목이 곧 내용인 화면은 본문의 `h1`으로 내린다** — 리포트 상세의 글 제목, 작성자 페이지의 작성자 이름

### 동작 버튼의 자리 — `PageActions`

```
┌─────────────────────────────────────────────────┐
│                                 [필터] [+ 작성] │  본문 첫 줄, 우측
│  본문 …                                         │
└─────────────────────────────────────────────────┘
```

- 헤더를 지운다고 **각 페이지가 알아서 버튼 줄을 만들게 두면 안 된다.** `PageHeader`의 `actions`가 애초에 없애려던 문제(리포트 필터·관심종목 예시·관리자 실행이 화면마다 다른 위치)가 그대로 돌아온다
- `PageActions`(`layout/page-content-shell.tsx`)가 그 한 자리다. `PageScrollShell`의 **첫 자식**, 우측 정렬, 좁으면 아랫줄로
- 넘길 것이 없으면 아무것도 그리지 않는다 — 빈 줄이 12px을 도로 먹으면 헤더를 지운 이유가 절반 사라진다
- **같은 동작을 본문 카드가 이미 들고 있으면 `PageActions`에 두지 않는다.** 비로그인 안내 카드의 「예시로 둘러보기」가 그 예다 — 헤더에 있을 때는 멀어서 안 보이던 중복이, 본문으로 내려오자 40px 간격으로 나란히 섰다
- **탭은 헤더에 붙이지 않는다.** 탭이 필요한 화면이 2~3개뿐이라 탭 유무로 헤더 높이가 갈리는 비용이 더 크다. 본문 최상단에 둔다

## 8. 각 메뉴별 화면

### 8.1 마켓 레이더 · 종목 워크스페이스 (터미널형, `wide`)

**리스트 폭 3단 전환** — 드래그 리사이즈는 도입하지 않는다.

| 단계 | 리스트에 보이는 것 |
|---|---|
| 좁게 | 종목명 · 등락률 |
| 보통 | + 현재가 |
| 넓게 | + 거래대금 · 점수 |

기존 접기 토글은 「좁게」보다 더 접는 상태로 남긴다. 선택한 단계는 화면별로 기억한다.

**종목 워크스페이스 탭 9개**(개요 · AI 분석 · 차트·호가 · 기업 정보 · 밸류에이션 · 재무제표 · 실적 · 내부자 거래 · 뉴스)는 **한 줄 가로 스크롤 유지**. 위계를 매기지 않는다 — 같은 종목을 여러 각도로 보는 것이라 「주요 5개」를 정당화할 근거가 없다.
→ **추가할 것**: 가장자리 페이드 + 화살표 버튼. 지금은 오른쪽에 탭이 더 있다는 걸 알 방법이 없다. 활성 탭 자동 스크롤은 유지.

### 8.0 홈 — 종합 대시보드 (`wide`)

여러 메뉴의 핵심을 한 화면에 모은다(`components/dashboard/dashboard-overview.tsx`).

```
지수 바 (MarketOverview)
┌─ 거래대금 상위 8 ────────────┬─ 오늘의 뉴스 6 ──┐   1280px 미만에서 세로로 쌓임
└─────────────────────────────┴──────────────────┘
┌─ 최신 투자 리포트 4 (카드) ─────────────────────┐
└────────────────────────────────────────────────┘
```

**각 블록은 독립적으로 실패한다.** 마켓 레이더가 죽어도 뉴스는 떠야 하고, 리포트가 401이어도 나머지는 보여야 한다. 블록마다 자기 로딩/빈 상태를 그리고, 하나의 에러가 화면 전체를 비우지 않는다.

랭킹 응답에는 종목명이 없어 `fetchQuotesBatchClient`로 이름을 채운다 — 코드만 보여주면 훑을 수 없다.

### 8.2 뉴스 (문서형, `wide`)

한 줄 행. `제목 + 매체 배지 + 시각`. 발췌를 넣지 않는다 — 뉴스 제목은 그 자체로 완결된 정보다.
원문은 **우측 시트**로 연다(뒤 목록이 계속 보여 다음 기사로 넘어가기 쉽다).

### 8.3 투자 리포트 (문서형, `reading`)

발췌가 있는 카드. 제목만으로는 읽을지 판단할 수 없고 논거를 보고 고르는 글이다.
**발췌는 2줄 → 1줄로 줄인다**(촘촘 밀도). 한 화면에 3개 → 5개.
본문(마크다운)은 **읽기용 글자 크기·행간을 유지한다** — UI 밀도와 별개.

### 8.4 기록형 (스탬프 · 메모장 · 목표가, `reading`)

별도 인터뷰 없이 **위 규칙의 적용**으로 정의한다.
- 목록: 리포트와 같은 카드형(결과·판정이 함께 보여야 하므로)
- 남기기: 짧은 입력 → 가운데 모달
- 상세: 긴 내용 → 우측 시트, 짧으면 인라인 확장

## 14. Design System

### 밀도 (전 화면 공통)

| 항목 | 값 | shadcn 기본 |
|---|---|---|
| 리스트/표 행 높이 | **30px** | 40px |
| 본문 기본 글자 | **12px** (`text-cell`) | 14px |
| 보조 글자 | **11px** (`text-micro`) | 12px |
| 카드 패딩 | **10px** | 16px |
| 요소 간격 | **8px** | 12px |
| 컨트롤 높이 | **32px** | 36px |

→ 마켓 레이더 한 화면에 약 20종목.
**shadcn 컴포넌트의 기본 size 값을 한 번만 조정한다.** 호출부마다 `className`으로 조이면 밀도가 137곳에 흩어져 다음에 못 바꾼다.

### 버튼 (v1.0.1)

**모든 버튼은 `<Button>` 컴포넌트에서 나온다.** 알약 스타일을 손으로 다시 적지 않는다.

| size | 높이 | 글자 | 아이콘 | 쓰는 곳 |
|---|---|---|---|---|
| `xs` | 24px | 12px | 12px | 행 안의 미니 동작 |
| `sm` | **28px** | 12px | **13px** | 헤더 액션·툴바·필터 — 기본으로 이것 |
| 기본 | 32px | 12px | 14px | 폼 제출·주요 동작 |

- **아이콘은 글자보다 한 단 작다.** 반대가 되면 lucide 아이콘마다 다른 획 밀도가 그대로
  버튼의 무게 차이로 보인다 — 종목 헤더의 여섯 개(별·서류가방·과녁…)가 제각각으로 읽히던
  원인이 이것이었다.
- **호출부에서 크기를 덮지 않는다.** `className`으로 넘겨도 되는 것은 **색**뿐이다.
  v1.0.1 이전에는 같은 알약 스타일이 네 벌 복사돼 있었고, 그 결과 한 페이지 안에
  높이가 **24.2 · 26.2 · 28 · 32 · 32.2px 다섯 가지**로 갈렸다(실측 `/reports`).
- 엘리먼트를 바꾸기 어려우면 **최소한 `cn(buttonVariants({ variant, size }), …)`을 쓴다.**
  v1.0.1에서 손으로 쓴 컨트롤 **116곳 중 104곳**을 이 방식으로 옮겼다(구조를 건드리지 않아
  조건부 active 상태와 pill 모양이 그대로 살아 있다). 남은 12곳은 버튼이 아니다 —
  탭·달력 날짜 칸·폼 세그먼트·세로 패딩 없는 칩.
- **패딩으로 높이를 만들지 않는다.** `py-*`는 글자 크기가 바뀌면 높이가 따라 흔들린다.
  계단의 `h-*`가 높이를 고정한다.

### 타이포그래피 (v1.0.0)

**폰트는 Pretendard Variable 한 벌이다.** 숫자도 같은 글꼴을 쓰고 `tabular-nums`로 자릿수를 맞춘다 — 정렬에 필요한 것은 고정폭 *글꼴*이 아니라 고정폭 *숫자*다. 고정폭이 실제로 필요한 자리(관리자 화면의 Redis 키·SQL·컬럼명, 마크다운 `<code>`)만 `font-code`를 쓰고, 그 값은 **OS에 이미 있는 글꼴**이다(웹폰트를 한 벌 더 받지 않는다).

크기는 **`fe/src/app/globals.css`의 `@theme inline` 한 곳**에서 나온다. 다음에 밀도를 손보는 일은 이 일곱 줄을 고치는 일이다.

| 토큰 | 크기 / 행간 | 용도 |
|---|---|---|
| `text-micro` | 11px / 1.35 | 배지·칩·각주·메타 — **하한. 이보다 작게 쓰지 않는다** |
| `text-cell` | 12px / 1.35 | 표 셀·목록 본문·기본 UI |
| `text-note` | 13px / 1.4 | 한 단 강조된 보조 · 위젯(`SectionCard`) 제목 |
| `text-read` | 14px / **1.7** | **읽는 글** — 브리핑·요약·AI 해설·메모 본문 |
| `text-article` | 15px / 1.85 | 문서 본문 — 리포트·기사 원문 |
| `text-section` | 15px / 1.4 | 페이지 섹션 제목(`<h2>`) |
| `text-page` | 19px / 1.35 | 페이지 제목(`PageHeader`) |

숫자 칸은 `font-num`(Pretendard + `tabular-nums`), 코드·식별자는 `font-code`.

**통화 단위는 값보다 한 단 작다** (v1.0.1). `PriceDisplay`·`PriceAmountPlain`·`QuotePrice`가
「원」·「$」를 별도 엘리먼트(`PRICE_UNIT_CLASS` = `0.85em` + `--text-muted`)로 그린다.
단위는 어느 줄에서나 같으므로 정보가 아니다 — 값과 같은 무게로 여덟 번 반복되면 소음이 된다.

- **가격을 화면에 그릴 때는 `formatPrice()` 문자열이 아니라 `<PriceDisplay>`를 쓴다.**
  문자열은 값과 단위를 나눌 수 없어 이 규칙이 닿지 않는다. 표 셀처럼 줄이 이미 크기를
  가진 자리에는 `size="inherit"`.
- `formatPrice()`는 **`title`·`aria-label`·템플릿 리터럴 등 문자열이 필요한 자리 전용**이다.
- **퍼센트(%)는 줄이지 않는다.** 「%」는 「원」과 달리 값의 일부로 읽힌다 — 흐리게 하면
  `−1.85`가 무엇의 −1.85인지 약해진다.

**규칙**

1. **긴 문단에 표 크기를 쓰지 않는다.** 두세 문장이 넘어가면 `text-read`다. 한국어는 같은 px에서 라틴 문자보다 조밀해, 12px 문단은 훑을 수는 있어도 읽히지 않는다.
2. **`text-micro` 아래로 내려가지 않는다.** v1.0.0 이전에는 7~10px가 화면마다 수백 개 있었다.
3. **행간은 `micro`·`cell`·`note`에 1.35~1.4까지만.** 표 안에 서는 글자라 행간이 곧 행 높이다. 필요하면 호출부에서 `leading-*`으로 덮는다(호출부가 이긴다).
4. **`text-sm`(14px) 이상의 Tailwind 기본 계단은 건드리지 않는다.** 버튼·입력·내비의 높이가 그 행간(20px)에 맞춰져 있다.
5. **새 계단을 추가하면 `fe/src/lib/utils.ts`의 `TEXT_SCALE`에도 넣는다.** tailwind-merge는 모르는 `text-*`를 **글자 색으로 분류**해서, `cn("text-새이름 … text-foreground")`처럼 색이 뒤에 오면 크기를 조용히 지운다.
6. **제목 크기는 칸 폭이 허락하는 만큼만 올린다.** 위젯 제목을 15px로 올렸다가 좁은 홈 칸에서 「AI 추천 랭킹 TOP」이 네 줄로 접힌 전례가 있다.
7. **캔버스·SVG 글자는 CSS를 상속받지 않는다.** lightweight-charts는 `layout.fontFamily`를, recharts는 `tick={{ fontSize }}`를 따로 준다.

실물 견본: `/dev/typography`

### 숫자 표현

```
74,300              41,250
+1,200   +1.64%     -750   -1.79%
```

- **색 + 부호.** 화살표(`▲▼`)와 배경 칩은 쓰지 않는다
- **부호를 항상 표기한다** — 색맹 사용자에게 색만으로는 방향이 전달되지 않는다. 부호는 화살표보다 폭도 덜 먹는다
- 상승 빨강 / 하락 파랑 (한국식). shadcn 팔레트에 흡수하지 않는다

### 반경

shadcn 반경 스케일(`--radius: 0.625rem`)을 2단계에서 켠다. Tailwind 기본 반경을 덮어쓰므로 **앱 전체 341곳**(`rounded-md` 105 · `lg` 194 · `xl` 39 · `sm` 3)이 동시에 움직인다 — 컴포넌트 교체와 같은 커밋에서 처리한다.

### 아이콘

lucide-react 유지. 인라인 14~16px, 아이콘 버튼 내부 16px.

### 접힘 — 「전체 보기」의 자리 (v1.6.0, 2026-09-03)

카드 안의 목록·칩 줄이 길어져 접을 때, **전 화면이 같은 규칙을 쓴다.**

1. **기본은 펼친 상태다.** 개수로 미리 접지 않는다. 그려 놓고 재서, 정해진 줄 수를
   넘을 때만 그 높이로 자른다. 넘치지 않으면 버튼도 뜨지 않는다.
2. **상한은 줄 수로 정한다** — 좁은 화면 2줄, `sm`(640px)부터 3줄. 개수로 정하면
   폭에 따라 차지하는 높이가 제각각이 된다.
3. **버튼은 그 묶음의 제목 바로 오른쪽에 선다.** 칩 줄 아래 오른쪽 끝이 아니다 —
   거기 두면 눈이 내용을 다 훑은 뒤에야 버튼이 있다는 걸 알게 되고, 카드마다 위치가
   달라진다. 카드 헤더 오른쪽 끝(`SectionCard`의 `href`·`action`)은 **다른 화면으로
   나가는 문**의 자리라 섞지 않는다.
4. **문구는 「전체 보기 +N」 / 「접기」.** N은 지금 접으면 가려지는 개수다 —
   「전체 보기」만으로는 누를 값어치를 알 수 없어 대개 안 눌린다.

구현은 `fe/src/components/ui/chip-collapse.tsx`의 `useChipCollapse` ·
`ChipCollapseRow` · `ChipCollapseToggle` 한 벌을 쓴다. 쓰는 곳: 홈 「오늘의 시장
브리핑」의 많이 언급된 종목, 홈 「오늘의 키워드」.

> 문단 접기(브리핑 본문의 「전체 읽기」)는 이 규칙과 별개다 — 거기는 줄 수가 아니라
> `line-clamp`이고, 버튼이 문단 바로 아래에 오는 것이 읽는 순서와 맞는다.

## 15. Interaction / Animation

- 전이는 **색·배경·투명도만**, 120~160ms. 레이아웃(폭·높이) 전이는 사이드바 접기와 시트 슬라이드에만
- `prefers-reduced-motion: reduce`를 존중한다 (탭 자동 스크롤은 이미 처리돼 있다)
- **차트·숫자에는 진입 애니메이션을 넣지 않는다.** 실시간 값이 움직이는 화면에서 애니메이션은 변화를 알아채는 걸 방해한다
- 시트/모달은 shadcn 기본 전이(`tw-animate-css`)

## 16. Accessibility

- **색만으로 정보를 전달하지 않는다.** 손익은 부호를 함께(14절), 상태 배지는 텍스트를 함께
- 계정 메뉴·탭·자동완성을 shadcn 컴포넌트로 교체하면서 키보드 조작과 포커스 관리가 정식으로 들어온다 (현재 계정 메뉴는 hover 전용이라 키보드로 열 수 없다)
- 아이콘 전용 버튼에 `aria-label` (접힌 사이드바 포함)
- 활성 탭 `aria-current="page"` 유지
- 포커스 링은 shadcn 기본(`ring-ring/50` 3px)을 쓴다 — 촘촘 밀도에서도 줄이지 않는다

## 17. 개발 시 주의사항

1. **`PageHeader`와 본문은 같은 아케타입 값을 넘겨야 한다.** 어긋나면 제목과 본문의 좌우 경계가 달라진다 — 과거 마켓 레이더가 "혼자 겉돌아 보이던" 원인이 이것이었다
2. **컬럼 폭 상한을 다시 넣는다면 반드시 `min(<값>, 100%)` 형태.** `100%` 항이 없으면 `AppShell`의 `overflow-x-auto`가 좁은 화면에서 가로 스크롤을 만든다
3. **`--radius-*`와 shadcn base 레이어는 컴포넌트 교체와 같은 커밋에서** 켠다. 따로 켜면 어느 쪽이 회귀를 만들었는지 되짚을 수 없다
4. **테마 전환 실측 시 `getComputedStyle`을 그냥 읽으면 안 된다.** shadcn 컴포넌트의 `transition-all` 때문에 직후 읽으면 전이 시작값(이전 테마 색)이 나오고, 기다렸다 읽으면 `PreferencesProvider`가 `data-theme`를 되돌려 놓는다. 전이를 죽이고 같은 태스크에서 동기적으로 읽을 것
5. **새 패키지 설치 후 dev 서버를 재시작**한다. Turbopack이 새 모듈을 못 찾아 `Can't resolve ...`로 죽는다
6. 브랜드 색은 **`var(--brand)`** (옛 `--accent`). shadcn의 `--accent`는 hover 표면이라 뜻이 다르다
7. **`--brand-foreground`는 정의된 적이 없는데 3곳에서 쓰인다**(`admin-llm-panel` 2 · `stock-news-panel` 1). 글자색이 상속으로 떨어지는 기존 버그 — Button 교체 시 해소된다
8. 교체하지 않는 것: lightweight-charts 터미널, recharts, 자체 마크다운 파서/렌더러/에디터
