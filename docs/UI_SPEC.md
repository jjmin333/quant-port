## 1. Product / Page 목적

여러 증권사 계좌를 하나로 합쳐 보는 **개인 투자 관리 플랫폼**. 단일 목적의 도구가 아니라 성격이 다른 네 덩어리가 한 앱에 들어있고, 이 문서의 규칙 대부분은 그 차이를 어떻게 다룰지에 대한 것이다.

| 성격 | 화면 | 이 화면이 해야 하는 일 |
|---|---|---|
| **터미널형** | 마켓 레이더, 종목 워크스페이스 | 많은 종목을 훑고 변화를 알아채기. **밀도가 곧 기능** |
| **문서형** | 뉴스, 투자 리포트 | 읽을지 말지 고르고, 골랐으면 편히 읽기 |
| **기록형** | 스탬프, 메모장, 목표가 | 남기는 마찰을 낮추고 나중에 결과와 함께 보기 |
| **관리자** | 뉴스·API·LLM·점수·배치·캐시·DB 관리 | 운영자 1인이 데스크탑에서 상태를 보고 조작하기 |

**UI 원칙 세 줄**
1. 화면에서 **색이 튀는 곳은 숫자(손익)뿐**이다. 네비게이션·탭·선택 상태는 전부 중립색을 쓴다
2. **밀도는 컴포넌트가 소유한다.** 호출부에서 `className`으로 조이지 않는다
3. 겉보기 통일보다 **콘텐츠 성격**이 우선이다 (뉴스는 행, 리포트는 카드)

## 2. Information Architecture

사이드바 7그룹. **기능 게이팅(`ACCOUNT_FEATURES_VISIBLE = false`)이 걸린 항목은 일반 사용자에게 보이지 않는다** — 지금 실제로 보이는 것은 10개다.

```
핵심    마켓 레이더 · 종목 분석 · 보유종목 · 관심종목
계좌    계좌 연동🔒 · 거래내역🔒
분석    포트폴리오 분석🔒 · 리스크 분석🔒
뉴스    국내 주식 · 해외 주식
리포트  투자 리포트
기록    스탬프 · 메모장 · 목표가 관리 · 백테스트🔒
관리    뉴스·API·LLM·점수·배치·캐시·DB 관리 (관리자만)
                                          🔒 = 현재 비활성
하단 고정  설정
```

**사이드바에 없는 화면**
- `종목 상세`(`/stocks/[symbol]`) — 검색·목록 링크로만 진입. **의도된 설계**
- `실시간 시세`·`재무제표`·`실적 캘린더`·`공시`·`AI 분석` — `lib/page-stubs.tsx`의 준비 중 화면. 기능이 생기면 사이드바에 넣는다

**커맨드 팔레트(⌘K)는 도입하지 않는다.** 메뉴 10개는 사이드바로 충분하고, 팔레트로 메워야 할 진입 경로 공백이 없다. 종목 이동 빈도가 높다는 게 확인되면 그때 얹는다.

## 3. 전체 Layout

```
┌────────────────────────────────────────────────────────┐
│ ☰  ◆ QUANT PORT   [🔍 종목 검색 ────]              Ⓙ▾ │  56px · 전체 폭
├──────────┬─────────────────────────────────────────────┤
│  핵심     │  페이지 제목                    [동작][동작] │  페이지 헤더
│  ▣ 마켓   │  부제                                       │
│  ▤ 분석   ├─────────────────────────────────────────────┤
│  ...      │                                             │
│           │   본문                                       │
│  [설정]   │   reading = min(72rem, max(42rem, 68%))     │
│           │   wide    = 100%                            │
└──────────┴─────────────────────────────────────────────┘
   220px ↔ 48px
```

- **헤더가 전체 폭을 가로지르고 사이드바는 그 아래에서 시작한다.** 검색·계정이 사이드바 상태나 화면 폭과 무관하게 항상 같은 좌표에 있는 것을 우선했다
- 본문만 스크롤한다(`h-[100dvh]` flex). 헤더·사이드바·페이지 헤더는 고정
- 컨텐츠 컬럼 아케타입 2종. **`PageHeader`와 페이지 본문이 반드시 같은 값을 넘겨야 한다** — 어긋나면 제목 컬럼과 본문 컬럼의 좌우 경계가 달라진다

### ⚠️ 2026-08-11 변경 — 기본 아케타입이 `wide`가 되었다

사용자 결정: **모바일 반응형이 따로 만들어져 있으므로, 데스크탑에서 중앙 컬럼만 쓰던 것을 그만두고 화면 폭을 다 써서 데이터를 더 보여준다.**

- `PageScrollShell` / `PageHeader`의 기본값이 `reading` → **`wide`**
- 거터는 `.page-shell-wide`가 `padding-inline: 0.75rem`으로 가진다. **`PageHeader`가 따로 `px-3`을 얹던 특례는 제거했다** — 거터가 두 겹이 되면 헤더와 본문 경계가 다시 어긋난다
- `reading`은 **긴 산문을 읽는 화면에만 명시적으로** 남긴다: 리포트 상세(`research-detail-client`), 리포트 작성(`research-compose`)
- 실측(1280px): 홈 본문 컬럼 **714px → 1050px**

이 변경으로 이 문서의 "reading이 기본"이라는 전제(아래 §7 포함)는 무효다.

## 4. Header

```
[☰]  ◆ QUANT PORT   [🔍 종목 검색 ─────────]                    Ⓙ▾
```

| 요소 | 규격 |
|---|---|
| 높이 | **56px 고정** (화면 종류와 무관) |
| 사이드바 토글 ☰ | 좌측 끝. 웹뷰 모드에서는 숨김 |
| 로고 | `◆` + `QUANT PORT`. 홈(`/`) 링크 |
| 검색 | 최대 380px, 높이 36px. 인라인 자동완성 |
| 우측 | **계정 아바타 하나** — 드롭다운에 이름/이메일 · 설정 · 로그아웃 |

**알림 🔔 버튼과 설정 ⚙ 아이콘을 제거한다.** 알림은 미구현이고(배지 `3`이 하드코딩), 설정은 사이드바 하단에 이미 있다. 알림은 실제로 만들 때 다시 넣는다.

**계정 메뉴는 shadcn `DropdownMenu`로 교체한다** — 현재는 `group-hover` CSS라 키보드로 열 수 없다.

## 5. Navigation

**검색 (헤더 인라인)**
- 종목 검색 전용. 타이핑하면 아래에 자동완성 목록
- 내부를 shadcn `Command`로 재구현해 키보드 위/아래 이동·하이라이트·`role="listbox"`/`aria-activedescendant`를 정식으로 갖춘다

**활성 상태 규칙 (전 화면 공통)**
> 사이드바 메뉴 · 탭 · 칩 · 세그먼트 등 **모든 선택 상태는 중립색**을 쓴다.
> 배경 `--sidebar-accent` / `--accent` + 진한 글자. **브랜드 파랑을 쓰지 않는다** — 파랑은 이 앱에서 하락(`--loss`)을 뜻한다.

## 6. Sidebar

| 항목 | 값 |
|---|---|
| 펼침 폭 | 220px |
| 접힘 폭 | **48px 아이콘 레일** (기존 44px에서 확대 — shadcn 아이콘 버튼 36px + 좌우 여백) |
| 접힘 상태 | 아이콘 클릭으로 이동 가능, hover 시 이름 툴팁 |
| 배경 | `--sidebar` — 라이트에서 본문보다 어둡고, 다크에서 본문보다 밝다 |
| 그룹 라벨 | 현행 유지 (핵심·계좌·분석·뉴스·리포트·기록·관리) |
| < 1024px | 오버레이(Sheet)로 전환 |
| 웹뷰 모드 | 렌더하지 않음 |

**접힘 상태를 저장한다.** 현재는 `matchMedia`로 매번 초기화돼 새로고침하면 풀린다. 사용자가 직접 토글한 값을 저장하고, 저장값이 없을 때만 화면 폭으로 판단한다.

shadcn sidebar 블록은 **통째로 쓰지 못한다**(블록은 세로 관통 사이드바 전제). 상태 관리·모바일 Sheet·단축키는 가져오되 배치는 위 3절 구조에 맞춘다. 블록이 쓰는 `--sidebar-width`(16rem)와 이 앱의 동명 레이아웃 변수(220px) **이름 충돌을 정리해야 한다.**

## 7. 페이지 헤더 & 컨텐츠

```
┌─────────────────────────────────────────────────┐
│ 투자 리포트                      [필터] [+ 작성] │
│ 공개된 투자 논거와 그 결과가 함께 기록됩니다      │
└─────────────────────────────────────────────────┘
```

- `PageHeader`에 **우측 동작 영역**을 추가한다. 좁은 화면에서는 버튼이 아랫줄로 내려가되 우측 정렬 유지
- 지금은 각 페이지가 본문 최상단에 제각기 버튼 줄을 만들고 있다 — 리포트 필터·관심종목 추가·관리자 실행 버튼이 서로 다른 위치. 고정 자리를 주면 이 편차가 사라진다
- **탭은 헤더에 붙이지 않는다.** 탭이 필요한 화면이 2~3개뿐이라 탭 유무로 헤더 높이가 갈리는 비용이 더 크다. 본문 최상단에 둔다

## 8. 각 메뉴별 화면

### 8.1 마켓 레이더 · 종목 워크스페이스 (터미널형, `wide`)

**리스트 폭 3단 전환** — 드래그 리사이즈는 도입하지 않는다.

| 단계 | 리스트에 보이는 것 |
|---|---|
| 좁게 | 종목명 · 등락률 |
| 보통 | + 현재가 |
| 넓게 | + 거래대금 · 점수 |

기존 접기 토글은 「좁게」보다 더 접는 상태로 남긴다. 선택한 단계는 화면별로 기억한다.

**종목 워크스페이스 탭 9개**(개요 · AI 분석 · 차트·호가 · 기업 정보 · 밸류에이션 · 재무제표 · 실적 · 내부자 거래 · 뉴스)는 **한 줄 가로 스크롤 유지**. 위계를 매기지 않는다 — 같은 종목을 여러 각도로 보는 것이라 「주요 5개」를 정당화할 근거가 없다.
→ **추가할 것**: 가장자리 페이드 + 화살표 버튼. 지금은 오른쪽에 탭이 더 있다는 걸 알 방법이 없다. 활성 탭 자동 스크롤은 유지.

### 8.0 홈 — 종합 대시보드 (`wide`)

여러 메뉴의 핵심을 한 화면에 모은다(`components/dashboard/dashboard-overview.tsx`).

```
지수 바 (MarketOverview)
┌─ 거래대금 상위 8 ────────────┬─ 오늘의 뉴스 6 ──┐   1280px 미만에서 세로로 쌓임
└─────────────────────────────┴──────────────────┘
┌─ 최신 투자 리포트 4 (카드) ─────────────────────┐
└────────────────────────────────────────────────┘
```

**각 블록은 독립적으로 실패한다.** 마켓 레이더가 죽어도 뉴스는 떠야 하고, 리포트가 401이어도 나머지는 보여야 한다. 블록마다 자기 로딩/빈 상태를 그리고, 하나의 에러가 화면 전체를 비우지 않는다.

랭킹 응답에는 종목명이 없어 `fetchQuotesBatchClient`로 이름을 채운다 — 코드만 보여주면 훑을 수 없다.

### 8.2 뉴스 (문서형, `wide`)

한 줄 행. `제목 + 매체 배지 + 시각`. 발췌를 넣지 않는다 — 뉴스 제목은 그 자체로 완결된 정보다.
원문은 **우측 시트**로 연다(뒤 목록이 계속 보여 다음 기사로 넘어가기 쉽다).

### 8.3 투자 리포트 (문서형, `reading`)

발췌가 있는 카드. 제목만으로는 읽을지 판단할 수 없고 논거를 보고 고르는 글이다.
**발췌는 2줄 → 1줄로 줄인다**(촘촘 밀도). 한 화면에 3개 → 5개.
본문(마크다운)은 **읽기용 글자 크기·행간을 유지한다** — UI 밀도와 별개.

### 8.4 기록형 (스탬프 · 메모장 · 목표가, `reading`)

별도 인터뷰 없이 **위 규칙의 적용**으로 정의한다.
- 목록: 리포트와 같은 카드형(결과·판정이 함께 보여야 하므로)
- 남기기: 짧은 입력 → 가운데 모달
- 상세: 긴 내용 → 우측 시트, 짧으면 인라인 확장

### 8.5 관리자 (`reading`)

**데스크탑 전용.** 좁은 화면에서는 "데스크탑에서 열어주세요" 안내로 대체한다. 기존 `data-shell` 감지를 그대로 쓴다.

## 11. Responsive Behavior

| 구간 | 동작 |
|---|---|
| ≥ 1024px | 기본 레이아웃. 사이드바 인라인 |
| < 1024px | 사이드바 오버레이(Sheet). 컨텐츠 컬럼 `100%`, 거터 `max(1rem, 4vw)` |
| 웹뷰(`data-shell="webview"`) | 사이드바 미렌더. `padding-bottom: env(safe-area-inset-bottom)` |

**표는 중요 3열 + 행 펼치기.** 가로 스크롤도 카드 변환도 쓰지 않는다.

| 표 | 남길 3열 |
|---|---|
| 관심종목 | 종목 · 현재가 · 등락률 |
| 보유종목 | 종목 · 평가금액 · 수익률 |
| 마켓 레이더 | 종목 · 거래대금 · 등락률 |

펼친 영역은 `라벨 — 값` 정렬로 나머지 컬럼을 순서대로. 관리자 표는 대상 아님(8.5).

## 12. Light Theme

shadcn `neutral` 베이스 기본값을 그대로 쓴다.

| 토큰 | 값 |
|---|---|
| `--background` | `#F5F5F5` — shadcn 기본은 순백이지만 **한 단 내렸다** (아래 경고) |
| `--foreground` | `#252525` |
| `--card` | `#FFFFFF` |
| `--sidebar` | `#FAFAFA` |
| `--border` | `#EBEBEB` |
| `--muted-foreground` | `#8E8E8E` |
| `--profit` (상승) | `#DC2626` |
| `--loss` (하락) | `#2563EB` |

⚠️ **shadcn 기본값의 활성 상태는 라이트에서 안 보인다.** `--sidebar`(#FAFAFA)와 `--sidebar-accent`(#F5F5F5) 차이가 너무 미세하다 → **활성 배경만 `#EDEDED`로 한 단 진하게** 조정한다(목업에서 실측 확인).

⚠️ **페이지 배경도 shadcn 기본(순백)에서 내렸다.** 기본값대로 두면 `--card`도 순백이라 **카드가 배경에서 분리되지 않는다** — 라이트 모드 화면 전체가 흰 판 하나가 되고 헤어라인 테두리만 남는다(2026-08-11 실측으로 확인된 회귀). 이 앱은 카드가 21개씩 깔리는 화면이 많아 그 단차가 정보 구조 자체다. 다크는 이미 배경 `#252525` / 카드 `#343434`로 단차가 있어 그대로 둔다.

**마이그레이션 (빠뜨리면 기존 사용자 테마가 깨진다)**
1. `lib/preferences.ts` — `ColorMode`에서 `midnight` 제거, `normalizeColorMode`가 저장된 `midnight`/`general`을 **`dark`로 매핑**
2. `globals.css` — `[data-theme="midnight"]`·`[data-theme="general"]` 블록 제거, `@custom-variant dark` 선택자 정리
3. `app/layout.tsx` — 테마 초기화 스크립트의 `general → midnight` 변환을 `→ dark`로
4. 설정 화면 — 테마 카드 3장 → 2장

## 14. Design System

### 밀도 (전 화면 공통)

| 항목 | 값 | shadcn 기본 |
|---|---|---|
| 리스트/표 행 높이 | **30px** | 40px |
| 본문 기본 글자 | **12px** | 14px |
| 보조 글자 | **11px** | 12px |
| 카드 패딩 | **10px** | 16px |
| 요소 간격 | **8px** | 12px |
| 컨트롤 높이 | **32px** | 36px |

→ 마켓 레이더 한 화면에 약 20종목.
**shadcn 컴포넌트의 기본 size 값을 한 번만 조정한다.** 호출부마다 `className`으로 조이면 밀도가 137곳에 흩어져 다음에 못 바꾼다.

### 타이포그래피

- 본문·UI — Pretendard Variable
- **숫자·금액·수익률 — Geist Mono + `tabular-nums`** (자릿수가 흔들리면 표에서 비교가 안 된다)
- 페이지 제목 17px/600 · 섹션 제목 13px/600 · 본문 12px · 보조 11px

### 숫자 표현

```
74,300              41,250
+1,200   +1.64%     -750   -1.79%
```

- **색 + 부호.** 화살표(`▲▼`)와 배경 칩은 쓰지 않는다
- **부호를 항상 표기한다** — 색맹 사용자에게 색만으로는 방향이 전달되지 않는다. 부호는 화살표보다 폭도 덜 먹는다
- 상승 빨강 / 하락 파랑 (한국식). shadcn 팔레트에 흡수하지 않는다

### 반경

shadcn 반경 스케일(`--radius: 0.625rem`)을 2단계에서 켠다. Tailwind 기본 반경을 덮어쓰므로 **앱 전체 341곳**(`rounded-md` 105 · `lg` 194 · `xl` 39 · `sm` 3)이 동시에 움직인다 — 컴포넌트 교체와 같은 커밋에서 처리한다.

### 아이콘

lucide-react 유지. 인라인 14~16px, 아이콘 버튼 내부 16px.

## 15. Interaction / Animation

- 전이는 **색·배경·투명도만**, 120~160ms. 레이아웃(폭·높이) 전이는 사이드바 접기와 시트 슬라이드에만
- `prefers-reduced-motion: reduce`를 존중한다 (탭 자동 스크롤은 이미 처리돼 있다)
- **차트·숫자에는 진입 애니메이션을 넣지 않는다.** 실시간 값이 움직이는 화면에서 애니메이션은 변화를 알아채는 걸 방해한다
- 시트/모달은 shadcn 기본 전이(`tw-animate-css`)

---

## 16. Accessibility

- **색만으로 정보를 전달하지 않는다.** 손익은 부호를 함께(14절), 상태 배지는 텍스트를 함께
- 계정 메뉴·탭·자동완성을 shadcn 컴포넌트로 교체하면서 키보드 조작과 포커스 관리가 정식으로 들어온다 (현재 계정 메뉴는 hover 전용이라 키보드로 열 수 없다)
- 아이콘 전용 버튼에 `aria-label` (접힌 사이드바 포함)
- 활성 탭 `aria-current="page"` 유지
- 포커스 링은 shadcn 기본(`ring-ring/50` 3px)을 쓴다 — 촘촘 밀도에서도 줄이지 않는다

## 17. 개발 시 주의사항

1. **`PageHeader`와 본문은 같은 아케타입 값을 넘겨야 한다.** 어긋나면 제목과 본문의 좌우 경계가 달라진다 — 과거 마켓 레이더가 "혼자 겉돌아 보이던" 원인이 이것이었다
2. **컬럼 폭 상한을 다시 넣는다면 반드시 `min(<값>, 100%)` 형태.** `100%` 항이 없으면 `AppShell`의 `overflow-x-auto`가 좁은 화면에서 가로 스크롤을 만든다
3. **`--radius-*`와 shadcn base 레이어는 컴포넌트 교체와 같은 커밋에서** 켠다. 따로 켜면 어느 쪽이 회귀를 만들었는지 되짚을 수 없다
4. **테마 전환 실측 시 `getComputedStyle`을 그냥 읽으면 안 된다.** shadcn 컴포넌트의 `transition-all` 때문에 직후 읽으면 전이 시작값(이전 테마 색)이 나오고, 기다렸다 읽으면 `PreferencesProvider`가 `data-theme`를 되돌려 놓는다. 전이를 죽이고 같은 태스크에서 동기적으로 읽을 것
5. **새 패키지 설치 후 dev 서버를 재시작**한다. Turbopack이 새 모듈을 못 찾아 `Can't resolve ...`로 죽는다
6. 브랜드 색은 **`var(--brand)`** (옛 `--accent`). shadcn의 `--accent`는 hover 표면이라 뜻이 다르다
7. **`--brand-foreground`는 정의된 적이 없는데 3곳에서 쓰인다**(`admin-llm-panel` 2 · `stock-news-panel` 1). 글자색이 상속으로 떨어지는 기존 버그 — Button 교체 시 해소된다
8. 교체하지 않는 것: lightweight-charts 터미널, recharts, 자체 마크다운 파서/렌더러/에디터
