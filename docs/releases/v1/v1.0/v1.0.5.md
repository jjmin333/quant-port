# Quant Port v1.0.5 — 오류 경계 · 클라이언트 오류 리포팅 · 확장 주입 감지

> **버전:** v1.0.5
> **기준일:** 2026-09-01 (KST)
> **Git 태그:** `v1.0.5` (커밋 후)
> **이전 버전:** [v1.0.4](./v1.0.4.md)
> **목적:** 렌더 중 예외 하나가 앱 전체를 내리던 구조를 고치고, 브라우저에서 난 오류를 우리가 먼저 알게 한다. 확장 프로그램이 페이지를 고쳤을 때 사용자가 스스로 벗어날 수 있게 한다.
> **범위:** 프론트엔드(오류 경계·전역 리스너·리포터·주입 감지) + 백엔드(공개 엔드포인트 1개, 로그 전용). DB 스키마·배치 변경 없음.

---

## 1. 한 줄 요약

사용자 브라우저 확장이 페이지 코드를 고쳐 뉴스 화면을 통째로 내린 일을 조사하다가, **앱에 오류 경계가 하나도 없다**는 사실이 드러났다 — `error.tsx` 0개 · `ErrorBoundary` 0개 · `window.onerror` 0개. 확장 때문이든 우리 버그든 결과가 같았다. 이제 화면 하나가 죽어도 **셸이 남고 「다시 시도」로 복구**되고, 주입이 확인되면 **확장을 끄라고 정확히 그때만** 안내하며, 같은 순간에 오류가 서버 로그로 흘러간다.

## 3. 배경 — 이 릴리스를 만든 사건

`/news/us`에서 `Cannot access 'mentions' before initialization`이 반복됐다. 앱 코드에는 그 오류가 존재할 수 없었다: 소스에서 `mentions`를 바인딩하는 두 곳(`news-client.tsx` · `market-briefing-card.tsx`) 모두 사용처보다 앞이고, 컴파일 산출물에서도 선언(12503행)이 모든 read(12682·12690·12958·13030행)보다 앞이다. nginx 캐시·서비스워커·중복 dev 서버도 아니었다.

결정적 차이는 **사용자 탭에만 `rhwpDev`가 주입돼 있다**는 것이었고, 사용자가 그 확장을 끄자 재현되지 않았다.

**여기서 진짜 문제는 확장이 아니다.** 남의 확장은 우리가 막을 수 없고 막아서도 안 된다. 문제는 **그 예외 하나가 앱 전체를 내렸고, 우리는 그 사실조차 몰랐으며, 사용자에게는 그저 「서비스가 고장났다」로 보였다**는 것이다. 같은 구조라면 우리 코드의 사소한 렌더 버그도 똑같이 전체 장애가 된다.

## 4. 구현

| 파일 | 내용 |
|---|---|
| `fe/src/app/(main)/error.tsx` | 라우트 오류 경계. **`(main)/layout.tsx` 아래**에 두는 것이 핵심 — 그 레이아웃이 `AppShell`을 감싸므로 본문만 대체되고 셸이 남는다 |
| `fe/src/app/global-error.tsx` | 루트 레이아웃까지 무너졌을 때의 마지막 그물 |

| `fe/src/components/providers/error-listeners.tsx` | `window.error` · `unhandledrejection` |
| `fe/src/lib/page-integrity.ts` | 깨끗한 iframe과 비교해 **주입된 전역·확장 리소스**를 찾는다 |
| `fe/src/lib/client-error-report.ts` | `sendBeacon` 전송 · 중복 제거 · 건수 상한 |

| `be/internal/server/{router,server}.go` | 공개 그룹에 등록(IP 리미터 아래) |

### 4.1 폭주를 먼저 막았다

오류는 폭주한다 — 이번 사례가 **1초에 69건**이었다(React가 렌더를 재시도하며 같은 예외를 다시 던진다). 상한이 없으면 리포터 자신이 사용자의 회선과 서버 로그를 태운다. 클라이언트에서 **같은 오류 30초 1회 · 페이지당 최대 5건**으로 자른다. 실측: 40건(동일 20 + 서로 다른 20) 발생 → 서버 도달 **5건**.

### 4.2 DB에 쓰지 않는다

인프라가 OCI Always Free이고 DB가 1 ECPU다. 폭주하는 성질의 데이터를 테이블에 넣으면 **장애 때 DB가 먼저 넘어간다.** 구조화 로그로만 남긴다.

### 4.3 신뢰하지 않는 입력으로 다룬다

공개 경로이고 본문은 브라우저가 보낸 문자열이다. `MaxBytesReader`(16KB) · 필드별 길이 절단 · **개행/제어문자 제거**로 로그 한 줄을 위조하지 못하게 한다. 실측: 메시지에 개행과 가짜 타임스탬프를 넣어도 **한 줄로 평탄화**된다. UA는 본문이 아니라 헤더에서 읽는다.

### 4.4 확장 주입은 감지할 수 있다 — 깨끗한 iframe과 비교하면 된다

처음에는 「스택에 확장 URL이 보이면 확장 탓」으로 판별하려 했으나 **이번 사례에는 그런 프레임이 하나도 없었다.** 확장이 우리 번들 자체를 고쳐 놓으면 스택은 우리 코드처럼 보인다.

대신 `page-integrity.ts`가 **같은 출처의 빈 iframe**을 만들어 손대지 않은 `window`를 하나 얻고, 전역 이름을 비교한다. 미리 만들어 둔 확장 목록도, 스크립트 실행 순서에 대한 가정도 필요 없다 — 그래서 처음 보는 이름도 잡힌다.

두 번의 실측 교정이 필요했다:

1. 필터가 없을 때는 Next·Turbopack의 개발용 전역이 목록 10칸을 채워 **정작 주입된 이름이 밀려났다.** 접두사·정확일치 허용 목록을 넣었다.
2. 비교 목록을 iframe **뒤에** 찍으면 우리가 붙인 iframe이 만든 프레임 인덱스가 「낯선 전역」으로 잡힌다. 순서를 뒤집었다.

교정 후 결과는 `foreignGlobals=[rhwpDev]` 한 줄이다.

이 값은 두 곳에 쓴다:

- **오류 화면 문구** — 주입이 확인됐을 때만 「이 페이지의 코드를 **브라우저 확장 프로그램이 수정**하고 있는 것으로 보입니다. 확장 프로그램을 끄거나 시크릿 창에서 열면 정상적으로 이용할 수 있습니다」로 바꾼다. 아니면 일반 문구를 쓴다 — 늘 확장 탓으로 적으면 우리 버그가 그 뒤에 숨는다.
- **리포트** — 로그에 이름이 남아, 어느 확장인지 우리가 곧바로 안다.

**평소에는 아무것도 하지 않는다.** 대부분의 확장은 무해하고, 켜져 있다는 이유로 경고를 띄우면 그게 더 나쁜 화면이다. 오류가 실제로 났을 때만 조사한다.

### 4.5 스택은 소스맵을 거치지 않은 원본을 보낸다

확장이 번들에 끼워 넣은 코드는 소스맵에 대응하는 위치가 없어서, 소스맵을 거친 프레임이 **우리 소스의 엉뚱한 줄**로 옮겨진다. 실제로 이번 오류는 계속 `news-client.tsx`의 브리핑 이펙트 줄을 가리켰지만 그 줄에는 `mentions`가 없다. 컴파일된 파일·줄이 있어야 실제로 실행된 코드를 짚을 수 있다.

### 4.6 CSP로 막지 않는다

크롬 확장의 content script는 **격리 세계에서 돌아 CSP로 막히지 않는다.** 페이지 컨텍스트 주입만 막히므로 부분적이고, nonce 배선 비용이 크며, 사용자가 고른 도구를 막는 방향이라 이 문제의 답이 아니다.

## 5. 사이드 이펙트·호환

| 항목 | 영향 |
|---|---|
| 오류 화면 문구 | 사용자에게 기술 정보를 보이지 않는다. 제보 시 단서는 서버 로그에서 찾는다 |
| React 경계의 한계 | 렌더·라이프사이클만 잡는다. 나머지는 전역 리스너가 받지만 **화면은 바뀌지 않는다**(보고만) |
| 네트워크 | `sendBeacon`이라 화면을 막지 않는다. 실패해도 사용자에게 아무 일도 없다 |
| 개인정보 | `location.pathname`만 보낸다 — 쿼리스트링(검색어 등)은 싣지 않는다 |
| 주입 감지 비용 | 오류가 났을 때만 iframe 하나를 만들었다 지운다. 정상 경로에서는 실행되지 않는다 |
| 오탐 | 무해한 확장도 `foreignGlobals`에 잡힌다. 그래서 **경고가 아니라 오류가 났을 때의 안내**로만 쓴다 |

## 9. 남은 일 — 근본 원인은 미증명, 「지켜보기」로 결정

### 9.1 증상은 멈췄다. 그러나 우리가 고친 것이 아니다

사용자가 확장을 다시 켜고 뉴스 화면을 열었을 때(02:09:52, `[rhwp]` 로그로 확인) **오류가 나지 않았다** — TDZ 0건, 리포터 수신 0건. 마지막 발생은 00:50:43이 끝이다.

그런데 그 사이 **`news-client.tsx`는 한 줄도 바뀌지 않았고, `NewsClient`가 든 청크도 그대로다**: 오류가 나던 그 파일(`src_0azqlys._.js`)을 지금도 내려주고, 선언 12503행 / 첫 사용 12682행으로 위치까지 같다. 달라진 것은 페이지가 **추가로 부르는 청크**뿐이다(오류 경계 · 리포터).

같은 코드 · 같은 확장인데 결과가 달라졌다는 뜻이므로, **번들 구성이 바뀌면 다시 나타날 수 있다.**

### 9.2 왜 지금 손대지 않기로 했나

정상이던 v0.9와의 유일한 구조적 차이는 남아 있다 — `quoteSymbols`(useMemo)가 `mentions`를 참조하는 것. 이것을 되돌리면 알려진 정상 형태가 되지만 **원인이라는 증명이 없고**, 비용이 0도 아니다. 실측: 언급 상위 6개 중 화면 기사 심볼에 없는 것이 국내 2개 · 해외 1개이고, 그 종목들은 이슈 스트립에서 이름만 나오고 등락률이 빠진다.

증명 없이 기능을 깎는 대신, **재발하면 자동으로 남는 원본 스택으로 정확히 고치는 쪽**을 택했다.

### 9.3 재발하면 무엇이 다른가

- 뉴스 화면이 깨져도 **셸이 남아** 다른 메뉴를 계속 쓸 수 있다
- 화면이 **확장 프로그램을 끄라고 직접 안내**한다(주입이 확인됐을 때만)
- **소스맵을 거치지 않은 원본 스택**이 서버 로그에 자동으로 남는다 — 사용자 제보를 기다리지 않는다

### 9.4 재발 시 조사 순서

1. `docker logs quant-port-api | Select-String "client error"` 에서 `path=/news/*` 항목을 찾는다
2. `stack=` 의 컴파일된 파일·줄(`chunks/src_xxx.js:줄:칸`)을 그 시점 청크에서 연다 — **청크는 재컴파일마다 덮어써지므로 먼저 복사해 둔다**
3. 그 줄이 우리 코드가 아니면 확장이 끼워 넣은 코드다. 무엇을 어떻게 고쳤는지 보고 그때 정확히 대응한다
4. `foreignGlobals=` 가 어느 확장인지 알려 준다
