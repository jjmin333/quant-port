## 1. 한 줄 요약

「우측 상단 여섯 개 버튼의 크기가 들쑥날쑥하다」는 지적은 착시가 아니었다 — 앱에 **버튼 체계가 두 개**(공용 `<Button>` 36곳 · 손으로 쓴 알약 16개 파일) 있었고, 그 여섯 개는 **같은 스타일 문자열 네 벌**로 복사돼 있었다. 공용 컴포넌트 하나로 합쳤다. 숫자는 값과 단위를 나눠 **「원」·「$」를 값보다 한 단 작고 흐리게** 만들었다.

## 2. 먼저 — 견본이 실물과 달랐던 문제

사용자가 **v1 견본과 실제 서비스의 글자가 다르다**고 지적했다. 확인해 보니:

**글꼴은 처음부터 같았다.** 앱과 견본에서 같은 문자열(`1,697,000원`)을 같은 스타일로 그려 폭을 재면 소수점까지 일치한다. 둘 다 Pretendard Variable 1.3.9 한 벌(가변축 45–920)을 쓰고 `font-synthesis:none`·`antialiased`도 같다.

| 스타일 | 앱 | v1 견본 |
|---|---|---|
| 24px/600 tabular | 141.53px | 141.53px |
| 14px/500 tabular | 81.02px | 81.02px |
| 12px/400 tabular | 68.06px | 68.06px |
| 12px/400 일반 | 61.83px | 61.83px |
| 15px/600 | 80.91px | 80.91px |

**다른 것은 v1 무대에 내가 임의로 넣은 크기·굵기·자간이었다.**

| 요소 | 앱 실제 | v1 견본 | 결과 |
|---|---|---|---|
| 헤더 가격 | 24px / 600 / 자간 normal | 26px / **700** / **−0.52px** | 더 굵고 좁아 **다른 글꼴처럼** 보였다 |
| 헤더 등락 | 12px (`QuoteChange size="sm"`) | 14px | 가격과의 낙차가 실제보다 작았다 |
| 종목명 | 18px / 600 | 15px / 700 / −0.01em | — |
| 목록 행 | 가격·등락률·거래대금 **세로 3단** (12·11·11px) | 가로 한 줄 12/12/11 | 실제 목록과 구조가 달랐다 |

**교훈:** 견본의 무대는 앱 컴포넌트에서 **값을 옮겨 와야** 한다. 눈대중으로 그리면 그 위에서 한 선택이 무의미해진다. v2에는 **앱에서 잰 기준 폭을 넣어 파일이 스스로 대조**하고, 어긋나면 상단 배지가 「이 파일로 판단하지 마세요」라고 말한다.

## 3. A1 — 액션 버튼을 공용 컴포넌트로

### 실측한 불일치 (한 페이지 `/reports` 안에서)

| 버튼 | 높이 | 모서리 | 출처 |
|---|---|---|---|
| 필터 칩 | 24.2px | 8px | 손으로 쓴 칩 |
| **종목 헤더 여섯 개** | **26.2px** | **10px** | 손으로 쓴 알약 ×4벌 |
| `<Button size="sm">` | 28px | 8px | 공용 컴포넌트 |
| 로그인·회원가입 | 32.0px | 8px | 공용 컴포넌트 |
| 리포트 쓰기 | 32.2px | 10px | 손으로 쓴 알약 |

한 종류여야 할 것이 **다섯 가지 높이 · 세 가지 모서리**였다. 게다가 헤더의 여섯 개는 고정 높이가 없어(내용에서 26.2px가 나왔다) **글자 크기를 건드릴 때마다 같이 흔들렸다.**

### 고친 것

네 벌로 흩어져 있던 알약 스타일을 지우고 전부 `<Button variant="outline" size="sm">`으로 옮겼다.

| 파일 | 전 | 후 |
|---|---|---|
| `stock-symbol-action-bar.tsx` | 관심 버튼 + `linkPillClass` ×3 | `<Button>` ×4 |
| `research/publish-call-button.tsx` | 알약 문자열 재작성 | `<Button>` |
| `stamps/stamp-button.tsx` | `size sm/md` 자체 분기 | `<Button>` (`size` 프로퍼티 삭제) |
| `stocks/stock-detail-client.tsx` | `px-2.5 py-1.5` 별도 크기 | `<Button>` ×2 + 오버라이드 제거 |

호출부에 남긴 것은 **색뿐**이다(`HEADER_ACTION_CLASS` 한 줄). 크기·높이·모서리·아이콘은 전부 컴포넌트가 정한다 — 호출부에서 덮으면 방금 없앤 문제가 그대로 돌아온다.

### 나머지 전부도 합쳤다 (2차)

앱 전체를 다시 훑으니 손으로 쓴 컨트롤이 **116곳**이었고, 크기 지문이 **서로 다른 35가지**였다.
이 중 **104곳을 `buttonVariants()`로 옮겼다** — 엘리먼트(`<button>`·`<Link>`)는 그대로 두고
className만 `cn(buttonVariants({ variant, size }), …색)`으로 바꾸는 방식이다. 구조를 건드리지 않으므로
조건부 active 상태·pill 모양(`rounded-full`)이 그대로 살아 있고, **크기는 이제 공용 정의 한 곳에서 나온다.**

세로 패딩을 계단에 대응시켰다 — 현재 높이에서 가장 가까운 칸을 골라 눈에 띄는 변화가 없다.

| 기존 | → size | 높이 |
|---|---|---|
| `py-0.5` · `py-1` | `xs` | 20.2 · 24.2 → **24px** |
| `py-1.5` | `sm` | 28.2 → **28px** |
| `py-2` · `px-4` | 기본 | 32.2 → **32px** |
| `h-9` | `lg` | 36 → **36px** |

**남긴 12곳**은 버튼이 아니다: 탭(`analysis-tab-bar`, `rounded-t`) · 실적 캘린더 날짜 칸 ·
스탬프 예측 폼의 세그먼트 컨트롤 · 세로 패딩이 없는 칩(`stock-score-chip` 등).
이들은 각자 다른 규칙을 따르는 것이 맞다.

실측 `/reports`: **24.2 / 32.0 / 32.2px · 모서리 8·10·full** → **24 / 28 / 32px · 모서리 8px**(의도한 pill 하나 제외).

### 아이콘 계단

`Button`의 `sm`에 `[&_svg]:size-[13px]`를 넣었다. 글자가 12px인데 아이콘이 14px이라 **아이콘이 글자보다 컸고**, lucide 아이콘마다 다른 획 밀도(별·서류가방·과녁)가 그대로 버튼의 무게 차이로 보였다. 계단은 **xs 12 · sm 13 · 기본 14px**. 이 한 줄이 `size="sm"` 버튼 전부에 걸린다.

### 실측 결과

여섯 개 전부 **28px 고정 · 12px/500 · 모서리 8px · 아이콘 13px**. 앱의 다른 `size="sm"` 버튼과 같은 줄에 선다.

## 4. C2 — 가격 단위를 값보다 한 단 작게

```
1,687,000원   →   1,687,000원   (원: 0.85배 + --text-muted)
```

단위는 어느 줄에서나 같으므로 정보가 아니다. 값과 같은 무게로 여덟 번 반복되면 그 여덟 개가 소음이 된다.

### 왜 컴포넌트만 고쳐서는 안 됐나

`formatPrice()`는 **문자열 하나**를 돌려주므로 값과 단위를 나눌 수 없다. 그런데 이 함수를 **직접 부르는 곳이 92곳**(39개 파일)이고 컴포넌트를 거치는 곳은 23곳뿐이었다. 컴포넌트만 고치면 **한 페이지 안에 축소된 단위와 그렇지 않은 단위가 섞여** 지금보다 나빠진다 — 실측으로 확인했다(`/analysis` 한 페이지에 문자열 가격 74개).

### 한 것

1. `PriceDisplay`에 **`size="inherit"`** 추가. 크기를 정하지 않아 표 셀(12px)처럼 **줄이 이미 크기를 갖고 있는 자리**에서 쓸 수 있다. 이게 없어서(가장 작은 `sm`이 14px) 호출부가 문자열로 도망갔던 것이다.
2. `PRICE_UNIT_CLASS`(`text-[0.85em] font-normal text-[var(--text-muted)]`)를 한 곳에 정의하고 `PriceDisplay` · `PriceAmountPlain` · `QuotePrice`가 단위를 별도 엘리먼트로 그린다.
3. **JSX 위치의 `{formatPrice(a, b)}` 46건을 27개 파일에서 기계 치환** → `<PriceDisplay … size="inherit" />`. 문자열이 필요한 자리(`title` · `aria-label` · 템플릿 리터럴 46건)는 건드리지 않았다 — 거기서는 단위 크기가 아무 의미가 없다.
4. 치환이 `string` 타입 프로퍼티에 들어간 4곳은 그 행 컴포넌트의 `value`를 `React.ReactNode`로 넓혔다(`Row` · `EvidenceRow` · `MetricRow`). 셋 다 값을 내용으로 그리는 컴포넌트다.

### 실측 결과

| 화면 | 단위 축소됨 | 문자열로 남은 가격 |
|---|---|---|
| `/analysis` | 75 | **0** |
| `/` (홈) | 12 | **0** |

### 퍼센트(%)는 건드리지 않았다

`formatPercent()`는 60곳 넘게 문자열로 쓰이고, **「%」는 「원」과 달리 값의 일부로 읽힌다** — 흐리게 하면 `−1.85`가 무엇의 −1.85인지 약해진다.

## 9. 남은 것

- **로그인 뒤 `/market` 실측** — 헤더 버튼 여섯 개와 순위 목록의 단위 축소.
- **`buttonVariants()`로 옮긴 104곳은 아직 `<button>`/`<Link>` 엘리먼트다.** 크기는 공용 정의에서 나오지만, 포커스 링·`asChild`·`disabled` 처리는 `<Button>` 컴포넌트를 써야 완전해진다. 다음 단계.
- **`/reports`의 「리포트 쓰기」가 툴바 32px · 사이드 레일 28px로 갈린다.** 둘 다 계단 위에 있지만 같은 이름의 버튼이므로 한쪽으로 맞추는 게 낫다.
- **문자열 `formatPrice()` 46건**은 그대로다. `title`·`aria-label`·템플릿 리터럴이라 화면 크기와 무관하지만, 그중 일부가 나중에 JSX로 옮겨질 수 있다.
- `fe/public/`에 예전 세션의 `typography-preview.html` · `typography-preview-16px.html`이 남아 공개 배포된다 — 정리 대상.
