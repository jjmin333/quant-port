# Quant Port v1.0.0 — 타이포그래피 통일 (Pretendard 단일 폰트 · 이름 있는 크기 계단)

> **버전:** v1.0.0
> **기준일:** 2026-09-01 (KST)
> **Git 태그:** `v1.0.0` (커밋 후)
> **이전 버전:** [v0.10.1](../../v0/v0.10/v0.10.1.md)
> **목적:** 폰트를 Pretendard 한 벌로 통일하고, 화면 곳곳에 하드코딩돼 있던 글자 크기를 **이름 있는 계단 일곱 개**로 모아 전 페이지의 가독성을 올린다.
> **범위:** 프론트엔드 전용. 백엔드·DB·배치 변경 없음.

## 1. 한 줄 요약

폰트는 이미 Pretendard였다. **문제는 크기였다** — 긴 한국어 문단이 표 셀과 같은 12px로 그려지고 있었고, 9~10px 글자가 화면마다 수백 개 있었다. 크기를 이름 있는 계단으로 모으고(`text-micro`…`text-page`), 읽는 글을 14px로 올리고, 최소 크기를 11px로 바닥 다졌다. 숫자 전용이던 Geist Mono는 걷어내고 Pretendard + `tabular-nums`로 대체했다.

## 2. 무엇이 문제였나 (실측)

### ① 읽는 글이 표 셀과 같은 크기였다

홈의 「오늘의 시장 브리핑」 본문은 **381자짜리 한국어 문단인데 12px / 행간 19.5px**로 그려졌다. 같은 화면의 표 셀(11px)과 한 단 차이다. 한국어는 같은 px에서 라틴 문자보다 획이 조밀해 더 작게 읽히는데, 문단에 그 크기를 쓰면 "훑을 수는 있으나 읽히지는 않는" 상태가 된다. 사용자가 처음 지적한 자리도 여기다.

홈 화면 전체를 실측했을 때 **본문 중 가장 큰 글자가 14px(사이드바 메뉴)**였다.

| 크기 | 홈 화면 요소 수 |
|---|---|
| 9px | 39 |
| 10px | 149 |
| 10.5px | 39 |
| 11px | 148 |
| 12px | 63 |
| 13px | 42 |
| 14px | 27 |

### ② 크기가 1,500곳에 흩어져 있었다

| 클래스 | 사용처 |
|---|---|
| `text-[11px]` | 495 |
| `text-[10px]` | 439 |
| `text-xs` (12px) | 410 |
| `text-sm` (14px) | 247 |

| `text-[13px]` | 36 |
| `text-[7px]` · `[8px]` · `[8.5px]` · `[9.5px]` · `[10.5px]` · `[11.5px]` · `[12.5px]` · `[13.5px]` | 나머지 |

`docs/UI_SPEC.md` §14는 **본문 12px · 보조 11px**를 규정하고 있었는데, 실제 코드는 그보다 아래로 조용히 내려가 있었다. 규정이 지켜지지 않은 게 아니라 **지킬 방법이 없었다** — "한 단 키우자"가 1,500곳을 고치는 일이었기 때문이다.

### ③ 폰트가 두 벌이었다 (그리고 세 번째가 숨어 있었다)

- 본문·UI: Pretendard Variable ✅ (이미 전역 적용돼 있었다)
- 숫자: Geist Mono — `next/font/google`로 받아 오는 두 번째 웹폰트
- **캔들 차트 축**: 지정이 없어 lightweight-charts 자체 기본값(Trebuchet MS 계열). 캔버스에 그려지므로 CSS를 상속받지 않는다 — 앱에서 유일하게 Pretendard가 아닌 글자였고, 아무도 지정한 적이 없어 알아채기 어려웠다.

## 4. 새 타이포 스케일

정의는 `fe/src/app/globals.css`의 `@theme inline` 한 곳이다. **다음에 밀도를 손보는 일은 이 일곱 줄을 고치는 일이다.**

| 토큰 | 크기 / 행간 | 용도 | 흡수한 옛 값 |
|---|---|---|---|
| `text-micro` | 11px / 1.35 | 배지·칩·각주·메타 — **이 앱의 하한** | 7 · 8 · 8.5 · 9 · 9.5 · 10 · 10.5px |
| `text-cell` | 12px / 1.35 | 표 셀·목록 본문·기본 UI | 11 · 11.5 · 12 · 12.5px, `text-xs` |
| `text-note` | 13px / 1.4 | 한 단 강조된 보조 · 위젯 제목 | 13 · 13.5px |
| `text-read` | 14px / **1.7** | **읽는 글** — 브리핑·요약·AI 해설·메모 | (신설) |
| `text-article` | 15px / 1.85 | 문서 본문 — 리포트·기사 원문 | 15px |
| `text-section` | 15px / 1.4 | 페이지 섹션 제목 | `text-sm`·`text-cell` 제목 |
| `text-page` | 19px / 1.35 | 페이지 제목 | `text-base sm:text-lg` |

### 왜 이렇게 나눴나

- **행간을 micro·cell·note에는 1.35~1.4로만 준다.** 이 셋은 표 안에 서는 글자라 행간이 곧 행 높이다. 반대로 `read`는 행간이 본질이라 1.7을 토큰에 묶었다 — 한국어 문단은 같은 px여도 행간이 좁으면 글자가 뭉쳐 보인다.
- **`article`과 `section`은 크기가 같지만 나눠 뒀다.** 하나는 읽는 글이고 하나는 제목이라, 다음에 문단만 키우거나 제목만 키우는 일이 반드시 생긴다. 그때 같은 토큰을 쓰고 있으면 한쪽을 위해 다른 쪽을 망가뜨린다.
- **`text-sm`(14px) 이상의 Tailwind 기본 계단은 건드리지 않았다.** 버튼·입력·내비의 높이가 그 행간(20px)에 맞춰져 있어, 같이 움직이면 컨트롤 높이가 따라 변한다. 크기를 고치려다 레이아웃을 고치게 된다.

## 5. 숫자 — `font-mono` → `font-num`

```css
@utility font-num {
  font-family: var(--font-pretendard);
  font-variant-numeric: tabular-nums;
}
```

**정렬에 필요한 것은 고정폭 글꼴이 아니라 고정폭 숫자다.** Pretendard는 `tnum`을 갖고 있어 그것만 켜면 표의 세로 정렬이 그대로 유지된다(실측 확인). 얻은 것:

- 웹폰트 한 벌 감소 — `next/font/google`의 Geist Mono 요청 제거
- 숫자 폭이 좁아져 촘촘한 표에 여유
- 이름이 사실과 맞는다 — Pretendard는 고정폭이 아니다. `font-mono`라는 이름을 남겨 두면 다음 사람이 "여기는 고정폭"이라는 전제로 칸 폭을 계산한다

**코드·식별자는 예외다.** 관리자 화면의 Redis 키·SQL·테이블 컬럼명과 마크다운 `<code>`는 여전히 고정폭이라야 읽힌다(24곳). 이들은 `font-code`로 옮겼고, 값은 **OS에 이미 있는 글꼴만** 쓴다(`ui-monospace, SFMono-Regular, Menlo, Consolas, …`) — 표시 하나 때문에 웹폰트를 한 벌 더 받지 않는다.

`--font-mono` 토큰 자체는 지우지 않고 `font-code`와 같은 값을 가리키게 뒀다. 미처 못 옮긴 호출부가 **사라진 Geist Mono를 부르며 브라우저 기본 고정폭(대개 Courier)으로 떨어지는** 일을 막는다.

## 6. 이번에 발견해서 고친 함정 — tailwind-merge가 크기를 지우고 있었다

새 이름을 붙이자마자 홈 위젯 제목이 **클래스는 붙어 있는데 상속 크기(16px)로** 나왔다. 원인은 `cn()`이다.

```tsx
cn("min-w-0 text-note font-semibold text-foreground")
//            ^^^^^^^^^ 지워진다
```

tailwind-merge는 **모르는 `text-*`를 글자 크기가 아니라 글자 색으로 분류한다.** 그래서 뒤에 오는 `text-foreground`와 같은 그룹으로 보고 앞의 것을 충돌로 판단해 떨어뜨린다. 임의값(`text-[11px]`)일 때는 길이 리터럴이라 크기로 정확히 분류됐기 때문에, **이름을 붙이는 순간 새로 생긴 함정**이다.

`fe/src/lib/utils.ts`에서 스케일을 tailwind-merge에 등록해 해결했다.

```ts
const twMerge = extendTailwindMerge({
  extend: { classGroups: { "font-size": [{ text: [...TEXT_SCALE] }] } },
});
```

> ⚠️ **새 크기 계단을 추가하면 `TEXT_SCALE`에도 넣어야 한다.** 안 넣으면 오류 없이 조용히 무시된다.

## 7. 손으로 판단한 자리

기계적 치환으로 끝나지 않는 곳들이다.

### ① 읽는 글 16곳을 `text-read`로 올렸다

브리핑 본문(홈·뉴스), 지수 해설, AI 분석 문단, 기업 정보 요약, 일별 AI 해설, 뉴스 기사 요약·발췌, 재무 요약, 메모 본문, 리포트 댓글, 스탬프 당시 요약. 기사 원문과 리포트 본문은 `text-article`(15px).

**불릿 목록과 캡션은 올리지 않았다** — 읽는 글이 아니라 훑는 글이고, 표와 같은 리듬에 서 있다.

### ② 위젯 제목은 15px가 아니라 13px다

`SectionCard`를 `text-section`(15px)으로 올렸더니 홈의 좁은 칸에서 **「AI 추천 랭킹 TOP」이 네 줄로 접히고** 카드 행 전체가 높아졌다(실측 1280px). 이 카드는 사이드 레일에도 서고 제목 오른쪽에 토글·더보기가 함께 놓인다. **제목 크기는 칸 폭이 허락하는 만큼만 올린다** — `text-note`(13px)로 되돌렸다. 페이지 섹션 제목(`<h2>` 26곳)은 `text-section`이다.

### ③ 중복된 링크 문구를 걷어냈다

②를 고쳐도 「AI 추천 랭킹 TOP」이 세 줄이었다. 제목 옆 링크 문구가 `"AI 추천 랭킹"`이라 **바로 왼쪽 제목과 같은 말**을 반복하며 폭만 먹고 있었다. 기본값(「더보기」)으로 바꿨다. 옆 칸 「주요 실적 일정」도 같은 이유로 `"실적 캘린더"` → 기본값. 두 칸 모두 한 줄로 정리됐다.

### ④ 죽은 분기를 걷어냈다

`compact ? "text-[11px]" : "text-[11px]"` 처럼 **양쪽이 같은 값인 삼항**이 7곳 있었다. 치환하면 그대로 남아 "여기엔 밀도 분기가 있다"는 거짓 신호가 된다. 정리했고, 그 결과 `daily-close-tab.tsx`의 `compact`가 실제로 쓰이지 않는다는 것이 드러나 프로퍼티만 남겼다.

### ⑤ 차트 글자

- 캔들 차트(`lightweight-charts`)에 `fontFamily`를 넘긴다 — `--font-pretendard`를 읽어 그대로 전달. 축의 날짜·가격이 이제 앱과 같은 글꼴이다.
- recharts 축·범례의 `fontSize: 9` · `10` **20곳을 11로** 올렸다. SVG 안이라 CSS 스케일을 타지 않아 별도로 손봐야 한다.

## 10. 사이드 이펙트 · 호환

- **행 높이가 조금씩 커진다.** 10px → 11px, 11px → 12px이라 촘촘한 목록은 한 화면에 담기는 줄이 소폭 줄어든다. 「A · 보수」를 고른 이유가 이것이다 — 터미널형 화면의 밀도는 기능이다.
- **`text-xs`는 앱 코드에서 사라졌다.** `text-cell`이 같은 값(12px / 행간 16.2px ≈ 기존 16px)을 갖는다. 새 코드에서 `text-xs`를 쓰면 동작은 하지만 스케일 밖의 값이 된다.
- `--font-geist-mono` 참조는 남아 있지 않다.
- 백엔드·DB·배치는 손대지 않았다.

## 12. 남은 것

- **로그인 뒤 화면 실측** — 마켓 레이더·워크스페이스·보유·관심. 특히 캔들 차트 축의 글꼴.
- **`/dev/typography`는 공개 라우트다.** 데이터를 읽지 않는 정적 견본이라 그대로 뒀지만, 상용에 노출하지 않으려면 관리자 게이트 뒤로 옮기거나 빌드에서 제외한다.
- **`text-sm` 이상은 두 체계가 공존한다.** 앱 계단(micro…page)과 Tailwind 기본(sm·base·lg·xl…). 컨트롤 높이 때문에 의도적으로 남겼지만, shadcn 컴포넌트를 마저 교체할 때 다시 볼 자리다.
- 홈의 「AI 추천 랭킹 TOP」은 여전히 두 줄이다. 칸 폭이 155px인데 제목·날짜·링크·토글 네 가지가 한 줄에 선다 — 제목 문구를 줄이거나 헤더 배치를 바꿔야 한 줄이 된다.
