# Quant Port v1.0.3 — 시세 배치가 심볼을 조용히 버리던 문제

> **버전:** v1.0.3
> **기준일:** 2026-09-01 (KST)
> **Git 태그:** `v1.0.3` (커밋 후)
> **이전 버전:** [v1.0.2](./v1.0.2.md)
> **목적:** `/api/v1/quotes/batch`가 심볼 수가 많아지면 대부분을 조용히 버리던 원인을 규명하고 고친다. (v1.0.2 릴리스 노트 「미해결」 항목)
> **범위:** 백엔드(시세 서비스·핸들러) + 프론트엔드 1줄(뉴스 심볼 상한). DB 스키마·배치 변경 없음.

## 1. 한 줄 요약

**원인은 쿼터도 동시성도 아니라 「목록인데 목록 모드가 아니었던 것」이다.** 배치가 심볼마다 상세 화면과 같은 경로를 타면서 종목당 상류 호출로 내려갔고(실측 **한 요청에 `/candles` 142회**), Toss 한도에 걸려 요청 마감(10초)을 넘기자 아직 못 푼 슬롯이 통째로 버려졌다. 이 함수에 `withListMode`를 붙이고 가격을 배치로 한 번만 받게 하니 **42개 요청 · 29개 반환 · 13.9초 → 41개 반환 · 0.32초 · 상류 캔들 호출 0회**가 됐다. 남은 1개(`179720` 머니무브, KONEX)는 저장된 종가가 아예 없는 종목이고, 이제 응답의 `missing`이 그 사실을 말한다.

## 3. 원인 — 실측

### 3.1 배치가 「목록」으로 취급되지 않았다

`BatchQuoteSummaries`는 심볼마다 `EnsureQuoteDetail`을 부르는데, 그 경로는 **상세 화면용**이다. 컨텍스트에 `withListMode`가 없으면 종목당 상류로 내려간다:

- `resolvePrevClose` → `fetchPrevClose` — 전 거래일 1분봉을 **페이지네이션으로 전부** 받는다(종목당 여러 번).
- `ensureQuoteDetailCached` → `refreshTerminalSnapshot` — 시세·호가·체결·캔들을 통째로 다시 받는다.
- `loadClosedMarketQuoteDetail` → `backfillClosedMarketFromToss` — 마감 후 체결·호가까지 받아 온다.
- `resolveRegularClose` → `fetchRegularSessionClose` — **마감 세션에서는 국내 전 종목이 이 분기를 탄다**(`quoteChangeUsesRegularClose("closed")`가 true).

같은 문제를 랭킹·관심종목 목록은 이미 겪고 고쳤다(`withListMode`, v0.10 계열). **배치만 빠져 있었다.**

### 3.2 측정 (2026-09-01 20:5x KST, 양 시장 마감)

42심볼 한 요청이 만든 API 로그(요청 창만 잘라냄):

```
GET /api/v1/candles     142
GET /api/v1/stocks       13
GET /api/v1/trades        4
GET /api/v1/orderbook     3

toss api rate-limit exceeded: /candles limit=20   35건
toss api failover: /candles group=MARKET_DATA_CHART  9건
toss api transient failure: context deadline exceeded 47건
858856d27cde/... GET /api/v1/quotes/batch 200 7.1kB 13.921933575s
```

같은 요청을 반복하면 **반환 집합이 매번 달라졌다**(29개로 개수는 같은데 심볼이 다름) — 심볼의 문제가 아니라 마감 경합이라는 증거다. 「7개씩 나누면 전부 온다」던 관찰도 같은 이유였다(사용자가 나눠 시험한 7개가 전부 매번 성공하던 쪽이었다).

### 3.3 마감을 만든 것은 `REQUEST_TIMEOUT_SECONDS`

기본 10초(`config.go`). `chi`의 Timeout이 컨텍스트를 끊으면 `BatchQuoteSummaries`의 goroutine이 `ctx.Err() != nil`에서 빈손으로 돌아오고, 해결 못 한 슬롯은 `filled[i] = false`로 남아 **조용히 버려졌다**. 응답이 13.9초인 것은 이미 나간 상류 요청이 풀리는 시간이다.

**마감을 늘리는 것은 답이 아니다.** 늘려도 상류 호출은 목록 길이에 그대로 비례하고, Toss 한도에서 초선형으로 나빠진다(기존 실측: `/quotes` limit 5/10/20/40/100 → 0.18/1.9/6.4/58/90초).

### 4.1 왜 ①(meta 보고)을 골랐나

제안된 셋 중 ②(부분 재시도)와 ③(상한 축소)은 **증상을 나눠 담을 뿐 상류 호출을 줄이지 않는다** — 인프라 제약(OCI Always Free · DB 1 ECPU · Toss 한도)에서 가장 피해야 할 방향이다. 원인을 없애고 나니 재시도할 것도 상한을 낮출 이유도 없어졌고, ①만 남겨 **「없는 종목」과 「시간이 모자란 종목」을 호출부가 구분**하게 했다.

### 4.2 응답 예

```json
{ "data": [ … 41건 … ], "limit": 100, "missing": ["179720"], "source": "toss" }
```

`179720`(머니무브, KONEX)은 카탈로그에는 있으나 `stock_daily_closes`에 행이 **0개**다 — 다시 물어도 같은 답이라는 뜻이고, FE는 이때만 종목코드를 그린다. `deadline: true`가 붙었을 때만 재요청이 값어치가 있다.

## 5. 사이드 이펙트·호환

| 항목 | 영향 |
|---|---|
| 마감 세션 목록 등락률 기준 | 「당일 정규장 종가 대비」 → **「전일 종가 대비」**. 홈 랭킹과 같아졌다(실측 삼성전자 두 화면 모두 −2.11%). 공식 일별 종가와의 평균오차는 2.47%p → **0.83%p**로 줄었다 |
| 시세 정밀도 | 아무도 보고 있지 않은 종목은 「최신 체결가」가 아니라 「배치 마지막가」. 상세 화면·스트림은 목록 모드가 아니라 그대로 |
| 응답 스키마 | 필드 **추가만**. 기존 FE는 무시해도 동작한다 |
| 다른 호출부 | 뉴스 브리핑·리서치·스탬프·샘플이 `BatchQuoteSummaries`를 그대로 쓴다 — 전부 목록이라 같은 이득을 본다 |

**남은 것(이번 범위 밖):** `currentPrice` 자체가 마감 후 시간외 가격이라 공식 종가와 다르다(평균 0.66%, 이번 변경 **전에도 0.71%**). 앱 전역이 같은 값을 쓰므로 화면 간 불일치는 없다. 마감 세션 목록에 `stock_daily_closes`의 확정 종가를 쓰면 0에 가까워질 것으로 보이나, 「현재가」의 정의를 바꾸는 일이라 별도 판단이 필요하다.
