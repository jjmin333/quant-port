# Quant Port v1.0.2 — 뉴스 모바일 정리 · 종목 언급 집계를 서버로

> **버전:** v1.0.2
> **기준일:** 2026-09-01 (KST)
> **Git 태그:** `v1.0.2` (커밋 후)
> **이전 버전:** [v1.0.1](./v1.0.1.md)
> **목적:** 모바일 뉴스 화면의 사용자 피드백 9건을 처리한다.
> **범위:** 프론트엔드 + 백엔드(읽기 전용 집계 엔드포인트 1개 추가). DB 스키마·배치 변경 없음.

---

## 1. 한 줄 요약

「뉴스 흐름이 최근 기사로만 판단하는 것 같다」는 지적이 정확했다 — **뉴스 목록 100건이 덮는 시간이 34분**이라, 그 위에서 센 모든 숫자가 「오늘」이 아니라 「지난 30분」이었다. 「많이 언급된 종목」을 「오늘의 키워드」와 같은 방식으로 **서버 집계(최근 1,000건)**로 옮겼고, 그 김에 종목명·해외 티커 문제가 함께 풀렸다. 모바일에서는 첫 기사까지 **1,129px → 683px**.

## 3. 원인 — 실측

### 3.1 표본이 34분이었다 (#1 #9)

`/api/v1/news/domestic`이 돌려주는 100건의 발행시각 범위:

```
n=100   newest=2026-09-01 16:47:39   oldest=2026-09-01 16:14:00   span=0.56h
```

`buildNewsFlow()`는 이 100건만 세면서 카드는 **24칸**을 그렸다. 23칸은 구조적으로 영원히 비어 있고, 「최근 24시간」이라는 라벨은 거짓이었다. 같은 표본 위에서 센 「SK하이닉스 15건」도 실은 **「지난 34분에 15건」**이라, 새로고침할 때마다 순위가 뒤집혔다.

「오늘의 키워드」가 [v0.10.1](../../v0/v0.10/v0.10.1.md)에서 **같은 이유로 이미 서버로 옮겨져 있었다.** 종목 언급만 화면에 남아 있어서, 같은 화면의 두 줄이 서로 다른 기간을 말하고 있었다.

### 3.2 종목코드로 보인 것은 로딩 플레이스홀더였다 (#6)

API는 정상이다 — 57개 심볼 전부 이름이 온다(`0219E0` → `KODEX 200커버드콜액티브`). 문제는 화면이 쓰던 표현이었다:

```tsx
{quote?.name || mention.symbol}   // 시세가 오기 전 = 종목코드
```

첫 프레임에 `000660 · —`, 시세 배치가 돌아온 뒤 `SK하이닉스 · +1.37%`. 사용자에게 그건 로딩이 아니라 **「종목코드가 뜨는 버그」**였다. **아직 안 온 것과 못 찾은 것이 같은 빈 맵으로 보이던 것**이 근본 원인이다.

### 3.3 제목은 flex가 눌러서 잘렸다 (#7)

행 컨테이너가 `max-h-20`(80px) + `overflow-hidden`인데 실제 내용은:

```
배지줄 21 + 제목 2줄 36 + 요약 2줄 34 + gap 8 = 99px
```

넘치는 만큼 flex 항목이 압축되어 **`h2`가 26.6px로 눌렸고**(2줄에 필요한 35.8px보다 작다), `overflow-hidden`이 남은 부분을 **글자 중간에서 가로로** 잘라 냈다. `line-clamp-2`는 두 줄을 그려 놨는데 상자가 그만큼 없었다.

### 3.4 pill이 두 벌이었다

`NEWS_INDEX_PILLS`에 `005930`·`000660`·`005380`이 박혀 있었다. 그 옆을 집계 종목이 채우면서, 오늘처럼 그 셋이 실제 상위권이면 **같은 줄에 삼성전자가 두 번, SK하이닉스가 두 번** 섰다. 코드 주석은 이미 「박아둔 pill 대신 실제 언급 종목을 붙인다」고 적혀 있었지만 목록에서 빼는 일이 빠져 있었다.

## 4. 구현

### 4.1 백엔드 — 「많이 언급된 종목」 집계

`TopKeywords`와 같은 자리·같은 모양이다. 파생 테이블로 최신 1,000건을 먼저 좁히면 `idx_news_market_published`(market, published_at DESC)를 앞에서부터 읽고 끝나므로 `JSON_TABLE`이 표 전체를 펼치지 않는다.

`stocks`를 **INNER JOIN** 한 것이 이 쿼리의 두 번째 값어치다 — 이름이 함께 오고(#6), 카탈로그에 없는 심볼(해외 티커·오탐 태그)이 자동으로 걸러진다(#4). 국내는 `asset_type='domestic'`까지 건다.

실측:

| 시장 | 표본 | 응답 | 상위 |
|---|---|---|---|
| domestic | 1,000건 | 117ms (콜드) | SK하이닉스 129 · 삼성전자 129 · 현대차 35 |
| us | 1,000건 | — | 엔비디아 148 · 테슬라 51 · 마이크론 49 |

국내 결과에 **NVDA가 없다.**

### 4.2 프론트 — 로딩과 미해결을 구분

`useSymbolQuotesState()`가 `{ quotes, loading }`을 돌려준다. 칩은 세 갈래로 그린다:

| 상태 | 표시 |
|---|---|
| 시세 있음 | 이름 + 등락률 |
| 배치 오는 중 | **같은 크기의 빈 자리** (줄이 흔들리지 않게) |
| 정말 못 찾음 | 종목코드 (아무것도 없는 것보다 낫다) |

기존 `useSymbolQuotes()`는 그 위의 얇은 껍데기로 남겨 다른 두 호출부(홈 뉴스 카드·관련 종목 패널)를 건드리지 않았다.

## 6. 남은 문제 — `/api/v1/quotes/batch`가 심볼을 버린다

이번 범위 밖이지만 조사 중 재현했다. **뉴스와 무관한 전역 문제다.**

```
63개 요청 → 27개 반환, 14.1초
같은 심볼을 7개씩 나눠 요청 → 7개 전부 정상
```

심볼 자체는 조회 가능한데 큰 배치에서만 떨어져 나간다. `BatchQuoteSummaries`가 해결하지 못한 슬롯을 **조용히 버려서**(`filled[i] = false`) 호출부는 이유를 알 수 없다. 그래서 기사 하단 칩 일부는 이번 수정 뒤에도 종목코드로 남는다 — 이름을 붙일 시세가 오지 않기 때문이다. 별도 작업으로 분리했다.
