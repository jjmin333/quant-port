## 한 줄 요약

Azure로 번역기를 바꾼 뒤 **이틀 동안 해외 제목 번역이 사실상 전부 실패**하고 있었다.
그런데 실패가 조용해서 — 제목이 영어로 남을 뿐 오류가 없다 — 아무도 몰랐고, 같은
24건이 2분마다 다시 나가며 **하루 100만 자**를 태웠다. 무료 한도(월 200만 자)의
75%가 이틀에 사라졌다.

---

## 1. 자리표시자가 Azure에서 안 살아남았다

회사 이름은 번역기에 맡기지 않고 자리표시자로 잠갔다가 되돌린다(`translate/names.go`).
그 자리표시자 모양은 **자체 모델(LMT-60) 기준**으로 골랐던 것이고, 엔진을 바꾸면서
그대로 깨졌다. Azure는 글자 뒤의 숫자를 낱말에서 떼어낸다:

```
$QPZ0: Ignore The Usual Naysayers    → $QPZ 0: 평소 부정적인 말을 무시하라
… Increases Stock Holdings in $QPZ0  → 알렉타…, $QPZ년 주식 보유 증가   (!)
```

`RestoreNames`가 자리표시자를 못 찾으면 **빈 문자열**을 돌려준다(주어가 사라진
제목을 내보내느니 다음에 다시 시도한다는 규칙). 빈 결과는 `headline_ko`를 비워 두고,
비어 있는 행은 다음 회차의 질의에 **또 잡힌다.**

### 실측 (2026-09-14)

| 지표 | 값 |
| --- | --- |
| 그날 Azure 요청 | **12,559건** |
| 그날 보낸 문자 | **1,069,514자** |
| 그날 새로 들어온 해외 기사 | **511건** |
| 낭비 비율 | **약 96%** |
| 9월 누계 (가동 이틀) | **1,496,453 / 2,000,000자 (74.8%)** |

### 고친 방법

접미사를 숫자에서 **글자**로 바꿨다. 같은 제목 틀 셋으로 재 봤다:

| 후보 | 생존 |
| --- | --- |
| `$QPZ0` (기존) | 0/3 |
| `$AAPL0` | 0/3 |
| **`$QPZA`** | **3/3** |
| `QPZA` · `XQPZAX` · `ZQZA` | 3/3 |

두 글자 고정폭(`$QPZAA`, `$QPZAB`, …)을 쓴다 — 한 글자면 이름이 27개를 넘을 때
`$QPZA`가 `$QPZAA`의 접두가 되어 되돌리기가 서로를 먹는다. 청구 문자는 제목당 1~2자
늘어난다.

Azure 공식 「동적 사전」(`<mstrans:dictionary>`)도 4/4 통과했지만 **마크업이 그대로
과금돼** 이름 하나에 70자가 붙는다(자리표시자는 6자) — 기각했다.

## 2. 원인은 하나였지만 구조가 셋이었다

자리표시자만 고치면 이 사고는 끝난다. 그런데 **다음 실패도 같은 모양으로 돌아온다** —
조용히, 청구서에만 보이게. 그래서 원인이 아니라 구조에 셋을 뒀다.

**㉠ 재시도 상한** (`translate_attempts`, migration 071). 세 번 실패한 제목은 영어로
남긴다. **예산에 걸려 못 보낸 회차는 세지 않는다** — 그건 제목의 문제가 아니라 그날
형편의 문제라, 한도가 찬 날이 그 제목들의 기회를 영구히 태우면 안 된다.

**㉡ 묶음 요청.** Azure는 한 요청에 100건을 싣는 API인데 우리는 1건짜리 슬라이스를
스물네 번 보내고 있었다. 이제 한 회차가 한 왕복이다 — 배포 후 실측 **24건 → 요청 1회**.

**㉢ 7일 창** (`translationWindowDays`). 목록은 최신부터 읽히고, 3주 지난 제목을 여는
사람은 거의 없다. 재시도 상한이 생기면서 쌓이는 「상한에 닿은 행」을 이 질의가 매번
지나가지 않게 하는 효과도 있다.

## 3. 하루치를 상수로 두지 않는다

무료 등급(F0)은 **월** 한도만 있다. 그 상태의 실패 모양이 나쁘다 — 한도를 다 쓰면
남은 날이 통째로 0이 된다. 실측 신규 해외 기사는 하루 429~2,845건, 제목 평균 68자라
전량 번역은 **월 약 2.5M자**로 한도를 넘는다.

고정 하루 한도(2M/31 = 64K)도 답이 아니다. 이미 1.5M을 쓴 달에도 64K를 허락하므로
22일쯤 월 벽에 부딪히고 거기서부터 또 0이다.

`SpreadMonthlyTokens`가 하루치를 **매번 다시 계산**한다:

```
오늘치 = (월 한도 − 어제까지 쓴 양) / 오늘 포함 남은 날 수
```

평상시엔 64K와 같은 값이고, 이번 사고 다음 날(9/15) 기준으로는 **약 30K/일**로
저절로 내려가 9월의 남은 날에 고르게 퍼진다. 나누는 기준이 「어제까지」인 이유는,
오늘 쓴 것까지 빼면 하루치가 쓸수록 줄어들어 끝에 닿지 않는 계단이 되기 때문이다.

### 배포 후 실측

| 시각 (UTC) | 그날 문자 | 그날 요청 | 비고 |
| --- | --- | --- | --- |
| 08:08 (배포 직전) | 1,088,568 | 12,810 | 실패 루프 |
| 08:22 (검증용 한도 개방 후) | 1,092,484 | 12,812 | **2회 요청에 50여 제목 번역 성공** |
| 08:45 | 1,092,484 | 12,812 | **23분간 증가 0** |

번역 결과 표본 (이름 복원 포함):

```
Nvidia (NVDA) Looks Cheap on Piper's Forecasts …
  → 엔비디아(NVDA)는 파이퍼의 예측에 비해 다소 저렴해 보이지만 …
Qualcomm (NASDAQ: QCOM) Loses Apple Modem Revenue …
  → 퀄컴 (나스닥: QCOM) 모뎀 수익 손실 애플 …
```

## 4. 별칭 관리 화면 (`/admin/aliases`)

2026-09-13에 별칭을 Go 소스의 map에서 표로 옮겼다. 옮긴 이유는 속도가 아니라
**한 줄 고치려면 배포를 해야 했다**는 것이었는데, 표만 만들고 화면을 안 만들면 그
이유가 절반만 이뤄진다 — 여전히 SQL을 쳐야 한다.

DB 콘솔(`/admin/database`)로 충분하지 않은 이유가 셋이다.

- **갈래마다 「대상」의 뜻이 다르다.** `brand`는 영문 표기(소문자), `symbol`은 종목
  심볼(대문자). 화면이 갈래를 먼저 묻고 칸 이름과 예시를 바꾼다.
- **심볼 오타는 조용히 실패한다.** 없는 심볼을 적으면 오류가 안 나고 그냥 아무 기사도
  안 붙는다. 이제 카탈로그에 대조해 **거부**한다.
- **캐시를 다시 읽어야 한다.** 쓰기 뒤에 이 프로세스의 스냅샷을 곧바로 갱신한다
  (워커 여덟은 자기 TTL 10분으로 따라온다 — 화면이 그 지연을 적어 둔다).

한 글자 별칭도 거부한다 — 「A」 하나가 붙는 순간 그 종목에 세상의 절반이 태깅된다.

실제 DB에 대고 한 바퀴 확인: 추가 → 중복 409 → 캐시 반영 → 끄기 → 캐시에서 빠짐 →
같은 값 저장(오류 없음) → 삭제 → 두 번째 삭제 404 → 카운트 원복(76/122/0).

## 5. AI 카드 — 「AI 핵심 요약」 하나로

| | 이전 | 이후 |
| --- | --- | --- |
| 제목 | AI 분석 | **AI 핵심 요약** (종목 모달과 같은 이름) |
| 생성 시각 | 「9. 14. 오전 11:25 생성」이 카드 폭을 한 줄 먹었다 | 없음 |
| 「분석 탭 ›」 | 간단/상세 옆에 나란히 | 없음 (같은 일을 하는 문이 둘이었다) |
| 상세 | 네 칸 그리드 | **이어진 산문** |
| 종목 모달 | 전문 고정 | **간단/상세 토글, 기본 간단** |

상세를 네 칸으로 나누면 넷이 서로 다른 이야기처럼 읽히는데, 실제로는 한 번의 호출이
쓴 한 편의 글이다.

## 6. 투자 리포트 — 글을 누르면 글이 나온다

이 메뉴의 목적은 남이 쓴 투자 인사이트를 **읽는** 것인데, 카드를 누르면 글이 아니라
계기판 모달이 떴고 그 모달에는 **댓글이 없었다.**

- **카드 = 링크.** 모달 제거, 사이드 레일 항목도 진짜 앵커로.
- **목록 카드 단순화.** 스파크라인·5축 막대·가격대 축·진행 막대는 상세로 내렸다.
  제목·발췌·작성자가 주인공이고 성과는 알파 하나만 남는다. 모바일에서는 표지가
  전체 폭 배너(235px)였던 것을 88px 사각형으로 옆에 세웠다 — 화면 하나에 카드 1장
  → 3장.
- **상세는 본문이 먼저.** 제목 → 한 줄 띠(종목·기준가→목표가·D-n) → **본문** →
  주장과 성과 → 발행 시점 근거 → 독자 반응. 계기판이 제목과 본문 사이에 서 있어서
  글을 읽으러 온 사람이 화면 하나를 지나야 첫 문장에 닿았다.
- **댓글이 이름을 얻었다.** 「독자 반응」 절 아래로 모았고, 한 줄 입력칸을 여러 줄로
  바꿨다(Enter는 줄바꿈, 등록은 버튼 또는 ⌘/Ctrl+Enter). 비로그인으로 등록을 누르면
  **401로 조용히 죽던 것**을 로그인 안내로 바꿨고, 실패는 이제 화면에 보인다.
