## 1. 같은 종목이 두 값이던 것 (사용자 지적 1)

### 증상

AI 랭킹 목록 **$11.36**, 같은 순간 그 종목 상세 헤더 **$11.39**. 상세가 다음 정규장까지
그 값을 붙잡고 놓지 않았다.

### 원인 — 사다리의 앞 세 칸이 정규장의 잔해다

목록(`listMode`)은 배치 가격 캐시(`market:price:v1`)로 끝낸다. 상세는 같은 함수에서
**체결 → 호가중간 → 형성봉 → 배치 캐시** 순으로 내려가는데, 앞의 셋이 하나라도 값을
내면 캐시는 읽히지도 않는다.

프리·애프터 세션에서 그 앞 셋이 전부 정규장의 잔해다 — 체결 캐시에는 정규장 마지막
체결이, 형성봉에는 정규장 봉이 남아 있다. **배치 가격만 시간외 호가를 따라 움직인다.**

체결만 고쳐서는 안 되는 근거가 실측에 있었다. 2026-09-04 21:13 KST 미국 프리마켓에서
**FDX가 상세 323.17 · 목록 324.31로 3회 표본 내내 고정**이었고, 그 종목의 체결 목록은
**비어 있었다** — 갭을 만든 것은 체결이 아니라 그 아래 두 줄이었다.

### 고친 것

배치 가격 캐시를 **기준**으로 올렸다. 그 캐시는 파생값이 아니라 가격이 모이는 곳이다 —
1초 폴러가 채우고 웹소켓 체결도 같은 키에 쓴다(`applyStreamPrice`). 호가중간은 거래된
값이 아니라 호가의 산술 평균이고, 형성봉은 캔들에서 되짚은 값이다.

체결만은 캐시보다 앞설 수 있어(구독 종목은 체결 프레임이 먼저 온다) **시각으로 견준다** —
`MarketDataStore.GetPriceAt`이 캐시 봉투의 시각을 함께 돌려준다(예전에는 `_ = at`으로
버리고 있어 비교할 수단 자체가 없었다).

### 실측

| 종목 | 표본 | 목록 vs 상세 |
| ---- | ---- | ------------ |
| AAPL | 5회  | **0 bps** (둘 다 323.38 → 323.25로 함께 이동) |
| ADBE | 5회  | **0 bps** (둘 다 266.64 → 266.68로 함께 이동) |
| FDX  | 5회  | **0 bps** (324.57 고정 — 그 창에 체결 없음)    |

10종목 1회 표본에서도 8종목 완전 일치, 나머지 둘은 순차 측정 시차였다(위 5회 표본에서
0 bps 확인).

## 2. 안 움직였는데 깜빡이던 것 (사용자 지적 3)

원인이 **두 겹**이었다.

### ① 서버가 값과 무관하게 발행했다

`publishListPrice`는 가격이 캐시에 써질 때마다 불린다 — 즉 폴러의 **매 틱마다**, 값이
움직였는지와 무관하게. 화면은 그 이벤트 하나하나를 갱신으로 세어 셀에 색을 칠했다.

`lastPublished`(심볼 → 마지막으로 내보낸 가격)를 두고 같은 값이면 보내지 않는다.
`sync.Map`인 이유는 발행이 폴러 고루틴들과 웹소켓 플러시에서 **동시에** 일어나고 키
집합이 거의 고정이기 때문이다.

### ② 화면이 「행이 바뀌었는가」로 판정했다

`applyListPriceTick`은 가격이 같아도 `updatedAt`이 다르면 `seq`를 올렸다. 그런데 그
시각은 「캐시에 쓴 시각」이라 **값이 안 변해도 틱마다 달라진다.**

그리고 `withStreamPrices`는 가격과 등락률 **문자열이 둘 다** 같아야 행을 그대로 뒀는데,
행이 들고 있는 등락률은 서버가 반올림한 `"0.29"`이고 화면이 다시 계산한 값은
`"0.2898550724637681"`이다 — **가격이 한 푼도 안 움직였는데 매번 달랐다.** 그래서 폴링이
목록을 새로 받을 때마다 전 종목이 한 번씩 깜빡였다.

둘 다 **숫자로** 비교하도록 고쳤다.

### 실측

| 항목                                | 결과                                      |
| ----------------------------------- | ----------------------------------------- |
| SSE 이벤트 (8종목 · 20초 · 1초 주기) | **20건** (이론상 160건) — 그중 실제 변화 16 |
| 남은 4건                            | 구독 직후 스냅샷과 같은 값 1회 (아래 참조) |
| 화면 헛플래시 (24셀 · 15초 · 75표본) | **0건**                                    |
| 플래시 방향                         | $156.96 → $157.00에 **빨강**(상승) 확인    |

남는 4건은 설계상 알려진 자리다: 구독자가 없는 동안의 변화는 `HasSubscribers` 가드가
먼저 끊어 `lastPublished`에 안 남으므로, 새 구독자의 첫 틱이 스냅샷과 같은 값을 한 번 더
받을 수 있다. 화면 쪽 가드가 그 한 번을 흡수해 **플래시로는 보이지 않는다.**

## 3. 1초 주기 (사용자 요청 5)

09-04 오전에 2초로 모았던 것을 같은 날 1초로 내렸다. **되돌린 게 아니라 조건이 달라졌다.**

2초를 고른 근거는 「폴링이 1초로 만든 값의 절반을 아무도 안 읽는다」였다. 가격이 SSE로
옮겨 가면서 만든 값이 만드는 즉시 구독자에게 밀려 나가 **전부 읽힌다.**

| 검토 항목       | 판단                                                                 |
| --------------- | -------------------------------------------------------------------- |
| 상류 한도       | `/prices`는 벌크(200종목/호출) → 초당 2~3호출, `MARKET_DATA` 한도 15 |
| 상류 갱신 주기  | 실측 median **999ms** — 1초가 소스 박자와 일치(2초는 절반을 건너뛰었다) |
| 이벤트 증가     | **없다** — 2번의 「값이 바뀔 때만」이 함께 들어가 프레임 수는 변화 횟수에 붙는다 |
| 상수 위치       | BE `marketPricePollInterval` · FE `PRICE_POLL_MS` 둘뿐               |

`use-quote-detail.ts`가 `price-cadence.ts`를 import하지 않고 자기 `POLL_MS = 2_000`을
들고 있었다 — 상수를 한 곳에 모으는 일이 실패하는 방식이 정확히 이것이라, 남은 세 곳
(`use-quote-candles` · `MARKET_RADAR_QUOTE_POLL_MS` · `MARKET_RADAR_PRICE_POLL_MS`)도
함께 공용 상수로 돌렸다.

### 공용 부품 둘

| 파일                              | 하는 일                                          |
| --------------------------------- | ------------------------------------------------ |
| `fe/src/lib/value-flash.ts`       | 판정 규칙(순수 함수) — DOM도 타이머도 없다        |
| `fe/src/components/ui/value-flash.tsx` | 타이머와 색                                  |

| `fe/src/hooks/use-live-quotes.ts` | 심볼 목록 → 이름·가격·등락률(배치 1회 + SSE)     |

규칙이 넷이라 부품으로 모았다 — 첫 값에는 색이 없다 / 같은 값에는 색이 없다 / 종목을
갈아 끼우면 기준을 옮긴다(`resetKey`) / 색은 다음 갱신 전에 꺼진다(700ms < 1초 주기).
넷 중 하나만 빠져도 증상은 「가끔 이상하게 깜빡인다」로 똑같고, 복사본이 다섯이면 그
넷을 다섯 번 맞춰야 한다.

### 적용 범위

가격만이 아니라 **가격에서 나온 금액 전부**다(요청 4의 「평가금액」): 보유 목록의
현재가·평가금액·평가손익(표·모바일 카드 양쪽), 관심 목록 현재가, 상세 헤더(`QuotePrice`의
`flashKey`), 실시간 차트·AI 랭킹 행.

**감싸지 않는 것**: 평단·목표가처럼 사용자가 입력한 값. 시세로 움직이지 않으므로 감싸면
화면을 처음 열 때만 한 번 뜨는 색이 되어 뜻이 없다.

## 6. 로그인이 필요한 동작 (사용자 요청 2)

### 스탬프 실패 문구가 화면에 눌어붙던 것

`stamp-button.tsx`의 `absolute` 말풍선은 지우는 길이 **하나도 없었다** — 닫기 버튼도,
타이머도, 다른 곳을 눌렀을 때의 정리도. 종목을 바꾸는 것만이 유일한 탈출구였다.
8초 자동 소멸 + 닫기 버튼 + `role="status"`를 넣었다.

### 401을 원천 차단

`useLoginGate`가 규칙 하나를 들고 있다: 버튼 문구 · 눌렀을 때의 분기 · 돌아올 자리.
목표가 모달만 갖고 있던 것을 스탬프 생성·보유 등록·관심 추가·스탬프 찍기로 넓혔다.

**「비활성화」 대신 「로그인으로 보낸다」로 구현했다.** 사용자가 같은 문장에서 기준으로 든
목표가 모달이 그렇게 동작하고, 완전히 잠그면 비로그인 사용자는 이 자리에서 로그인으로
갈 길을 잃는다(`disabled` 버튼은 툴팁조차 안 뜬다). 요청에 함께 적힌 목적 —
**「오류 원천차단」** — 은 401이 날 요청을 아예 보내지 않는 것으로 달성된다.

문구는 버튼마다 다르다. 처음에 셋 다 「로그인하고 저장」으로 맞췄더니 종목 헤더에 **같은
글자 셋**이 나란히 서서 어느 것이 무엇인지 사라졌다 → 「로그인하고 스탬프」·「로그인하고
보유 등록」·「로그인하고 목표가 설정」.

**실측**(비로그인 · `/analysis?symbol=005930`): 버튼 클릭 → `/stamps` 요청 **0건** ·
다이얼로그 안 열림 · `/login?next=%2Fanalysis%3Fsymbol%3D005930`으로 이동.
모바일 375px에서 ⋯ 를 펴면 아이콘 셋의 `aria-label`에 같은 문구가 실리고 가로 넘침 없음.

## 7. 요청이 너무 잦던 것 (사용자 지적 11)

사용자 선택: **배치 API + 한도 소폭 상향**.

`useUpcomingEvents`의 머리글에 「배치 엔드포인트가 없어 종목당 1요청이다」라고 적혀
있었는데 **그 문장이 오래전에 거짓이 됐다** — `/stocks/earnings/batch`도, 그것을 부르는
`fetchEarningsBatchClient`도 이미 있었고 이 훅만 옛 경로에 남아 있었다. 관심·보유·뉴스
레일 세 화면이 쓰고 최대 12종목이라, 화면 하나를 여는 것만으로 요청 12개가 한꺼번에
나갔다.

레이트리밋 근거 주석이 **정상 폴링만 세고 화면 전환을 안 셌다.** 화면을 여는 순간은
모든 위젯이 첫 데이터를 동시에 부르고 앞 화면의 요청이 아직 살아 있다.

**실측**: 5개 화면 연속 이동 → 총 **26요청 · 전부 200 · 429 0건** ·
`earnings/batch?symbols=NVDA,AAPL,TSLA` **1건**.

## 8. 「삼전닉스」 (사용자 지적 10)

「37% 빠진 삼전닉스…노무라 "심각한 저평가"」에 종목이 하나도 안 붙었다.

이름 인덱스는 **상장명**으로 만든다. 「삼전닉스」는 회사가 등록한 이름이 아니라 시장이
두 종목을 묶어 부르는 말이라 그 표에 있을 수 없다. 기존 별칭 표(`HangulNameAliases`)로도
못 푼다 — 그쪽은 **읽기 하나 → 종목 하나**이고, 여기 필요한 것은 **한 단어 → 종목 여럿**이다.

`news_symbol_nickname.go`(신규)에 통칭 표를 따로 뒀다. 별도 표인 이유: 기존 별칭은
「영문 상장명의 한글 읽기」라 회사가 바뀌지 않는 한 안 바뀌지만, 통칭은 시장이 지어낸
말이라 유행을 탄다. 정밀도 규칙 넷(세 글자 이상 · 종목을 가리킬 때만 쓰이는 말 ·
상장명으로 되짚어 푼다 · 경계 검사)을 지킨다.

재태깅 표식을 `news:retag:v7:` → **`v8:`** 로 올려 기존 기사를 다시 훑게 했다.

**실측**: 그 기사가 `["005930","000660"]`. 같은 스윕에서 「삼전 67만원·하닉 470만원」,
「삼전·닉스 다시 뛴다」 등 9건이 함께 붙었고, 국내 200건 중 89건이 종목을 갖는다.

## 9. 국내 뉴스에 해외 종목 (사용자 지적 12)

`NewsUpcomingEventsCard`가 `mySymbols`를 시장 필터 없이 받았다. 심볼은 사용자의
보유·관심에서 오는데 그 목록에는 두 시장이 섞여 있다.

`isDomesticAsset(assetType, symbol)`로 거른다. 자산 구분이 없으면 **심볼 모양**으로
판단하도록 넓혔다(국내는 여섯 자리 숫자) — 예전에는 빈 값을 무조건 국내로 봐서, 자산
구분을 안 실어 주는 경로의 미국 티커가 국내 목록에 섞이면 KRX가 닫히는 15:30에 스트림이
끊겨 미국 정규장 내내 값이 멈췄다.

**실측** `/news/domestic`: 삼성전자 · SK하이닉스 · NAVER(전부 6자리 코드), 해외 0건.
덤으로 이름이 「005930」처럼 종목코드로 뜨던 것을 배치 응답의 이름으로 고쳤다(요청 추가 없음).
