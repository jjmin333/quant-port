**wp-admin·php·zip 스캔이 Next 라우터까지 들어와 요청당 232ms를 태우고 있었다** — 이제
nginx가 응답을 만들지 않고 끊는다(444). 그리고 뉴스 목록의 종목·지수 칩은 화면을 떠나는

## 1. 스캐너 노이즈를 엣지에서 끊는다 (사용자 요청 1)

### 무엇이 잘못돼 있었나

사용자가 붙인 로그:

```
[2026-09-05 22:11:34.420 KST] user= name= GET /wp-admin/install.php?step=1
 GET /wp-admin/install.php?step=1 404 in 232ms
   (next.js: 13ms, proxy.ts: 24ms, application-code: 195ms)
```

그 아래로 `.zip` GET이 줄줄이 이어졌다. 사람이 아니라 인터넷을 훑는 봇이다.

문제는 **404를 만드는 데 232ms를 썼다**는 것이다. nginx를 지나 Node로 가서 `proxy.ts`가
요청 로그를 찍고, Next 라우터가 매칭에 실패한 뒤, not-found 페이지를 렌더해서 돌려준다.
봇 한 대가 초당 수십 건을 쏘면 그 195ms짜리 렌더가 **실제 사용자의 시세·뉴스 요청과 같은
Node 이벤트 루프를 놓고 경합한다.**

### 고친 것 — 판단할 것이 없으면 앱까지 보내지 않는다

`deploy/nginx/block_noise.conf` 한 벌을 `app_routes.conf`·`app_routes.host-fe.conf`의 **맨
위**에서 include 한다(정규식 location은 적힌 순서대로 검사하고 첫 매치가 이긴다). 그래서
dev(평문 `nginx.dual.conf`)와 prod(`nginx.tls.conf`)가 **같은 규칙**을 쓴다.

끊는 것은 셋이다.

| 갈래 | 예 |
| ---- | -- |
| 확장자 | `.php` `.phtml` `.asp` `.jsp` `.cgi` `.sh` `.exe` `.bak` `.sql` `.dump` `.zip` `.tar.gz` `.7z` `.war` `.pem` … |
| 숨김 파일 | `/.env` `/.git/config` `/.aws/credentials` — **`.well-known`만 예외**(ACME 챌린지) |
| CMS·관리도구 | `/wp-*` `/wordpress` `/phpmyadmin` `/administrator` `/vendor/` `/actuator` `/telescope` `/cgi-bin/` `/boaform` … |

**응답 코드는 444**다. 404를 돌려주면 상태줄·헤더·본문을 만들어 보내야 하고, 봇에게
「여기 서버가 산다」는 답을 준다. nginx 전용 코드 444는 응답을 만들지 않고 커넥션을
그냥 닫는다 — 바이트 0, 렌더 0, Node 홉 0.

**로그는 끄지 않고 아예 남기지 않는다**(`access_log off`). 이 트래픽의 본질이 「양」이라,
끊어 놓고 줄을 계속 쓰면 디스크만 옮겨 담는 꼴이다(부트 볼륨 50GiB — `docker-compose.yml`
머리말).

**우리 라우트를 물지 않게** 패턴에서 뺀 이름들: `admin`(우리 화면이다 — 막는 것은 Joomla의
`/administrator`), `analysis` `market` `news` `earnings` `stocks` `dev` `api` `media`
`_next` `logos` 등. 업로드 이미지 키는 `.jpg|.png|.gif|.webp`로 끝나므로(`media/store.go`
의 `keyPattern`) 확장자 목록과 겹치지 않는다.

### 실측 (nginx 재기동 후)

```
/                        200      /wp-admin/install.php?step=1   끊김
/news/domestic           200      /backup.zip                    끊김
/api/v1/news/domestic    200      /site.tar.gz                   끊김
/health · /ready         200      /.env · /.git/config           끊김
/_next/static/…js        200      /wp-login.php · /xmlrpc.php    끊김
/admin · /analysis       200      /phpmyadmin/index.php          끊김
/market · /earnings/…    200      /vendor/phpunit/…/eval-stdin.php 끊김
/stocks/005930           200      /administrator/index.php       끊김
```

확인 명령(444는 curl이 「Empty reply from server」로 받는다):

```bash
curl -sS -o /dev/null -w '%{http_code}\n' http://localhost/wp-admin/install.php
```

## 2. 모바일 종목 헤더의 「NASDAQ …」이 잘렸다 (사용자 지적 2)

펼친 헤더의 둘째 줄은 `flex` 한 줄에 **현재가 · 등락 · 시장/시각 각주** 셋을 세우고,
각주에 `shrink-0`을 걸어 뒀다. `shrink-0`은 「줄이지 마라」는 뜻이라 자리가 모자라면
각주가 줄어드는 대신 **상자 밖으로 나가** 헤더의 `overflow`에 잘렸다 — 같이 붙어 있던
`truncate`는 줄어들 수 없는 요소에 말줄임표를 붙이지 못한다.

실측(375px, NVDA): 줄 폭 327 / 현재가 132 + 등락 161 + 간격 16 = 309 → 각주에 남은 자리
**18px**인데 「NASDAQ · 09.05 오전 08:50:00」은 **150px**이 필요했다.

해외 종목은 원화 환산까지 달고 나오므로 **어떤 축약으로도 한 줄에 셋이 들어가지 않는다**
(각주를 시각만 남겨도 95px). 그래서 줄을 접는다 — `flex-wrap`이면 들어갈 때는 한 줄이고
모자랄 때만 각주가 아랫줄 오른쪽으로 내려간다(`ml-auto`가 오른쪽 끝에 붙인다).

**결과**(375px NVDA): 각주 오른쪽 끝 483 → **351 = 줄 오른쪽 끝**. 헤더 81 → 98px.

## 3. 뉴스 카드 메타 줄의 배지가 흔들렸다 (사용자 지적 3)

언론사 배지가 **자기 글자만큼** 넓어지므로 그 뒤 키워드 배지의 시작점이 기사마다 달랐다.

실측(375px): 「매일경제」(56px) 뒤 키워드는 x=**164**, 「hosu-news」(75px) 뒤 키워드는
x=**183**. 목록을 세로로 훑으면 배지 기둥이 19px씩 좌우로 흔들린다.

메타 줄을 **격자**로 바꿨다 — 언론사 `4.75rem` · 키워드 나머지 · 시각 자기 폭.
4.75rem(76px)은 실측한 이름 중 가장 긴 것(「파이낸셜뉴스」·「hosu-news」 = 75px)이 들어가는
폭이다. 배지가 모두 같은 크기가 되므로 글자는 가운데로 둔다. 키워드 묶음은 `flex-nowrap` —
줄바꿈을 허용하면 두 번째 줄이 부모의 `max-h`에 잘려 어떤 기사만 배지가 반쯤 보인다.

**결과**: 열 개 카드의 키워드 시작점이 전부 x=**184**, 언론사 배지 폭 전부 76px.

## 4. 종목 뉴스 탭에서 기사가 앱 밖으로 나갔다 (사용자 지적 4)

`stock-news-panel.tsx`만 `window.open(link)`으로 새 탭을 띄우고 있었다. 앱의 다른 모든
자리는 `useNewsArticleModal`을 쓴다 — 그래서 같은 기사가 홈·지수 모달·종목 퀵룩에서는
번역·원문 셸과 「관련 종목·지수」를 달고 열리는데, **종목 화면의 뉴스 탭에서만** 언론사
사이트로 튕겨 나갔다. 지금은 그 훅을 쓴다(`pool`로 받아 둔 목록을 넘겨 「같은 이슈」 묶음도
함께 선다).

## 5. 「속보만」 필터 (사용자 요청 5)

최신순·인기순 오른쪽에 `🚨 속보 N` pill을 뒀다. **정렬이 아니라 필터**이므로 모양도
「내 종목」과 같은 pill이다.

판정은 목록·카드·티커가 이미 함께 쓰는 규칙 하나다(`isArticleBreakingNews`): 제목의
「[속보]」나 `속보` 태그 **그리고 24시간 이내**. 속보에는 시간 창이 있어 조용한 날에는
0건이 정상이므로, **건수를 칩에 적고 0이면 잠근다** — 눌러도 빈 목록만 나오는 필터는
고장으로 보인다(실적 화면의 「내 종목만」과 같은 규칙).

건수와 목록은 `lib/news-breaking-filter.ts`의 **같은 함수**에서 나온다. 두 자리에서 각자
`filter`를 쓰면 언젠가 한쪽만 조건이 바뀌어 「3건이라며 눌렀더니 1건」이 된다.

## 6. 종목·지수 칩은 **어디서 눌러도 같은 창** (사용자 지적 6)

앱 전체가 이미 퀵룩 모달을 갖고 있는데, **뉴스 목록의 칩만** 링크였다. 기사 아래
「삼성전자 +3.63%」를 누르면 `/analysis?symbol=…`로, 「코스피 +1.64%」를 누르면 `/market`
으로 화면을 떠났다. 기사를 훑던 사람이 종목 하나를 곁눈질하려다 목록에서 튕겨 나가고,
돌아오면 스크롤 위치도 필터도 사라져 있었다.

화면을 **떠나야 하는** 자리는 둘뿐이다 — 「실시간 차트」(`/market`)와 「AI 추천 랭킹」
(`/analysis`). 거기서는 종목을 고르는 것이 곧 그 화면의 목적이다.

### 왜 전역 제공자인가

칩은 목록 → 카드 → 기사 모달까지 여러 겹 안쪽에 있다. 창을 여는 함수를 props로
내려보내면 중간 컴포넌트 전부가 자기와 상관없는 인자를 들고 다녀야 하고, 한 군데만
빠뜨려도 그 화면의 칩만 다시 링크가 된다 — 지금까지가 정확히 그 상태였다.
`QuickLookProvider`를 `AppShell`에 한 번 두고 `useQuickLook()`으로 부른다.

**지수 폴링은 열었을 때만**: `useMarketIndices`는 30초 폴링을 붙이므로, 제공자가 그 훅을
늘 부르면 설정 화면에서도 지수 요청이 30초마다 나간다. 그래서 지수 모달은 **골랐을 때
마운트되는 별도 컴포넌트**(`IndexQuickLookHost`)로 감쌌다 — 닫으면 언마운트되고 구독이
끊긴다. 종목 쪽은 닫혀 있으면 아무것도 부르지 않으므로 그대로 둔다.

`href`는 남긴다 — 가운데 클릭·「새 탭에서 열기」·크롤러가 쓰는 진짜 주소다. 가로채는
것은 **평범한 왼쪽 클릭**뿐이고, 제공자가 없는 자리(껍데기 밖)에서는 예전처럼 이동한다.

## 7. 종목 퀵룩 모달을 넓힌다 (사용자 요청 7)

### 7-1 「최근 흐름」 → 「일별 종가」 · 20일 / 60일 / 전체

예전에는 일봉 스냅샷 **40포인트 고정**이었다(`useSparklineCandles`). 이름이 「최근 흐름」
이었던 것은 그 40개가 며칠치인지 화면도 모르기 때문이다 — 커버리지가 성근 종목은 40봉이
8개월에 걸쳐 있다.

지금은 지수 모달과 **같은 재료·같은 토글**을 쓴다: 일별 종가를 최대치(250)로 한 번 받아
클라이언트에서 자른다. 기간을 바꿔도 요청은 나가지 않는다. 이력이 아예 없는 종목은 예전
스파크라인으로 되돌아가며 제목도 「최근 흐름」으로 돌아간다.

기간 규칙은 `lib/daily-close-window.ts` 한 벌로 모았고, 그러면서 **「전체」의 뜻을
바로잡았다**: 예전 구현은 실제 봉 수가 겹치는 단계만 걸러 내면서 라벨은 그 단계의 이름을
그대로 썼다. 그래서 31행짜리 지수가 「20일 / **60일**」로 떴다 — 60일 버튼이 그리는 것은
31봉인데도. 같은 파일의 주석은 「20일과 전체 둘만 뜬다」고 적어 두었으니 코드가 아니라
주석 쪽이 맞았다. 이제 **가진 것을 다 그리는 단계는 「전체」**로 부른다.

### 7-2 AI 핵심 요약 + 최근 일별

둘 다 **일별 종가 응답에 이미 실려 오는 값**이다(추가 요청 0).

- **AI 핵심 요약** — `analysisSource === "llm"`인 **가장 최신 행**의 `aiSummary`. 규칙이
  만든 문장까지 「AI」라고 부르면 그 이름이 아무것도 구분하지 못하므로 `llm`인 행만 고른다.
  오늘 배치가 아직 안 돌았어도 어제 것이 있으면 보여 준다 — 자리를 비우면 「이 종목은
  요약이 없다」로 읽히는데 사실은 오늘 것만 없다. `llm` 행이 하나도 없으면 블록 자체가
  뜨지 않는다.
- **최근 일별** — 지수 모달과 **같은 표**(`DailyCloseMiniTable`로 공용화). 오늘 점수 하나만
  보여 주면 그것이 높은 건지 알 수 없다 — 어제·그제가 옆에 서야 58이 방향을 갖는다.

### 7-3 면책 문구 삭제

「2026-09-04 기준 · 점수는 정보이지 매매 신호가 아닙니다.」를 뺐다. 기준일은 제목 옆 점수
배지가 이미 달고 있고, 면책은 모든 창에서 같은 말을 반복하며 읽히지 않는 줄이 됐다.

### 7-4 헤더에 동작 다섯

가격·등락률 **위**에 관심 · 메모장 · 보유 · 스탬프 · 목표가(사용자가 지정한 순서).
이 다섯은 지금까지 랭킹 목록의 행과 종목 상세 헤더에 나뉘어 있어서, 뉴스나 홈에서 종목을
눌러 창을 연 사람은 무엇도 할 수 없었다 — 관심 하나 담자고 창을 닫고 랭킹으로 가야 했다.

로그인 규칙은 앱과 같다(`hooks/use-login-gate`): 창을 여는 넷은 비로그인에게도 열리고
막는 자리는 창 안의 저장 버튼, **관심은 창이 없으므로** `run()`으로 감싸 로그인으로 보낸다.

관심 여부는 앱 공용 저장소(`lib/watchlist-store`)를 `useSyncExternalStore`로 구독한다 —
복사해 두면 같은 종목을 다른 화면에서 담았을 때 이 창의 하트만 옛 상태로 남는다.

## 8. 발표가 하나도 없는 달 (사용자 지적 8)

국내 실적은 2·5·8·11월에 몰린다. 9월에 이 화면을 열면 **한 건도 없는 달**을 보게 되는데,
화면은 그 사실을 어디에서도 말하지 않았다: 위 스코어보드는 「0건」과 「—」 다섯 칸으로 서
있고, 달력은 31칸이 전부 빈 채로 그려지고, 아래 목록만 작은 글씨로 한 줄을 적었다.
사용자 입장에서는 **데이터가 없는 것인지 화면이 고장 난 것인지** 구분할 방법이 없다.

이제 그 달에는 **스코어보드를 세우지 않고**, 달력 카드가 정중앙에서 한 번만 말한다:

> **9월에는 국내 기업 실적 발표 일정이 없습니다.**
> 국내 기업 실적은 2 · 5 · 8 · 11월에 몰립니다. 위 화살표로 달을 옮겨 보세요.

**달 이동 줄은 그대로 남긴다** — 격자까지 통째로 감추면 다른 달로 갈 길이 함께 사라져
사용자가 갇힌다. 판정과 문구는 `lib/earnings-empty.ts` 한 곳에서 나온다(스코어보드를
감출 때와 달력에 문구를 낼 때가 반드시 같은 답이어야 한다). 로딩 중(`null`)은 비었다고
하지 않는다 — 잠시 뒤 달력이 채워지면서 화면이 자기 말을 뒤집는다.

## 9. 실적 일정 모바일 개선안 (사용자 요청 9)

구현이 아니라 **제안**이다 — `docs/mockups/earnings-responsive-v1.html`에 세 안을 PC·모바일
프레임으로 나란히 그렸다. 현재 화면의 실측 근거:

| 실측(375×640 본문) | 값 |
| ------------------ | -- |
| 스코어보드 높이 | 244px |
| 월 달력 높이 | 345px |
| 둘의 합 | **589px** — 목록이 첫 화면 밖에서 시작한다 |
| 목록 표 | `min-width: 900px` 9열 → **3열만 보임**, 손잡이 없는 가로 스크롤 |

- **A안(권장)** — 상단을 접고(요약 한 줄 띠 + 주 스트립) 목록을 카드로. 첫 화면 0건 → **6건**, 가로 스크롤 제거. 모바일 분기만 손대므로 데스크톱 위험 없음.
- **B안** — 모바일 탭 3개(요약·달력·목록). 첫 화면 8건으로 가장 많지만 「달력에서 고르고 목록을 본다」가 탭 왕복이 된다. 데스크톱은 2단 배치로 함께 개선.
- **C안** — 표를 지키고 모바일 열만 셋으로. 가장 작게 고치지만 상단 589px을 그대로 두면 값이 없다 — A안의 상단 접기와 함께 쓰는 조각.
