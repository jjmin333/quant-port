## 한 줄 요약

**호스트는 60초 만에 돌아왔는데 스택은 96분을 더 누워 있었다** — 컨테이너 13개가 전부
`restart: unless-stopped` 였지만 그 정책은 **도커 엔진이 살아 있을 때만** 동작하고,
Docker Desktop 이 `AutoStart=False` 라 부팅 후 엔진이 뜨지 않았다. 함께, 크래시 직전
로그에서 **해외 종목 하나가 국내 시세 39종목을 매 틱 떨어뜨리던** 별건 버그를 찾아 고쳤다.

## 1. 96분은 어디서 왔나

### 사고 타임라인 (실측)

| 시각 (KST) | 사건 | 근거 |
| ---------- | ---- | ---- |
| 22:07:52 | API 로그가 요청 처리 중 뚝 끊김 | `docker logs` 마지막 줄 |
| ~22:08:12 | 호스트 BSOD `0x0000000A` (IRQL_NOT_LESS_OR_EQUAL) | Event 1001 · `Minidump\090826-18953-01.dmp` |
| 22:08:51 | Windows 부팅 완료 | `LastBootUpTime` |
| **22:09 ~ 23:44** | **엔진 미기동 · 스택 전체 다운 (96분)** | Docker Desktop `AutoStart=False` |
| 23:44:40 | Docker Desktop 수동 기동 | 프로세스 `StartTime` |
| 23:44:57 | 컨테이너 13개 일제히 기동 | `docker events` |

### 부하가 원인이라는 짐작은 성립하지 않는다

사용자 짐작은 「그 시간대에 사용자가 많아져 부하로 꺼졌다」였다. 실측이 전부 반대다.

1. **크래시 시점 요청량이 오히려 낮았다** — 피크는 22:00 의 253줄/분이었고 크래시
   직전 22:07 은 50줄이었다(그중 21줄이 아래 2번의 폴러 에러다).
2. **시간당 13,521건 = 초당 3.75건.** 24코어 16GB 기계에 무의미한 수준이다.
3. **compose 상한 합계가 CPU 10/24코어 · 메모리 7.2/16GB** 다. 스택 전체가
   최대치로 돌아도 기계의 절반을 못 쓴다.
4. 유일한 실질 CPU 소비자인 `translator`(llama.cpp, **CPU 전용** · `--threads 2` ·
   `cpus: 1.5`)는 **일정한** 속도로 돌았다 — 107줄/분 평행선이 크래시 순간까지 변화 없다.
5. **WHEA 하드웨어 오류 0건 · 열 이벤트 0건 · 리소스 고갈 이벤트 0건.**
6. 과부하로 꺼진 PC 는 버그체크 없이 Event 41 만 남긴다. 이번엔 **버그체크 코드와
   덤프가 남았다** → 드라이버 폴트다. (과거 Event 41 3건 — 07-04 · 05-01 · 04-21 —
   은 버그체크가 없어 오히려 그쪽이 전원·열 계열로 보인다. 이번 건과 다른 종류다.)

### 고친 것

`restart: unless-stopped` 는 옳았고 그대로 둔다. 구멍은 그 **아래층**이었다.

- `deploy/scripts/watchdog.ps1` — 헬스 점검 · 엔진 기동 · 컨테이너 복구 · 알림
- `deploy/scripts/install-watchdog.ps1` — 작업 스케줄러 등록/해제

되살릴 때 `docker compose up -d` 를 쓰지 않는다. `fe`·`nginx` 가 `prod` 프로파일이라
프로파일 없이 `up` 하면 빠지고, `up` 은 compose 와 `.env` 를 다시 평가해 컨테이너를
재생성할 수 있다. **워치독이 배포를 하면 안 된다.** 라벨로 멈춘 것만 찾아 `docker start` 한다.

### 검증에서 드러난 한계

엔진 복구를 실제로 시험했다(Docker Desktop 강제 종료 → 워치독 실행).
**감지·기동·판정·알림은 전부 설계대로 동작했고 복구만 실패했다** — Docker Desktop 이
모달 오류 대화상자(`Quit` / `Reset to factory defaults`)를 띄우고 사람을 기다렸다.
원인은 강제 종료가 남긴 고아 AF_UNIX 소켓이었다.

워치독은 이제 이 경우를 알아보고 스스로 치운다(`backend.error.json` 에서 경로를 읽어
디렉터리 이름 변경 후 1회 재기동). 다만 **Docker Desktop 이 사용자 세션에 붙는 GUI 앱**
이라는 사실은 워치독으로 못 메운다 — 자동 로그인이 아니면 부팅 후 로그인 전까지
스택이 없다. 무인 운영이 목표면 WSL2 안의 `dockerd`(systemd) 또는 OCI VM 으로 가야 한다.

## 2. 해외 종목 하나가 국내 시세 39종목을 떨어뜨렸다

크래시와 무관한 별건이다. 크래시 20초 전 로그에서 나왔다.

사용자가 `/stocks/search` 로 **QXO(미국 종목)** 를 열어 폴러 대상에 들어간 순간부터
`market price poller: batch 0-39 failed ... toss api 400 invalid-request` 가 초당 2회씩
찍혔다. 직전 틱은 `terminalSyms=[073570]` 로 정상이었다.

`toss.GetPrices` 는 심볼 목록을 검증 없이 콤마로 이어 상류에 넘긴다. 상류가 목록
**전체**를 400 으로 거절하면 `refreshPricesNow` 의 `continue` 가 그 청크를 통째로
건너뛴다. 청크 크기가 200 인데 실제 배치가 40 이라 청크가 하나뿐 — **불량 1개 때문에
나머지 39개가 그 틱에서 전부 빠졌다.** 400 은 재시도로 낫지 않으므로 같은 요청이
영원히 나갔고 Toss `MARKET_DATA` 버킷을 태웠다.

### 고친 것

`fetchPricesIsolatingBad` 가 400 을 만나면 묶음을 반씩 갈라 원인 심볼을 찾아
격리하고 **나머지는 살려서** 돌려준다. 격리된 심볼은 다음 틱부터 `dropQuarantinedSymbols`
가 앞에서 걸러 호출에 실리지 않는다.

비용은 불량 k개에 대해 대략 O(k log n) 호출이고 **한 번만** 치른다. 지금의
「영원히 초당 2회 실패」보다 싸다. 격리는 6시간 뒤 만료된다 — 상장·거래재개처럼
나중에 유효해지는 심볼이 있어 영구 제외는 틀린다.

## 사이드 이펙트 · 호환

| 항목 | 영향 |
| ---- | ---- |
| 기존 시세 경로 | 없음 — 400 이 아닌 오류(429·5xx)의 처리는 그대로다 |
| 상류 호출 수 | **줄어든다** — 무한 재시도가 1회 탐색 + 격리로 바뀐다 |
| 격리 상태 | 프로세스 메모리. 재기동하면 초기화되고 필요하면 다시 탐색한다 |
| DB · 마이그레이션 | 없음 |
| FE | 없음 |
| 워치독 | 로컬 Windows 전용. OCI VM 은 `systemctl enable docker` 로 대신한다 |

## 운영

```powershell
# BE 재기동
cd be; .\scripts\restart.ps1 -Background

# 워치독 등록 (1회)
powershell -ExecutionPolicy Bypass -File deploy\scripts\install-watchdog.ps1
```

**작업 중 스택을 내려 둘 때는 `deploy/watchdog.paused` 를 만든다.** 없으면 워치독이
5분 뒤에 도로 올려 놓는다.

## v1.13.0 로 복원하기

```bash
git restore --source=v1.13.0 -- be/internal/service/market_data_store.go be/internal/toss/errors.go
rm be/internal/service/market_poller_badsymbol_test.go
git restore --source=v1.13.0 -- be/internal/service/market_poller_sim_test.go
powershell -ExecutionPolicy Bypass -File deploy\scripts\install-watchdog.ps1 -Remove
```

되돌리면 잃는 것: 부팅 후 자동 복구와 다운 알림이 사라지고, 상류가 거절하는 심볼
하나가 다시 같은 묶음의 나머지 시세를 매 틱 떨어뜨린다.
