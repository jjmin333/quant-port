## 1. 놓친 배치 재처리

### 왜 필요한가

감시 체계(v1.13.1 이전에 도입)는 `late`를 **판정까지** 한다. 그런데 판정은 사람이
화면을 열어야 닿는다. 09-08에 22:07에 죽고 23:44까지 누워 있었는데 그 사이 지나간
슬롯을 아침까지 아무도 안 채웠다. **새벽에 죽으면 매번 그렇게 된다.**

### 「늦었으면 다시 돌린다」는 틀렸다

잡마다 늦게 도는 것의 뜻이 다르다. 그래서 **허용 목록**이고, 표에 없는 잡은 자동
재처리하지 않는다 — 새 잡이 조용히 재처리 **대상이 되는 것**보다 조용히 **빠지는 쪽**이
안전하다.

**빼는 것과 이유가 이 설계의 핵심이다.**

| 잡 | 왜 자동으로 돌리지 않는가 |
| --- | --- |
| `llm_summary_*` | **돈이 든다.** 창 밖에서 돌면 다음 날 예산을 먹는다. 「LLM 호출은 배치·관리자 수동만」 규칙에 따라 사람이 정한다 |
| `news_briefing_*` | **슬롯이 지나면 의미가 없다.** 다음 슬롯이 덮는데 LLM만 태운다 |
| `daily_close_*` | **자기 catch-up이 이미 있다**(`catchUpMissedSessions`) — 두 번 한다 |
| `candle_rollup` | 다음 날 어차피 돈다. 놓친 만큼 봉이 더 남을 뿐 해롭지 않다 |

넣는 것: `stock_scores` · `data_retention` · `research_verdict`(멱등·DB만),
`warnings_sync` · `disclosures_daily`(멱등·그날 것을 다시 받으면 됨),
`insider_*` · `financials_*`(로테이션), `earnings_*`(기동 catch-up은 프로세스가 떠야 돈다).

### 안전장치 넷

- **`failed`·`stuck`은 재처리하지 않는다** — 「안 돌았다」가 아니라 「깨졌다」·「붙잡혔다」다.
  원인을 모른 채 다시 넣으면 같은 실패를 반복하거나 붙잡힌 실행과 겹친다.
- **회차당 2개까지** — 열두 시간 죽어 있다 살아나면 여러 잡이 한꺼번에 `late`가 된다.
  전부 밀어 넣으면 외부 API 한도에 걸려 채우려던 것마저 실패한다. 15분 뒤 다음 회차가 잇는다.
- **`HasPending` 확인** — 두 시간짜리 잡이 아직 돌고 있을 수 있다.
- **`trigger_kind`를 `manual`과 가른다** — 「내가 누른 적 없는 수동 실행」이 보이면
  사람이 원인을 잘못 짚는다.

## 2. 워치독의 사각 셋

### ㉠ 5분마다 창이 떠서 작업이 끊겼다 (사용자 지적)

`-WindowStyle Hidden`은 소용없다. powershell은 **콘솔을 먼저 만들고 나서** 숨기고,
Windows 11은 그 콘솔을 **Windows Terminal**로 띄운다. 창 열거 대조 실험:

| 실행 방식 | 새로 뜨는 보이는 창 |
| --------- | ------------------- |
| `powershell.exe -WindowStyle Hidden` | **`WindowsTerminal`** |
| `wscript.exe watchdog-hidden.vbs` | **없음** |

### ㉡ 워커가 죽어도 `/health`는 200이다

`/health`는 nginx→api 한 줄만 지난다. 워커 8개나 redis가 멈춰 있어도 그 줄은 멀쩡해서
200이 나오고, **워치독은 「정상」이라고 적는다.** 09-08 다운 뒤에도 그랬을 수 있다.
이제 헬스가 정상이어도 컨테이너 census를 본다.

### ㉢ `/health`는 liveness뿐이라 DB 장애를 못 본다

MySQL이 죽어도 200이다. `/ready`가 MySQL·Redis를 실제로 찌른다. 다만 **`/ready` 실패를
복구 신호로 쓰면 안 된다** — OCI MySQL 장애를 Docker Desktop 재기동으로 고칠 수 없고,
시도하면 고칠 수 없는 조건에서 재기동을 반복한다. 그래서 역할을 나눴다:

	/health 실패 → 스택이 없다               → 고친다
	/ready  실패 → 의존성이 아프다            → 알리기만 한다

Redis만 죽으면 `/ready`는 **200에 `"degraded"`**를 담아 보낸다(핸들러는 MySQL일 때만 503).
상태 코드만 보면 놓치므로 본문의 `status`까지 본다.
