## 3. ① 뉴스 탭과 같은 페이지네이션

요구가 두 가지였다: **「뉴스 탭처럼」**, 그리고 **「30일이 아니라 30행」**.

- **30행**은 이미 그랬다(`PAGE_SIZE = 30`, 행을 자른다). 거래일 30개면 주말을 빼고 약 6주다.
- **모양**을 바꿨다. 헤더 우측의 `◀ 1/2 ▶`를 없애고, 목록 아래에 뉴스 탭과 똑같은 번호 버튼을 놓았다.

**두 벌로 두지 않았다.** 뉴스 탭에 있던 `pageWindow` + 페이저 마크업을 `components/ui/page-nav.tsx`로 꺼내 두 화면이 같은 컴포넌트를 쓴다 — 같은 모양이어야 한다는 요구를 코드로 보장하지 않으면 반드시 갈라진다.

적재량도 60 → **120행**으로 올렸다(서버 상한 `dailyCloseMaxLimit = 120`). 60행이면 페이지가 둘뿐이라 번호 페이지네이션의 뜻이 약했다. 실측 005930: 120행 → **4페이지**, 페이지 이동 시 **추가 요청 0건**.

## 4. ② 삼성전자 — DART는 줬고, 우리가 놓쳤다

빈 칸은 **2023년 4분기 매출 한 칸**이었다. 그런데 화면에서는 네 곳이 비었다:

| 화면 | 왜 |
|---|---|
| 매출·순이익 | 그 분기 매출 막대 없음 |
| 이익률 | 매출이 없으면 마진을 못 만든다 → 2023Q4 비고, 이웃이 비어 2023Q3가 외딴 점이 된다 |
| 성장률 (매출) | 2023Q4 자신 + **다음 분기(2024Q1)의 직전 비교값**까지 두 칸 |

**한 칸이 네 곳으로 번진다** — 결측을 셀 때 「칸 수」와 「보이는 구멍」이 다른 이유다.

### 4.1 원인 — 같은 해, 두 보고서, 다른 이름

4분기는 `연간 − 3분기 누적`으로 만든다. DART 원본을 직접 확인했다:

| 보고서 | 매출 계정명 | 값 | 옛 사전 |
|---|---|---|---|
| 2023 **연간** (11011) | **`영업수익`** | 258.9조 | ✗ 매칭 실패 |
| 2023 **3분기** (11014) | **`수익(매출액)`** | 191.2조 (누적) | ✓ |

연간이 `nil`이라 `nil − 191.2조`가 되어 4분기 매출이 통째로 사라졌다. **SK하이닉스와 정확히 같은 원인**(계정명 사전)이고, 다만 그쪽은 분기 보고서끼리, 삼성전자는 연간과 분기 사이에서 어긋났다.

### 4.2 결과

v1.4.0의 새 파서로 재적재:

```
go run ./cmd/backfill-empty-financials -market=domestic -holes-only -symbols=005930
```

| | 이전 | 이후 |
|---|---|---|
| 남은 구멍 | 1칸 | **0칸** |
| 2023Q4 매출 | — | **67.8조** (= 258.9 − 191.2, 계산과 일치) |
| 2023Q4 영업이익률 | — | **4.2%** |
| 2023Q4·2024Q1 매출성장률 | — | **+0.6% / +6.1%** |

이어서 국내 **구멍 있는 전 종목**에 같은 재적재를 돌렸다(`-holes-only`). 대상이 **1,151 → 602종목**까지 줄어들었다 — 그리고 거기서 멈췄다. 왜 멈췄는지는 §4.4가 답이다.

> **운영 기록:** 첫 배치가 아직 살아 있는 줄 모르고 두 번째를 띄워 한동안 두 프로세스가 동시에 돌았다. 로그상 실패 0건이라 무해해 보였지만 **그 판단 자체가 틀렸다** — 그때 이미 DART 한도를 태우고 있었고, 계기가 고장 나 있어서(§4.4ⓑ) 알 방법이 없었다. 배치를 다시 띄우기 전에 살아 있는지 먼저 확인해야 한다.

### 4.3 남은 결측을 다시 파 보니 — 계정명 패턴 두 개가 더 나왔다

재적재 뒤에도 「구멍 그대로」인 종목이 있어 무엇이 남았는지 봤다. 대부분 **EPS**였다.

| 종목 | 실제 계정명 | 판정 |
|---|---|---|
| 제일파마홀딩스(002620) | `지배기업 소유주지분 기본주당손익` | **고칠 수 있다** — IFRS 주당이익은 원래 지배기업 소유주 귀속 기준이라 접두사만 붙었을 뿐 개념이 같다 |
| 대상(001680) | `우선주기본주당순이익(손실)`, `제1우선주 기본주당순이익` | **채우면 안 된다** — 연결재무제표에 보통주 EPS가 없다. 우선주 EPS를 그 자리에 넣으면 다른 주식 종류의 값을 이 종목의 EPS라고 말하게 된다 |

앞엣것만 고쳤다: 모든 계층이 빈 뒤에 **한 번만** 귀속 접두사(`지배기업소유주지분` 등)를 떼고 1순위를 다시 본다(`AllowOwnerPrefix`, EPS 전용). 접두사 없는 이름이 있으면 언제나 그쪽이 이긴다. 순이익에는 켜지 않았다 — 거기서는 총액과 귀속분이 실제로 다른 값이고 이미 2순위로 다룬다.

**그 과정에서 정규화 버그를 하나 잡았다.** 기간 표지를 `strings.ReplaceAll(out, "분기", "")`로 지우고 있었는데, 낱말 경계를 넘어 자른다 — `지배기업소유주지분기본주당손익`의 「지**분기**본」이 걸려 `지배기업소유주지본주당손익`이 됐다. 표지는 언제나 `순이익`·`순손익` 바로 앞에 붙으므로 **`당기순`·`분기순`·`반기순` → `순`**으로 그 자리에서만 떼도록 고쳤다. 테스트가 잡아냈다.

> ⚠️ 실행 중이던 배치는 **이 수정 이전 바이너리**로 돌고 있다. 귀속 접두사 종목은 이번 배치에서 안 채워지고 코호트에 남으므로, 배치가 끝난 뒤 `-holes-only`를 **한 번 더** 돌려야 한다.

### 4.4 그런데 배치는 사실 아무 일도 하고 있지 않았다 — 원인 셋

배치가 끝났을 때 결과가 이상했다: **`attempted=705 ok=705 failed=0`인데 코호트가 한 종목도 안 줄었다.** 파고들어 보니 원인이 세 겹이었고, 전부 **실패가 성공처럼 보이는** 종류였다.

**ⓐ DART는 거절도 HTTP 200으로 준다.** 한도가 소진되면 `corpCode.xml`이 ZIP 대신 149바이트짜리 `<result><status>020</status>…</result>`를 **200으로** 돌려준다. 전송 계층은 성공이므로 `err == nil`이고, 그 XML을 corp_code 목록으로 파싱하면 오류 없이 **빈 맵**이 된다. 그 맵은 24시간 캐시로 굳고, 그 뒤 **모든 종목이 「corp_code not found」**로 떨어진다 — 원인에서 한참 떨어진 곳에서 터지는 데다, 종목 하나하나의 문제처럼 보인다.

**ⓑ 예산 계기가 0을 가리키고 있었다.** `fetchURLHTTP`만 `Check`/`Record`를 했고 **curl 폴백은 아무것도 안 했다.** 그런데 Windows에서는 Go의 TLS 협상이 DART와 실패해서(`isDartTLSFailure`) **모든 호출이 curl 경로로 간다.** 결과: 2만 회 넘게 부르고 DART가 020을 돌려주는 동안 우리 계기판은 `used_day=0 / headroom=18000`이었다. `backfillMaxSymbols` 가드가 아무것도 못 막은 것은 당연하다 — 계기가 0인데 막을 방법이 없다.

**ⓒ 종목당 호출 수를 4로 잡고 있었다.** 실제로는 `FetchQuarterlyHistory`가 **(years+1)년 × 보고서 4종 = 16회**, `FetchQuarterlySnapshots`가 4~8회로 **20회가 넘는다**(연결이 없어 별도로 재시도하면 각 호출이 두 번). 1,151종목 × 20 ≈ 23,000회로 일일 한도 20,000을 처음부터 넘는 계획이었다.

여기에 **동시 실행**까지 겹쳤다(§4.2 운영 기록). 셋이 합쳐져 한도를 태웠고, 그 뒤로는 아무것도 안 하면서 전부 ok로 보고했다.

#### 고친 것

| 문제 | 고침 |
|---|---|
| 거절이 200으로 온다 | `dartErrorPayload` — **JSON·XML 두 꼴 모두** 인식. 020은 `ErrDartQuotaExceeded`로 |
| 빈 corp_code 맵이 캐시로 굳는다 | 빈 목록이면 설치하지 않고 오류를 낸다 |
| curl 폴백이 예산에 안 잡힌다 | `Check`/`Record`를 `fetchURL` **한 곳으로** 올렸다 — 어느 전송을 타든 잡힌다 |
| 간격을 못 지키면 조용히 건너뛴다 | `waitForBudget` — `ErrPacing`이면 **기다렸다 다시 본다**(`MinInterval` 주석이 말하는 그 용법). 소진은 그대로 올린다 |
| 한도 소진이 종목 실패로 묻힌다 | 위로 전파해 **배치를 세운다** |
| 종목당 4회 가정 | 24회(분기)·48회(전체)로 정정 — 가드가 실제로 캡을 건다 |

**실측 (수정 후, 한도 소진 상태):**

```
done attempted=1 ok=0 failed=1 stopped="DART 일일 한도 소진 — 남은 종목은 다음 날 이어서 돌린다"
  detail: 001940: dart: 일일 사용한도 초과
quota dart: headroom_calls=17978 used_day=22   ← 계기가 드디어 움직인다
```

수정 전이라면 705종목을 계속 돌며 1만 5천 회를 더 태우고 `ok=705`로 끝냈을 자리다.

## 5. ③ 밸류에이션 탭 — 「배수」 화면 삭제

두 서브탭이 실제로 무엇을 보여주는지 세어 봤다:

| 지표 | 배수 | 지표 |
|---|---|---|
| PER · PBR · FWD PER · CY PER | ✓ | ✓ |
| **PSR** | ✓ | ✗ |
| ROE · 영업마진 · 매출성장률 · EPS성장률 · 부채비율 | ✗ | ✓ |

**5개 중 4개가 그대로 중복**이고, 배수에만 있는 진짜 데이터는 **PSR 하나**였다.

배수 화면에만 있던 나머지는 전부 지어낸 값이었다:

| 요소 | 실제 정체 |
|---|---|
| 스파크라인 | `buildTrendSeries(value, \`${symbol}-${label}\`)` — 심볼 문자열 해시를 시드로 한 의사난수 12점 |
| 「과거 5년 대비 Low/Mid/High」 | 그 의사난수의 중앙값과 비교한 **판정** |
| 「산업 대비」 | 업종 중앙값 = `med5y * 1.05` |
| 「NTM 추정」 | `value * 0.92` |
| 5Y 중앙 / 5Y 범위 | 의사난수의 통계량 |

재무제표 탭의 가짜 추세선보다 나빴다 — **장식이 아니라 판정**을 지어낸 숫자에서 뽑고 있었고, `parseValuationSubTab`의 기본값이 `"multiples"`라 **탭을 열면 이 화면이 먼저 보였다.**

그래서: 배수 화면과 서브탭을 없애고, PSR을 지표 판넬로 옮기고, 지어내던 `analysis-chart-utils.ts`를 **파일째 삭제**했다(다른 참조 0건 확인). 실제 PER·PBR 분기 추이가 필요하면 재무제표 탭의 「PER · PBR (분기말 종가 기준)」에 있다 — v1.4.0에서 일봉 × 분기 재무로 실제 계산한 값이다.

### 5.1 PSR은 어떻게 만드나

시가총액을 저장하지 않으므로 `주가 × 발행주식수 ÷ 매출`로 만든다. 화면이 부르기 전에 `applyLiveValuationMultiples`가 주가를 실시간 값으로 갈아 두므로 PSR도 함께 산다. 셋 중 하나라도 없거나 매출이 0 이하면 **지표를 만들지 않는다** — 0으로 그리면 「PSR 0배」라는 없는 사실이 된다.

실측 005930: 248,500원 × 5,846,278,608주 ÷ 333.6조 = **4.4x** ✓

### 5.2 지표마다 한 줄 풀이

「PER」만 적힌 카드는 입문자에게 아무 말도 하지 않는다. 값 바로 아래에 세 가지를 한 문장으로 적는다 — ⓐ 무엇을 무엇으로 나눈 값인지, ⓑ 높으면/낮으면 무슨 뜻인지, ⓒ 어느 쪽이 유리한지.

> **PER** 37.6x
> 주가를 주당순이익으로 나눈 값으로, 낮을수록 기업이 내는 이익에 비해 주가가 저평가되어 있다는 의미입니다.

> **PSR** 4.4x
> 시가총액을 매출액으로 나눈 값으로, 낮을수록 기업의 매출에 비해 주가가 저평가되어 있다는 의미입니다. 아직 이익을 내지 못하는 회사를 견줄 때 씁니다.

「저평가」·「고평가」를 **단정하지 않는다** — 배수 하나로 결론이 나지 않고, 이 앱은 투자 자문이 아니다. 「~라는 의미입니다」까지만 적는다. 8개 지표(PER·PBR·ROE·영업마진·매출성장률·EPS성장률·PSR·부채비율) 전부에 붙였다.
