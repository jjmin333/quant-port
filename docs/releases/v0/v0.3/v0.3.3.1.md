> **버전:** v0.3.3.1  
> **기준일:** 2026-07-31 (KST)  
> **Git 태그:** `v0.3.3.1` (커밋·태그 생성 후)  
> **이전 버전:** [v0.3.3](./v0.3.3.md)  
> **목적:** 차트 **과거 pagination** 커서 버그 수정 — DB-first lazy upsert 정상화

---

## 1. 한 줄 요약

차트 스크롤(load-more) 시 `nextBefore`가 **date-only**(`2024-01-26`)로 내려가 Toss API가 거부되어 **404**가 나던 문제를 수정했습니다. 모든 pagination 커서를 **RFC3339 KST**로 정규화해, DB → Toss backfill → MySQL upsert 체인이 2024-01 이전까지 이어집니다.

---

## 2. v0.3.3 → v0.3.3.1 변경 요약

| 영역 | v0.3.3 | v0.3.3.1 |
|------|--------|----------|
| 차트 과거 스크롤 | ~2024-01에서 404로 중단 | **RFC3339 커서로 연속 pagination** |
| `nextBefore` 형식 | date-only / RFC3339 혼재 | **항상 RFC3339 KST** |
| Toss `before` | date-only 시 API 실패 | **호출 전 정규화** |
| DB lazy upsert | 설계대로이나 backfill 미도달 | **backfill + UpsertBatch 정상** |
| FE package | `0.3.3` | `0.3.3.1` |

---

## 3. 원인

| 단계 | 문제 |
|------|------|
| DB/집계 경로 | `nextBefore` = `2024-01-26` (date-only) |
| FE round-trip | 동일 문자열을 `before`로 재전송 |
| DB miss | Toss backfill 시도 |
| Toss API | `before`는 **ISO 8601 date-time** 필수 → **오류 → BE 404** |
| FE | `catch {}` → load-more 조용히 실패 |

---

## 4. 수정 내용 (BE)

### Canonical pagination cursor

- `model.CanonicalPaginationCursor` — 일봉/주봉/월봉 bucket → midnight KST RFC3339; 분봉은 분 해상도 유지
- **Inbound:** `GetCandlesPage` 진입 시 `before` 정규화
- **Outbound:** 모든 `NextBefore` 응답 정규화
- **Toss:** `fetchTossCandlesWithRetry`에서 `before` / `nextBefore` 정규화

### Read chain (변경 없음, 정상 동작 복구)

```
스크롤 load-more (before=cursor)
  → MySQL candle_bars (1m/1d)
  → miss → Toss 1× fetch → UpsertBatch
  → nextBefore (RFC3339) → 다음 페이지
```

### 주요 파일

| 파일 | 역할 |
|------|------|
| `be/internal/model/candle_time.go` | `CanonicalPaginationCursor` |
| `be/internal/service/candles_cursor.go` | Inbound/outbound/Toss helpers |
| `be/internal/service/candles_page.go` | `GetCandlesPage` 정규화 |
| `be/internal/service/candles_db.go` | `oldestBarCursor`, snapshot cursor |
| `be/internal/service/quotes_toss_retry.go` | Toss 호출 전후 정규화 |

## 5. 사이드 이펙트·호환

| 항목 | 영향 |
|------|------|
| FE | 변경 없음. 기존 RFC3339·date-only `before` 모두 수용 |
| DB `ListBefore` | `BeforeCursorTime`이 두 형식 동일 파싱 → SQL 비교 동일 |
| `candles[].time` | 변경 없음 (커서만 정규화) |
| 분봉 커서 | 이미 RFC3339 → idempotent |
| Toss 호출량 | **감소** (한 번 backfill 후 DB hit) |

**FE 404 재시도는 의도적으로 미포함** — BE에서 근본 해결.

## 6. 검증

```powershell
cd be
.\scripts\restart.ps1 -Background

# date-only cursor (이전 404 재현 케이스)
curl.exe -s "http://localhost:8080/api/v1/quotes/000660/candles?interval=1M&before=2024-01-26"
# → 200 + 2023년 월봉 + nextBefore RFC3339

curl.exe -s "http://localhost:8080/api/v1/quotes/000660/candles?interval=1M&before=2023-03-30"
# → 200 + 2022년 데이터
```

```powershell
cd be
go test ./internal/model/... ./internal/service/... -run "Candle|Cursor|Pagination" -count=1

```

- [x] `nextBefore` 항상 `…T00:00:00+09:00` 또는 분봉 RFC3339
- [x] 재요청 시 DB hit (`source: db`) 가능
- [x] go test / go build
