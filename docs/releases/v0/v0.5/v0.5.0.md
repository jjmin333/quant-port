# Quant Port v0.5.0 — Project Snapshot (실적 탭 구현)

> **버전:** v0.5.0
> **기준일:** 2026-08-07 (KST)
> **Git 태그:** `v0.5.0` (커밋·태그 생성 후)
> **이전 버전:** [v0.4.0](../v0.4/v0.4.0.md)
> **목적:** **신규 기능** — 종목 워크스페이스의 `실적` 탭(그동안 "준비 중" 플레이스홀더)을 무료 데이터 소스(DART/EDGAR/Finnhub)만으로 실제 데이터를 채워 구현
> **범위:** 백엔드(신규 엔드포인트 1개, DART/EDGAR 분기 데이터 추출) + 프론트엔드(신규 탭 컴포넌트, 워크스페이스/종목분석 양쪽 배선)

---

## 1. 한 줄 요약

`실적` 탭에 매출·순이익·EPS·YoY 요약, 최근 실적 공시/발표 일정, 분기별 실적 상세를 실제 데이터로 채웠습니다. 구현 과정에서 DART API가 Docker(Linux) 컨테이너 안에서 조용히 전부 실패하고 있던 기존 TLS 폴백 버그와, EDGAR 분기 데이터가 누적(YTD) 수치와 단일 분기 수치를 구분하지 못해 비현실적으로 커지던 데이터 정확성 버그를 함께 발견해 수정했습니다.

## 3. Phase별 구현 내용

### Phase 1 — 백엔드: 신규 엔드포인트 `GET /api/v1/stocks/{symbol}/earnings`

종목의 국내/미국 여부(`ResolveFundamentalsAssetType`, 기존 `FundamentalsService`의 판별 로직을 패키지 함수로 추출해 재사용)에 따라 분기 처리:

- **국내(DART)**: 최근 1년 공시 중 `잠정실적`/`영업(잠정)실적`/`사업보고서`/`분기보고서`/`반기보고서` 키워드가 포함된 것만 필터링해 "최근 실적 공시"로 제공. DART에는 미래 발표 일정 API가 없어 **이미 제출된 공시 이력**으로 대체 표시(UI 라벨도 정직하게 "실적 발표 일정"이 아닌 "최근 실적 공시"로 구분). 분기별 상세는 `reprt_code` 4종(11013=1Q, 11012=반기, 11014=3Q, 11011=연간)을 현재 연도 기준으로 조회, 미제출 시 전년도로 폴백.
- **미국(Finnhub + EDGAR)**: 발표 일정은 기존 `MarketDataStore.EnsureEarningsForSymbols`(브리핑에 쓰던 캐시)를 재사용해 종목별로 필터링. 분기별 상세는 EDGAR `companyfacts`에서 실제 신고된 기간(10-Q/10-K)을 최근 5개까지 추출.
- **서프라이즈·컨센서스**: 항상 `available:false` + 사유 메시지 — 무료 API 어디에도 없는 데이터를 만들어내지 않음.
- Redis 캐시(24h TTL)로 DART/EDGAR 재조회 최소화. DB 스키마 변경 없음 — `stock_fundamentals`는 symbol당 1행 구조라 분기 이력은 저장하지 않고 매 요청 시 라이브 조회(캐시 우선).

### Phase 2 — 버그 수정: DART TLS 폴백이 Docker에서 무효했던 문제

구현 중 국내 종목 실적이 항상 빈 배열로 응답되는 것을 발견. 원인 추적 결과, `fetchURLViaCurl`(Go의 `crypto/tls`가 opendart.fss.or.kr과 핸드셰이크에 실패할 때 curl로 우회하는 기존 폴백)이 `curl.exe`를 하드코딩하고 `runtime.GOOS == "windows"`로 게이트되어 있어, **Docker(Linux) 컨테이너에서는 항상 스킵**되고 있었습니다. 이 프로젝트는 `go run` 대신 Docker 전용 배포이므로(AGENTS.md), 사실상 컨테이너 안에서 DART 실시간 호출(신규 코드 포함)이 전부 조용히 실패하는 상태였습니다. 기존 `stock_fundamentals` 데이터가 며칠 전 값으로 정상 응답하던 것은 DB에 저장된 과거 성공분을 읽고 있었을 뿐, 실시간 DART 파이프라인 자체는 막혀 있었던 것으로 보입니다.

- `dart_http.go`: OS 게이트 제거, `curl`/`curl.exe` 바이너리명을 런타임에 선택하도록 수정.

### Phase 3 — 버그 수정: EDGAR 분기 데이터가 누적(YTD) 수치를 섞어 반환하던 문제

수정 후 확인한 애플 분기 데이터가 Q2 매출 \$254.9B, Q3 매출 \$364.4B처럼 비현실적으로 컸습니다. SEC XBRL은 같은 분기에 대해 **단일 분기(3개월) 수치와 연초 누적(YTD, 6/9개월) 수치를 같은 회계기간 태그로 함께 신고**하는데, 기존 선택 로직이 기간 길이를 구분하지 않고 먼저 매칭되는 값을 집었던 것이 원인. `xbrl_select.go`에 표준 분기 길이(60~100일) 검증을 추가해 단일 분기 값만 선택하도록 수정 — 수정 후 애플 분기 매출이 \$109~144B 범위로(실제 수치와 일치) 정상화됨.

## 5. 사이드 이펙트·호환

| 항목 | 영향 |
|------|------|
| DART 호출량 | curl 폴백 수정으로 국내 종목 실적 조회 시 실제 DART 호출이 발생하기 시작(이전엔 실패 상태). `apibudget` MinInterval(1초)이 그대로 적용되어 4개 reprt_code 순차 조회 시 최대 ~4초. Redis 24h 캐시로 반복 조회는 막음 |
| EDGAR 호출량 | 종목당 `companyfacts` 1회 추가 호출(기존 fundamentals 호출과 별개) — 24h 캐시 |
| 기존 `/fundamentals` 엔드포인트 | 변경 없음. 실적 탭 "실적 요약" 섹션은 이 엔드포인트를 그대로 재사용(중복 호출 없음) |
| `stock_fundamentals` 테이블 | 스키마 변경 없음 |
| curl 폴백 수정 | DART를 사용하는 다른 기존 경로(오늘자 공시, 연간 fundamentals 갱신)도 Docker 안에서 함께 정상화됨 — 부작용이 아니라 잠재 버그 수정 |
| DB/UI | 새 테이블·마이그레이션 없음. 관리자 화면 변경 없음 |

## 9. 후속 (이번 릴리스 범위 밖)
