## 1. 한 줄 요약

파일럿 종목 관리를 API 관리 탭에서 분리해 전용 "LLM 모델 관리" 메뉴로 옮기고, 종목 목록·호출 주기를 관리자가 직접 편집(재기동 불필요)할 수 있게 했습니다. 호출량·한도량과 실제 LLM에 전송된 입력(INPUT) 기록도 이 페이지에서 함께 확인할 수 있습니다. 관리자 메뉴 어디를 눌러도 "뉴스 관리" 탭이 활성화된 것처럼 보이던 사이드바 버그도 함께 고쳤고, 메뉴명을 실제 기능에 맞게 정리했습니다("관리자"→"뉴스 관리", "데이터베이스"→"데이터베이스 관리").

## 3. Phase별 구현 내용

### Phase 1 — 사이드바 활성 탭 버그 수정

`sidebar.tsx`의 활성 탭 판정 로직에 `item.href === "/admin"`일 때 `pathname.startsWith("/admin/")`이면 무조건 활성으로 표시하는 특수 케이스가 있었음 — `/admin`이 다른 모든 관리자 페이지(`/admin/api`, `/admin/llm`, ...)의 접두사이기 때문에, 어느 관리자 페이지에 있든 "뉴스 관리"(구 "관리자") 탭도 함께 활성화되어 보이던 원인. 특수 케이스를 제거하고 다른 모든 메뉴 항목과 동일한 정확 일치/자식 경로 규칙만 사용하도록 단순화(기존에 `/analysis`, `/market`용으로 있던 특수 케이스도 실질적으로 동일한 동작이라 함께 정리).

### Phase 2 — 파일럿 종목을 env에서 DB 설정으로 전환

신규 `llm_settings` 테이블(`market_data_settings`와 동일한 단일 행 패턴) + `LLMSettingsRepo`/`LLMSettingsStore`. Store는 요청마다 DB를 즉시 재조회하므로 관리자가 `/admin/llm`에서 종목을 편집하면 재기동 없이 바로 다음 요청부터 반영됩니다. 기존 `STOCK_SUMMARY_LLM_SYMBOLS` env 플러밍은 완전히 제거(단일 소스 유지).

### Phase 3 — 호출 주기를 관리자가 직접 편집

`llm_settings`에 `refresh_interval_hours` 컬럼 추가(1~24시간 범위로 클램프). 기존에는 `time.Ticker`로 6시간 고정이었는데, 관리자가 런타임에 값을 바꿀 수 있어야 하므로 `time.Ticker`를 버리고 매 주기마다 최신 설정값을 다시 읽는 sleep 루프로 전환(`RunScheduler`).

### Phase 4 — LLM 모델 관리 페이지 상세화

`/admin/llm`에 다음을 통합 표시:
- **LLM Provider 상태**: 활성 여부 + provider(gemini/openai)
- **API 한도**: 분당/일간/월간 호출량 그래프(기존 `/admin/api`의 그리드와 같은 시각화, 이 페이지에서 바로 확인 가능 — `/admin/api`로 이동할 필요 없음)
- **파일럿 종목 · 호출 주기 편집 폼**: 쉼표 구분 심볼 입력 + 시간 단위 주기 입력, 저장 시 즉시 반영
- **파일럿 종목 캐시 상태**: 종목별 AI 생성/규칙 기반, 생성 시각
- **요청 INPUT 기록**(신규): 최근 30건까지 LLM에 실제 전송된 facts JSON을 펼쳐서 확인 가능, 성공/실패 뱃지 포함

`/admin/api`에서는 "AI 요약 파일럿" 섹션을 제거하고 원래 목적(provider별 호출량/한도 카드 그리드)만 유지 — 사용자가 애초에 원했던 "타 API처럼 호출량·한도만 확인" 요구사항 그대로.

### Phase 5 — 요청 INPUT 기록 (백엔드)

`GenerateStockSummary` 호출마다 factsJSON·타임스탬프·성공/실패·에러 메시지를 Redis 캡드 리스트(`llm:requests:v1:log`, 최근 30건, 7일 TTL)에 기록. 신규 `GET /admin/llm-requests`(읽기 전용)로 조회.

### Phase 6 — 버그 발견+수정: 스케줄러 파일럿 종목 간 호출 간격

(v0.7.0 배포 직후 실측 중 발견) 스케줄러가 파일럿 종목을 간격 없이 연속으로 갱신해 2번째 종목부터 apibudget `MinInterval`(4초)에 매번 걸려 조용히 규칙 기반으로만 캐시되던 문제 — 005930은 `source:"llm"`, 000660은 `source:"rule"`로 실측 확인 후 발견. 종목 사이에 6초 간격을 추가해 수정, 재검증 후 두 종목 모두 `source:"llm"` 확인.

### Phase 7 — 메뉴 명칭 정리

사이드바: "관리자" → "뉴스 관리"(실제로 뉴스 키워드·통계·폴링 설정 페이지), "데이터베이스" → "데이터베이스 관리". 해당 페이지의 `PageHeader` 타이틀도 함께 변경.

| 항목 | 영향 |
|------|------|
| `STOCK_SUMMARY_LLM_SYMBOLS` env | 완전히 제거됨 — 설정해뒀더라도 더 이상 읽지 않음. 기본 파일럿 종목(005930, 000660)은 `027_llm_settings.sql` 마이그레이션의 초기 INSERT 값으로 대체 |
