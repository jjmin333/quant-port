# Quant Port v0.7.0 — Project Snapshot (뉴스 탭 + AI 3줄 요약)

> **버전:** v0.7.0
> **기준일:** 2026-08-07 (KST)
> **Git 태그:** `v0.7.0` (커밋 후)
> **이전 버전:** [v0.6.0](../v0.6/v0.6.0.md)
> **목적:** **신규 기능** — 종목 워크스페이스에 `뉴스` 탭 신설 + 재무제표/실적/전망/내부자거래/차트/뉴스 탭 상단에 AI 3줄 요약(밸류에이션·기술적분석·내부자·뉴스감성) 추가. Gemini 3.1 Flash-Lite(무료 티어)를 OpenAI 호환 엔드포인트로 연동, SK하이닉스·삼성전자 2종목 파일럿으로 제한 운영
> **범위:** 백엔드(신규 엔드포인트 2개, 기술적 지표 계산 신규 구현, LLM 통합, 관리자 모니터링) + 프론트엔드(신규 탭 1개, AI 요약 배너 컴포넌트, 관리자 페이지 확장) + v0.6.0 이후 누적된 패치 1건(재무제표 "1년" 트레일링 윈도우 버그 수정)

## 1. 한 줄 요약

`뉴스` 탭에서 종목 관련 최신 뉴스 5건을 바로 확인할 수 있고, 재무제표·실적·전망·내부자거래·차트·뉴스 탭 상단에서 AI가 생성한 3줄 요약(밸류에이션, 기술적 분석, 내부자 동향, 뉴스 감성)을 볼 수 있습니다. 기술적 지표(RSI·MACD·ADX 등)는 실제 캔들 데이터로 계산하고, LLM 호출은 종목당 1회로 묶어 Gemini 무료 티어 한도 안에서 SK하이닉스·삼성전자 2종목에 먼저 적용했습니다.

## 3. Phase별 구현 내용

### Phase 1 — 뉴스 탭

백엔드 변경 없이 기존 파이프라인 재사용: `fetchStockNews`(이미 심볼 필터 지원)와 그동안 미사용 상태였던 `StockNewsPanel` 컴포넌트를 워크스페이스/`/analysis` 양쪽 "뉴스" 탭에 연결. `stock-workspace-tabs.ts`/`analysis-tabs.ts`에 `news` 탭 id 추가.

### Phase 2 — 기술적 지표 계산 (신규)

`be/internal/service/technical_indicators.go`: `candle_bars` 최근 200일봉에서 SMA20/50/200, RSI(14, Wilder 방식), MACD(12,26,9), ADX(14, Wilder 방식), 52주 최고/최저, 최근 스윙 고저를 순수 함수로 계산. 데이터가 부족한 지표는 값을 지어내지 않고 해당 필드만 `nil` 처리. 유닛 테스트 3건(짧은 히스토리/단조 상승/빈 입력).

### Phase 3 — AI 3줄 요약 파이프라인

- **비용 통제 설계**: 탭 4개(밸류에이션·기술적분석·내부자·뉴스)를 **LLM 호출 1회**로 묶어 생성(`llm.GenerateStockSummary`). `InsightsService`(포트폴리오 브리핑)와 동일한 stale-while-revalidate 패턴을 심볼 기준으로 이식(`StockSummaryService`, Redis `stock:summary:v1:<symbol>`, TTL 24h/6h 지나면 백그라운드 재생성).
- **뉴스 감성**: LLM이 숫자를 지어내지 못하도록 기사별 긍정/부정/중립 라벨만 반환받고, 집계(건수·평균 점수)는 서버가 직접 계산 — 항상 실제 기사 수와 일치.
- **LLM 미설정/실패 시 폴백**: 항상 규칙 기반 문장(계산된 실수치만 나열)을 먼저 만들어두고, LLM 성공 시에만 덮어씀 — LLM 장애가 탭을 깨지 않음.
- `llm/client.go` 리팩터: `GenerateBriefing`/`TranslateENToKO`가 중복 구현하던 HTTP 스캐폴딩을 `chatCompletion` 공용 헬퍼로 추출(동작 변경 없음).

### Phase 4 — Gemini 연동 + 2종목 파일럿 제한

- `config.buildLLMConfig()`: `OPENAI_API_KEY` 우선, 없으면 `GEMINI_API_KEY`로 폴백해 Google의 OpenAI 호환 엔드포인트(`https://generativelanguage.googleapis.com/v1beta/openai/`)와 `gemini-3.1-flash-lite`를 기본값으로 사용. `OPENAI_BASE_URL`/`OPENAI_MODEL`로 오버라이드 가능해 provider 전환에 코드 변경이 필요 없음. 실측: 삼성전자·SK하이닉스 모두 실제 Gemini 응답으로 `source:"llm"` 확인(재무 수치·기술 지표·내부자 집계 모두 실데이터 기반, 허구 수치 없음).
- **2종목 파일럿**: `STOCK_SUMMARY_LLM_SYMBOLS` env(기본값 `005930,000660`)로 LLM 호출 대상 심볼을 제한. `StockSummaryService.build()`는 모든 종목에서 실행되어 규칙 기반 요약은 항상 제공하되, LLM 호출 자체는 파일럿 심볼에서만 발생. 백그라운드 스케줄러도 파일럿 심볼만 6시간 주기로 예열(기존 `MarketDataStore.AllTrackedSymbols` 기반 전체 예열에서 축소). 실측: AAPL 등 비파일럿 종목은 `source:"rule"` 고정, apibudget 호출 카운트 증가 없음 확인.
- **apibudget 예산 조정**: Gemini 3.1 Flash-Lite 무료 티어 공개 한도(~15 RPM, ~1,000 RPD)보다 보수적으로 `DailyQuota:800`/`PerMinute:10`/`MinInterval:4s` 설정.

### Phase 5 — 관리자 모니터링

- 신규 `GET /api/v1/admin/stock-summary`(관리자 전용): 활성 LLM provider(openai/gemini)와 파일럿 종목별 캐시 상태(캐시 여부·source·생성 시각)를 읽기 전용으로 반환 — 생성을 트리거하지 않음.
- `/admin/api` 페이지에 "AI 요약 파일럿" 섹션 추가(provider 배지 + 종목별 카드).
- **버그 발견+수정**(이전 세션 v0.6.0 작업의 연장): `apibudget.Manager.AllUsage()`의 provider 하드코딩 목록에 `ProviderOpenAI`가 빠져 있어 `/admin/api`에 LLM 항목 자체가 안 보이던 것을 실측 후 발견·수정(v0.6.0 세션에서 이미 반영, 본 릴리스에 포함).

### Phase 6 (v0.6.0 이후 패치, 본 릴리스에 포함) — 재무제표 "1년" 트레일링 윈도우 버그 수정

`DartClient.FetchQuarterlyHistory`가 연도 단위로 DART를 조회해(`currentYear-offset`), "1년" 선택 시 연초에는 이미 제출된 1~2분기만 반환하던 버그. `years`보다 1년치 여유분을 더 가져온 뒤 최근 `years*4`개 분기만 남기도록 수정해 진짜 트레일링 12개월이 되도록 함. 미국(EDGAR)은 원래 "최근 N개 신고기간" 방식이라 이 버그가 없었음(대조군으로 확인).

## 9. 후속 (이번 릴리스 범위 밖)

- AI 요약 파일럿을 더 많은 종목으로 확장할지는 실사용 관찰(캐시 히트율, Gemini 응답 품질, 무료 티어 한도 내 여유) 후 결정
- 관리자 페이지의 "AI 요약 파일럿" 섹션 실제 로그인 화면 확인 필요(위 검증 항목 참고)
- `response_format: json_object`가 Gemini OpenAI 호환 레이어에서 계속 안정적으로 동작하는지 장기 모니터링 필요(공식 문서에 명시적 보장 없음, 이번엔 정상 동작 확인)
- 뉴스 감성 라벨은 기사 12건까지만 반영(`stockSummaryNewsLimit`) — 더 많은 기사를 반영하려면 토큰 비용과 트레이드오프 재검토 필요
