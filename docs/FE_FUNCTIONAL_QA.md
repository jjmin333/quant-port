### BUG-01 · 모달 안 종목 검색 자동완성을 마우스로 고를 수 없다

- **화면**: `/stamps` 「스탬프 찍기」 모달, `/holdings` 「종목 일괄 추가」 모달
- **재현 방법**:
  1. `/stamps` → 「스탬프 찍기」
  2. 검색칸에 `삼성전자` 입력 → 목록 8건이 정상적으로 뜬다
  3. `삼성전자` 행을 **마우스로 클릭**
- **기대 동작**: 종목이 선택되고 예상 주가·검증 기간 칸이 열린다
- **실제 동작**: 아무 일도 없다. 몇 번을 눌러도 반응이 없다
- **재현 여부**: 100% (마우스 경로 전부). 키보드 `↓`+`Enter`로만 선택된다
- **원인(확인함)**: 자동완성 패널이 `createPortal(document.body)`로 나가는데
  (`fe/src/components/layout/header-stock-suggestions.tsx`),
  Radix Dialog가 열리면 `react-remove-scroll`이 `body { pointer-events: none }`을 건다.
  실측: 패널의 계산된 `pointer-events = none`, 옵션 중앙 좌표의
  `document.elementFromPoint()`가 **다이얼로그 오버레이**를 돌려준다
- **관련 기능**: 스탬프 생성, 보유 일괄 추가
- **심각도**: **Critical** — `/stamps` 화면의 유일한 주 행동이 마우스 사용자에게 불가능하다.
  화면은 완전히 정상으로 보여서 사용자는 "내 클릭이 안 먹네"로만 인지한다
- **증거**: `qa/shots/stamp-dlg-suggest.png`, `qa/25-stamp-dlg-dbg.mjs`
- **참고**: 같은 컴포넌트라도 **모달 밖**(보유 사이드레일·목표가 레일·메모 폼·관심종목
  레일)에서는 정상이다(`pointer-events: auto`, 클릭 가능 확인). 다이얼로그 안일 때만 깨진다

### BUG-02 · 「발행하기」가 검증도 확인도 없이 빈 공개 리포트를 영구 발행한다

- **화면**: `/reports/new`
- **재현 방법**:
  1. `/reports/new` → 종목만 고른다 (제목·본문·의견 전부 비움)
  2. 「발행하기」 1회 클릭
- **기대 동작**: 필수값 안내, 또는 되돌릴 수 없는 행동이므로 확인
- **실제 동작**: 즉시 `/reports/999`로 발행 완료. 본문 자리에 "본문이 없습니다."
  공개 범위는 기본값 **공개**라 커뮤니티 피드에 그대로 올라간다
- **재현 여부**: 100%
- **관련 기능**: 리서치 콜 발행, 하루 5건 한도, 같은 종목 30일 쿨다운
- **심각도**: **Critical** — 같은 화면이 스스로 "발행하면 …잠깁니다 … 철회는 가능하지만
  통계에서 빠지지 않습니다"라고 경고한다. 그런데 그 되돌릴 수 없는 행동에 아무 방어가
  없다. 발행은 한도와 쿨다운을 소모하고, 삭제 API가 없어 되돌릴 수도 없다
- **비교**: 훨씬 가벼운 「철회」에는 `window.confirm`이 붙어 있다 — 방어의 방향이 반대다
- **증거**: `qa/29-reports-publish.mjs`, `qa/shots/rep-999.png`

## 2. 높음 (P1)

### BUG-03 · 헤더 종목 검색이 같은 검색어에 매번 다른 결과를 준다

- **화면**: 헤더 검색(모든 화면)
- **재현 방법**: 「삼성」을 입력하고 지웠다 다시 입력하기를 4회
- **기대 동작**: 같은 검색어면 같은 목록
- **실제 동작**: 결과 창이 **호출마다 정확히 한 칸씩 밀린다**

  ```
  try1: 530063, 530089, 530094, 530095 …
  try2: 530089, 530094, 530095, 530104 …
  try3: 530094, 530095, 530104, 530106 …
  try4: 530095, 530104, 530106, 530112 …
  ```

- **재현 여부**: 100%. **API로도 동일**
  (`GET /api/v1/stocks/search?limit=5&offset=0&q=삼성`, `total=98`)
  → FE가 아니라 **검색 API의 정렬이 불안정**하다. FE는 `limit=8&offset=0` 고정
- **덤으로**: 「삼성」 98건 중 상위 8건이 전부 ETN/레버리지 상품이고 **삼성전자(005930)가
  없다**. 「삼성전자」로 정확히 치면 005930이 1위로 나온다 → 접두어 검색의 랭킹 문제
- **관련 기능**: 헤더 검색, 종목 선택이 필요한 모든 폼
- **심각도**: **High** (근본 원인은 BE. FE에서 드러나는 증상으로 기록).
  국내 1등 종목을 이름 앞 두 글자로 찾을 수 없고, 정렬이 불안정하므로 향후 페이징을
  붙이면 중복·누락이 생긴다
- **증거**: `qa/10-search-repro.mjs`, `qa/08-search.mjs`

### C-4. 실패와 빈 상태를 갈라 말하기 + 한국어로

- **현재 상태**: `internal` / `{"error":"internal"}` / `Failed to fetch`가 그대로 나오고,
  `/targets`는 데이터가 있는데도 온보딩 튜토리얼을 보여준다(BUG-09, BUG-10)
- **제안**: 원문 메시지를 사용자 문구로 매핑하고, **불러오기 실패일 때는 빈 상태 대신
  실패 상태 + 다시 시도**를 그린다. `/journal`이 이미 옳게 하고 있다("메모를 불러오지
  못했습니다.") — 그 패턴을 표준으로
- **왜 필요한가**: 지금 화면은 "당신에게 데이터가 없다"고 단언한다. 사실은 "못 불러왔다"이다
- **사용자 이점**: 데이터 유실 오해 제거. 재입력 사고 방지
- **구현 난이도**: 중간
- **기존 UX 영향**: 정상 경로 변화 없음

### C-5. 검색 Enter의 기본 선택을 손보기

- **현재 상태**: 첫 항목이 자동 하이라이트되고 Enter가 그것으로 이동한다. 랭킹이 불안정해
  「삼성」+Enter가 `ACE 삼성그룹섹터가중` / `ACE 삼성그룹동일가중`으로 갔다(실측 2회, 서로 다름)
- **제안**: (a) 랭킹·정렬 안정화(BUG-03/04)를 먼저, (b) 그 전까지는 자동 하이라이트를 끄고
  Enter는 화면 안 검색으로만
- **왜 필요한가**: 지금은 Enter가 **매번 다른 엉뚱한 종목**으로 데려간다 — 아무 반응이
  없는 것보다 나쁘다
- **사용자 이점**: 검색이 예측 가능해진다
- **구현 난이도**: 낮음(FE) / 중간(BE 랭킹)
- **기존 UX 영향**: 키보드 사용자가 `↓`를 한 번 눌러야 한다

### C-6. `/analysis` 모바일 레이아웃

- **현재 상태**: ≤414px에서 종목 헤더가 겹치고 액션 버튼이 잘리며 스크롤로도 못 닿는다(BUG-12)
- **제안**: 액션 줄을 가로 스크롤 컨테이너에 넣거나 접기, 헤더를 세로로 쌓기
- **왜 필요한가**: 사이드바 주요 메뉴이자 **헤더 검색이 종목을 고르면 착지하는 화면**이다
- **사용자 이점**: 폰에서 검색→종목 흐름이 완성된다
- **구현 난이도**: 중간
- **기존 UX 영향**: 데스크톱 변화 없음

### C-7. 리포트 카드를 링크로

- **현재 상태**: 피드 카드가 `div` + onClick이라 새 탭·링크 복사가 안 된다(BUG-16)
- **제안**: 카드 루트를 `<Link href="/reports/{id}">`로
- **왜 필요한가**: 리포트는 공유가 목적인 공개 발행물인데 링크를 복사할 수가 없다
- **사용자 이점**: 새 탭·공유·미리보기·검색엔진 수집
- **구현 난이도**: 낮음
- **기존 UX 영향**: 카드 안 버튼은 `stopPropagation` 정리 필요

### C-8. 관심종목 재추가 시 최초 「담은 가격」 유지

- **현재 상태**: 해제했다 다시 담으면 새 id·오늘 가격으로 기록된다(실측 68→69,
  257,500→258,000)
- **제안**: 오클릭 복구 시 원래 담은 가격을 되살리거나, 최소한 덮어쓰기 전에 알린다
- **왜 필요한가**: 「담은 뒤로 얼마나 움직였나」가 이 기능의 정체성인데 그 기준선이
  조용히 리셋된다
- **사용자 이점**: 기록의 신뢰. A-2(실행 취소)와 한 묶음
- **구현 난이도**: 중간 (BE 협조 필요)

### C-9. 입력 오류 문구를 실제 원인으로

## 9. 정상 동작을 확인한 것

문제만 나열하면 화면이 실제보다 나빠 보이므로, 확인해서 **통과한 것**도 남긴다.

**상태 변화가 실제 결과와 일치**

- 관심 추가 → 버튼 `관심 추가`→`관심 해제`, `GET /watchlist` 반영, 목록·요약·뉴스 카드 갱신
- 보유 추가(NVDA 12@150) → 토스트 "엔비디아 12주를 추가했습니다." → 보유·매매 이력·평단 일치
- 목표가 수정 → 기존 값 프리필(목표가 333,000 · 메모) → 저장 시 **행이 늘지 않고 갱신**
- 리포트 저장(북마크) `저장`↔`저장됨`, 추천 `0`→`1`→`0`, 댓글 등록 후 새로고침에도 유지
- 삭제 → 목록에서 사라지고 **새로고침 후에도 안 돌아옴**

**중복 제출 방어** — 로그인·보유 추가·리포트 발행·댓글 모두 빠른 3연타에 **요청 1건**.
보유 추가는 저장 후 입력칸이 비활성으로 잠긴다.

**입력 검증** — 보유 추가는 종목 미선택 시 버튼 비활성, 잘못된 수량·단가는 저장 차단
(문구만 부정확). 댓글 `maxlength=2000`, 빈 값이면 등록 비활성. 로그인은 HTML5 required 2건.

**XSS** — 메모·리포트 본문·댓글에 `<script>alert(1)</script>` 및 6,000자 한글을 넣어도
alert 0건, `main` 내부 주입 `<script>` 0개, 텍스트로 이스케이프됨.

**정렬·필터** — 보유 표 8개 컬럼 오름/내림 정확, 리포트 최신/조회/추천 정렬 정확,
뉴스 카테고리 필터(100→59→46→23건) 정확, 실적 「내 종목만」 209→0(안내 문구)→209 정확.

**네비게이션** — 뒤로/앞으로 5단계 왕복 정확, 깊은 URL 새로고침 정상, 로그아웃 후 헤더 즉시
갱신·뒤로가기로 로그인 화면 복원 안 됨, 로그인 상태에서 `/login` → `/` 리다이렉트,
비관리자의 `/admin/*` 7개 → `/` 리다이렉트, `/dashboard`·구 경로 리다이렉트 정상.

**반응형** — 390 / 768 / 1440 전부에서 **문서 레벨 가로 오버플로 0**.
넓은 표는 `overflow-x-auto` 안. 모바일 드로어는 이동 후 정상적으로 닫힘.

**로딩** — 4초 지연을 걸어 확인: 스켈레톤 `/analysis` 32개, `/holdings` 15개,
`/news` 13개 — 빈 화면으로 두지 않음.

**테마** — 라이트/다크 전환이 새로고침·라우트 이동을 넘어 유지(`data-theme`).

**레이스** — `/market` 국내/해외 12연타 후에도 상태 일관, 콘솔 오류 없음.

**세션** — 쿠키를 지우고 새로고침하면 헤더가 즉시 로그아웃 상태로 바뀌고 로그인 CTA가 뜬다.

## 10. 실패했지만 **테스트 문제**였던 것 (FE 버그 아님)

기록해 둔다 — 다음 사람이 같은 함정을 밟지 않도록.

| 처음 본 증상 | 실제 |
|---|---|
| "보유 표 정렬이 안 된다" | `<th>`가 아니라 **안쪽 `<button>`** 을 눌러야 한다. 눌러 보니 8개 컬럼 모두 정확 (BUG-24는 클릭 영역 이야기로만 남김) |
| "목표가 「수정」이 죽었다" | 목록 행 자체가 `role="button"`이고 접근명에 "수정 삭제"가 들어 있어 `getByRole('button',{name:'수정'})`이 **행**을 잡았다. 진짜 버튼은 정상 동작 |
| "리포트 정렬이 안 먹는다" | 스크레이핑이 사이드바 랭킹(`1·2·3·4`)을 읽고 있었다. 피드는 정확히 정렬됨 |
| "실적 「내 종목만」이 무반응" | 표 행 수로 재보니 209→0→209로 정확 |
| "모바일 드로어가 안 닫힌다" | 화면 밖으로 밀린 데스크톱 사이드바를 `:visible`이 세고 있었다. 스크린샷으로 정상 확인 |
| "스탬프 화면이 로그인을 잃었다" | 저장해 둔 storageState의 토큰 만료. 스크립트마다 새로 로그인하도록 바꿈 |
