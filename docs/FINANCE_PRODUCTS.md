# 금융상품 비교 (예·적금 · 대출) — MVP

> 2026-09-29 착수. 주식 기능은 건드리지 않고 **독립 섹션**으로 붙였다.
> 사용자 결정: 메뉴 3항목 + 화면 안 탭 · 파킹통장 제외 · 외부 링크는 금융회사 홈페이지와 금감원만.

## 1. 기존 시스템에서 재사용한 것

| 층 | 재사용 |
|---|---|
| 적재 | worker-filings 슬롯·수동 큐·원장(`batch_job_runs`)·감시(`batch_expectation`)·만회 허용 목록 |
| 한도 | `apibudget` 버킷 `fss_finlife` (관리자 「API 관리」에 자동 노출) |
| 조회 | `/api/v1` 공개 그룹 + `edgeDaily` 엣지 캐시, 보호 그룹(로그인) |

| 탈퇴 | `UserRepo.Delete`의 소유 표 목록에 `fin_watchlist` 추가 |

## 2. 메뉴 · 화면

```
금융상품 (사이드바 그룹, 커뮤니티 아래)
 ├ 예·적금 비교   /finance/savings      ?tab= ranking | deposit | saving
 ├ 대출 금리 비교 /finance/loans        ?tab= ranking | credit | mortgage | rent
 └ 금융 계산기    /finance/calculator   ?tab= deposit | saving | loan
상품 상세         /finance/products/{id} (색인 안 함)
```

요청서의 9개 메뉴와의 대응: 예·적금 랭킹 = savings「랭킹」, 예금·적금 비교 = 각 탭, 대출 금리 랭킹 = loans「랭킹」,
신용·주담대·전세 = 각 탭, 계산기 = calculator. **파킹통장 비교는 없다**(아래 §3).

## 3. 데이터 소스

**금융감독원 「금융상품 한눈에」 Open API** — `https://finlife.fss.or.kr/finlifeapi/{서비스}.json?auth=&topFinGrpNo=&pageNo=`

| 서비스 | 우리 kind | 주요 필드 |
|---|---|---|
| `depositProductsSearch` | deposit | 기본 `join_way·join_member·join_deny·spcl_cnd·mtrt_int·max_limit·etc_note` / 옵션 `save_trm·intr_rate_type·intr_rate·intr_rate2` |
| `savingProductsSearch` | saving | 위 + 옵션 `rsrv_type`(정액 S·자유 F) |
| `mortgageLoanProductsSearch` | mortgage | 기본 `loan_inci_expn·erly_rpay_fee·dly_rate·loan_lmt` / 옵션 `mrtg_type·rpay_type·lend_rate_type·lend_rate_min·max·avg` |
| `rentHouseLoanProductsSearch` | rent | 주담대에서 `mrtg_type` 없음 |
| `creditLoanProductsSearch` | credit | 기본 `crdt_prdt_type(_nm)·cb_name` / 옵션 `crdt_lend_rate_type`(A 대출금리·B 기준·C 가산·D 가감조정) × 점수 구간 8개 + 평균 |
| `companySearch` | — | `homp_url·cal_tel` |

권역 `020000` 은행 · `030200` 여신전문 · `030300` 저축은행 · `050000` 보험 · `060000` 금융투자.

- **인증키**: finlife.fss.or.kr 회원가입 후 신청(32자리) → `be/.env`에 `FSS_FINLIFE_API_KEY=`. 키가 없으면 API는
  `{"err_cd":"010","err_msg":"미등록 인증키"}`를 준다(2026-09-29 실측). http는 https로 307.
- **2026-10-01 키 등록·첫 수집**: 정기예금 431 · 적금 335 · 주택담보 111 · 전세자금 58 · 신용대출 112 · 금융회사 173.
  대조(DB ↔ 그 자리 API 호출): 수협 개인신용대출 801~900점 5.18%·평균 5.15% 일치, 우리저축은행 정기예금 12개월 단리 4.00%·복리 4.07% 일치,
  목록·상세·계산기 세후 이자 350,818원 일치. **주의**: curl 기본 UA(`curl/…`)로 부르면 서버가 응답 없이 멈춘다 —
  Go 클라이언트 UA(`Mozilla/5.0 (compatible; quant-port/1.0)`)·브라우저 UA는 정상. 손으로 시험할 땐 `-A`를 줄 것.
- 화면(10-01): 회사명의 「주식회사·(주)」는 표시에서만 뗀다(`shortCompanyName`). 목록 → 상세·계산기로 금액·기간·방식·금리가 따라간다
  (`prefillQuery`/`readCalcPrefill`). 주담대·전세는 전월 평균이 지금 범위 아래면 「최근 인상」 표시(실데이터 상위 3개가 전부 그랬다).
- **없는 것**: 수시입출금(파킹통장) 공시, 상품별 가입 URL, 대출 기간, 신용대출 한도, 우대조건의 구조화된 값(자유 텍스트).
  → 파킹통장은 넣지 않았고, 가입 URL 대신 회사 홈페이지·금감원 첫 화면으로만 링크한다. 은행 페이지 스크래핑은 하지 않는다.
- **한도**: 명세에 없다. 하루 한 번 약 60호출, 1.1초 간격, 버킷 1,000/일 · 90/분.
- **이용 조건(2026-10-01 확인)**: finlife 오픈API 화면에 별도 약관은 없고 금감원 「저작권보호정책」(fss.or.kr menuNo=200701)을 따른다 —
  비영리·개인 이용은 자유, **영리 목적은 금감원과 사전 협의·허락**, 게재 시 출처 「금융감독원」 명시, 무단 변경 금지. → §8.

## 4. 스키마 (`be/migrations/095_fin_products.sql`)

- `fin_products` — (kind, fin_co_no, fin_prdt_cd) 유일. 공통 칸 + `base`·`options` JSON에 **공시 원문 그대로**.
  `active`: 모든 권역이 성공한 수집에서 안 보인 상품만 0(삭제 없음). `fetched_at`: 마지막 수집 시각.
- `fin_companies` — 홈페이지·대표전화.
- `fin_watchlist` — (user_id, product_id).

## 5. 수집 구조

`worker-filings` 잡 `fin_products` 매일 **05:10 KST** → `FinProductService.Run`
(회사 → 5종 순, 권역마다 `max_page_no`까지, 최대 20페이지). 결과는 원장에 종류별 건수·숨김 수·실패 목록.

- 권역 하나라도 실패한 종류는 숨기지 않는다 — 실패가 「상품 없음」이 되지 않게.
- 호출이 전부 실패하면 잡이 **오류**로 끝난다(키 오류가 「0건 성공」으로 묻히지 않게).
- 전송 오류 메시지에서 인증키를 지운다(`*url.Error`가 URL을 통째로 싣는다).
- 화면은 이틀 넘게 갱신이 없으면 「갱신 지연」을 붙인다. 조회 경로에서 외부 호출은 없다.

## 6. 순위 알고리즘 (화면 「이 순위는 어떻게 매기나요?」와 같은 내용)

**예·적금** — `rankSavings` (`fe/src/lib/fin-products-api.ts`)
1. 입력한 금액·기간의 공시 옵션으로 **세후 이자**를 계산해 많은 순. 최고금리 숫자로 줄 세우지 않는다.
2. 기본 기준은 **기본금리(우대 없음)**. 「최고금리(우대 모두 충족)」는 선택. 상세 화면에서 사용자가 충족 가능한
   우대금리만큼(0 ~ 최고−기본 %p) 직접 올려 볼 수 있다 — 서비스가 충족 여부를 판정하지 않는다.
3. 한 상품에 조건 맞는 옵션이 여럿이면 기준 금리가 가장 높은 하나.
4. 정기예금은 입력 금액이 공시 최고한도보다 크면 제외(개수 표시). 동점은 기본금리 높은 순.
5. 필터: 기간 · 세금(15.4/9.5/0) · 단리·복리 · 정액·자유 · 금융권 · 가입 제한 없음 · 관심만.

**대출** — `rankLoans`
1. 입력한 금액·기간·상환 방식으로 **총이자** 적은 순(고정금리·매월 상환 가정).
2. 주담대·전세: 기본 금리는 **전월 실제 취급 평균**. 「최저금리(광고 금리)」는 별도 기준으로만 고르고 경고 문구가 붙는다.
   평균이 비어 있는 상품은 순위에서 빠진다(개수 표시).
3. 신용: 대출금리(A) 행의 **고른 신용점수 구간 금리**. 그 구간 취급 없으면 제외.
4. 중도상환수수료·부대비용은 총이자에 넣지 않고 원문으로 보여 준다.

광고·제휴 순위는 없다(대가를 받지 않으므로 「광고 순위」 자체가 존재하지 않는다).

**계산식** — `fe/src/lib/fin-calc.ts`: 예금 단리 `P·r·n/12`, 월복리 `P((1+r/12)^n−1)`; 적금 단리 `M·r/12·n(n+1)/2`,
월복리 `M(1+i)((1+i)^n−1)/i − Mn`; 이자 과세 후 원 단위 반올림. 대출 원리금균등 `P·i/(1−(1+i)^−n)`, 원금균등, 만기일시 — 행마다
원 단위 반올림, 마지막 달이 잔액을 정리.

## 8. 법률·규제 확인 항목 (출시 전 전문가 검토 필요 — 이 문서는 법률 의견이 아니다)

- [ ] **금융소비자보호법상 판매중개 해당 여부.** 비교·순위 + 특정 금융회사 계약으로 이어지는 동선은 중개로 볼 여지가 있다
      (2021년 금융위의 온라인 플랫폼 판단 사례). MVP는 가입 버튼·제휴·추적 링크·수수료가 없고, 링크는 회사 홈페이지 첫 화면과 금감원뿐.
- [ ] **「추천」 표현.** 화면은 「기준별 순위」로만 쓴다. 맞춤 추천(개인 정보 기반)은 자문업 등록 이슈가 있어 넣지 않았다.
- [ ] **광고 규제(금소법 광고 주체·표시 사항).** 금리 나열 화면이 광고로 해석될 여지와 필수 표시 문구.
- [ ] **금감원 자료 영리 이용 허락** — 저작권보호정책상 영리 목적이면 사전 협의 필요(10-01 확인). 광고·제휴·유료화 전에 금감원에 문의. 출처 표시는 화면마다 하고 있다.
- [ ] 제휴·중개 수수료를 도입하려면 등록(판매대리·중개업) 여부를 먼저 확정.

## 9. 배포 · 운영

1. `be/.env`에 `FSS_FINLIFE_API_KEY` 추가 → worker-filings 재생성(`docker compose up -d --build worker-filings`,
   돌던 배치가 없는지 먼저 확인).
2. 새 예약 잡은 **첫 배포 직후 워치독 만회로 한 번 돈다** — 수동 큐에 또 넣지 말 것.
3. 원장에서 `fin_products` 결과(종류별 건수·실패)를 보고, 화면 두세 상품을 금감원 사이트 수치와 대조.
4. 감시: 「배치 관리」의 `fin_products` 지연·실패, 화면의 「갱신 지연」 표시.
