2026-10-09 · Search Console 색인 46 / 미색인 1,040 · 모든 숫자는 운영 DB·서버 HTML에서 잰 값

질문에 대한 답: 화면은 상위 100개인데 왜 1,000종목인가

  • 화면 목록과는 별개 목록입니다. 실시간 차트(/market)의 상위 100은 지금 순간의 거래대금·거래량 순위이고, 크롤러가 읽는 사이트맵과 색인 허용 목록은 BE가 따로 뽑습니다(be/internal/repository/seo_stocks.go).
  • 뽑는 기준: 점수가 있는 종목 약 1.6만 개 중 최근 20거래일 평균 거래대금(종가×거래량, 미국은 원/달러로 환산) 상위 1,000개입니다(09-24 결정). 시가총액은 ADR 오류 때문에 기준에서 뺐습니다.
  • 종목 페이지(/stocks/<종목>)는 1.6만 개 모두 열리지만, 이 1,000개에만 index와 canonical을 주고 나머지는 noindex로 둡니다.
점검 중 발견: 1,000개 중 국내는 34개뿐입니다(해외 966). 원화로 환산하면 미국 대형주 거래대금이 국내보다 한두 자릿수 크기 때문에 국내 종목이 밀려납니다. 삼성전자·SK하이닉스·NAVER는 들어가지만 셀트리온·카카오·삼성바이오로직스·POSCO홀딩스·신한지주·LG는 noindex입니다(운영 사이트맵 실측). 한국어 검색 수요(「○○ 주가」)의 대부분이 국내 종목이라 비용이 큽니다.
제안: 시장별 몫을 따로 둡니다. 국내 500 + 해외 500, 각 시장 안에서 거래대금 순입니다. 총량 1,000은 그대로라 크롤 부담은 같습니다.

진단: 구글이 1,000개를 색인하지 않는 이유

  • 고아 페이지: 서버 HTML 기준으로 홈·실시간 차트·스크리너·변화·뉴스·실적 어디에도 <a href="/stocks/…">가 0개입니다. 행 클릭은 JavaScript로 패널을 여는 방식이라 크롤러가 따라갈 수 없습니다. 구글은 사이트맵에만 있고 링크가 없는 주소를 「발견됨 – 현재 색인되지 않음」으로 미룹니다.
  • 얇은 본문: 종목 페이지에서 서버가 그리는 글은 요약 한 줄, 평균 209자입니다. 1,000개 페이지가 거의 같은 틀로 보여 「크롤링됨 – 현재 색인되지 않음」이 되기 쉽습니다.
  • 그래서 1.5만 개 전체를 색인으로 여는 것은 지금은 역효과입니다. 링크와 본문을 먼저 보강하고, 색인 비율이 오르면 범위를 넓힙니다(예: 2,000 → 3,000).

이미 배포함(화면 변화 없음)

  • 옛 주소 6개(/wealth·/wealth/*·/finance/calculator)가 200 + 빈 화면 + index로 응답하던 것을 308 리다이렉트로 바꿨습니다.
  • 사이트맵에 색인 대상인데 빠져 있던 5개 화면을 추가했습니다: /screener · /changes · /finance/rates · /real-estate · /real-estate/auctions (1,016 → 1,021).

B. 목록의 종목명을 링크로 + 뒤로 가기로 이전 종목 복원 동작 변경

대상: 실시간 차트 목록, 스크리너 결과, 오늘의 변화, 뉴스의 종목 칩. 겉모양은 그대로 두고 행 안의 종목명을 진짜 <a href="/stocks/…">로 바꿉니다.

D. 리포트 작성자 페이지 공개 설정만

robots.txt의 /reports/authors/ 차단을 풀고, 작성자 페이지에 index를 줍니다. 화면 변화는 없습니다. 지금은 공개 리포트가 3건이라 효과는 작지만, 리포트가 늘면 리포트끼리 이어 주는 허브가 됩니다. 작성자 페이지에는 아이디·닉네임만 나옵니다(개인정보 없음). 확인 필요: 작성자 페이지가 공개 목록인 것이 괜찮은지
