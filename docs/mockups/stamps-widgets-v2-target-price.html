스탬프 v2 — 예상 주가 · 검증기간 · 판정 규칙

B안에서 요청하신 예상 주가(필수)와 자유 검증기간은 스키마·판정 로직까지 바뀝니다. 결정할 것만 모았습니다.

1

스탬프 찍는 순간 — 폼이 언제 뜨나

지금 스탬프 버튼은 한 번 누르면 바로 저장되고 가설(관점·기간·메모)은 저장 후 팝오버에서 붙입니다. 코드 주석에 그 이유가 적혀 있습니다 — "폼을 먼저 받으면 그 순간에만 의미 있는 캡처와 사용자 사이에 폼이 끼어든다." 그런데 예상 주가를 필수로 만들면 저장 전에 값을 받아야 합니다. 두 방식이 있습니다.

2

적중/빗나감을 무엇으로 판정할까 — 가장 중요한 결정

지금 규칙은 방향만 봅니다 (강세 → 수익률>0이면 적중). 예상 주가가 생기면 "얼마나 정확했나"를 물을 수 있습니다. 아래 표의 예시는 전부 같은 스탬프 4건에 규칙만 바꿔 적용한 것입니다.

2-A. 방향만 현행 유지

강세 → 오르면 적중 · 약세 → 내리면 적중 · 관망 → ±3% 이내면 적중.
예상 주가는 참고 표시만.

스탬프목표결과판정
삼성 강세82,000+9.6%적중
SK 약세185,000+8.3%빗나감
NVDA 강세$210+0.4%적중
애플 강세$260+18%적중
  • 기존 적중률 통계가 그대로 이어짐
  • 머리로 재현 가능한 규칙
  • NVDA +0.4%인데 적중 — 목표 $210(+18%)엔 한참 못 미침
  • 예상 주가를 필수로 받는 의미가 약함

2-B. 목표가 도달 엄격

만기 종가가 목표가에 도달했는가.
강세 → 종가 ≥ 목표 · 약세 → 종가 ≤ 목표.

  • 삼성 81,300원(+9.6%)인데 빗나감 — 700원 차이
  • 적중률이 크게 떨어져 (예시 4건 중 1건) 의욕이 꺾임
  • 목표를 보수적으로 적는 쪽이 유리해짐

2-C. 방향 + 정확도 2단 추천

적중/빗나감은 방향으로 (기존 통계 유지).
거기에 목표가 정확도를 별도 지표로 — 오차 = |만기가 − 목표| ÷ 목표.

5

스키마 변경 — 기존 스탬프 전량 삭제

"이번 장 종료 / 다음 장 종료"는 일수로 표현할 수 없어서 horizon_days를 만기 시각(due_at) + 종류(horizon_kind)로 바꿔야 합니다. 만기는 생성 시점에 확정 저장합니다 — 나중에 계산하면 휴장일 데이터가 바뀔 때 과거 판정이 흔들립니다. 장 마감 시각은 기존 marketdata/calendar가 이미 알고 있습니다 (KRX 15:30 KST · US 16:00 ET, 휴장일 포함).

-- be/migrations/046_stamps_target_price.sql TRUNCATE TABLE stamps; ← 전체 사용자의 스탬프가 사라집니다 (복구 불가) ALTER TABLE stamps ADD COLUMN target_price DOUBLE NOT NULL AFTER conviction, ADD COLUMN horizon_kind VARCHAR(20) NOT NULL DEFAULT '1m' AFTER target_price, ADD COLUMN due_at TIMESTAMP(3) NOT NULL AFTER horizon_kind, DROP COLUMN horizon_days; -- horizon_kind: session_close | next_session_close | 1w | 1m | 3m | custom -- due_at: 생성 시 캘린더로 확정한 UTC 만기 (표시는 KST)

현재 DB에 스탬프가 몇 건 있는지 확인한 뒤 진행하겠습니다. 삭제 대신 기존 행을 남기고 target_price = 0인 것을 "구버전 스탬프"로 목록 하단에 따로 보여주는 방법도 있습니다 — 통계에서는 제외하고요.
