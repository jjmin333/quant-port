스탬프 v3 — 시안 A

개봉 극장 (Reveal-first)
A 개봉 극장 B 예측 원장 C 만기 트랙 D 판단 코치
한 줄 주장
스탬프 화면의 유일한 사건은 개봉이다. 그러니 개봉이 화면의 주인공이어야 한다. 지금은 「개봉 대기 3건」이 네 개 타일 중 하나로 다른 통계와 같은 무게를 갖고 있고, 실제 개봉은 모달 뒤에 숨어 있다 — 재방문 동기 전체가 그 안에 갇혀 있다.

시안 A는 화면을 세 층으로 나눈다. ① 봉인 카드 덱(만기가 지났고 아직 안 연 것) — 결과를 가려두고 그때의 내 예측과 메모만 보여 준 뒤 「열기」로 뒤집는다. ② 검증 중 트랙(D-day와 목표까지 진행률). ③ 지난 기록(압축 표).

가려두는 것이 핵심이다. 결과가 처음부터 옆에 적혀 있으면 「그때 나는 뭐라고 했지」를 스스로 떠올릴 기회가 사라지고, 채점은 그냥 숫자 확인이 된다.

이 시안이 쓰는 데이터

  • 봉인면 — note, targetPrice, expectedReturn, horizonKind, dueAt, conviction, stance
  • 개봉면 — horizon.return / benchmarkReturn / alpha, targetAccuracy, targetHit, verdict, current.score
  • 맥락 — context.news[0], context.aiKeywords, snapshot.held / watchlisted
  • 진행률 — targetProgress, peakReturn, troughReturn

재사용하는 기존 컴포넌트

  • StampSeal — 개봉면 판정 도장 (크기만 확대)
  • StampTargetGauge — 검증 중 트랙의 진행 게이지
  • StampRevealModal — 「모두 열기」 경로로 유지
  • StampDetailModal · StampScorecardModal — 그대로
  • StockAvatar · PriceDisplay · SectionCard

버리는 것

  • 4개 균등 타일 — 개봉 대기가 다른 통계와 같은 크기였다
  • 타임라인/종목별 토글 — 「지난 기록」 표의 정렬로 흡수
  • 행 하나에 숫자 8개를 균등 배치하던 StampRow

약점 (미리 밝힘)

  • 스탬프가 0건이거나 개봉 대기가 0건이면 화면 상단이 텅 빈다 → 그때는 「검증 중」이 승격되도록 층 순서를 바꿔야 한다
  • 개봉 대기가 10건 넘게 쌓이면 덱이 길어진다 → 3장 + 「나머지 7건 모두 열기」
