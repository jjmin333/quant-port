## 1. 한 줄 정의

**리서치 콜 = 공개 종목 논증 + 검증 가능한 예측.**
작성자는 *논거*만 쓰고, **근거 데이터·판정·순위는 서버가 만든다.**

### 스탬프와의 관계 — 없음 (2026-08-09 사용자 결정)

초기 설계는 스탬프를 콜로 "승격"시키는 경로를 뒀으나, **두 기능은 서로 연동하지 않는
독립 기능으로 간다.** 따라서:

- 스탬프 화면에서 콜로 넘어가는 진입점을 두지 않는다.
- **리서치는 스냅샷 타입을 직접 소유한다**(`ResearchContext`/`ResearchNews`/`ResearchIndex`/
  `ResearchChart`/`ResearchCurrent`/`ResearchReturn`). 다른 기능이 바뀌었다는 이유로 바뀔 수
  있는 스냅샷은 박제된 게 아니다.
- 일별 종가 시계열·벤치마크 배정·거래일 판정 같은 **시장 데이터 원시 연산만 공유**한다
  (`service/close_series.go`). 이건 어느 기능의 소유물도 아니다.

콜의 진입점은 종목 화면(`콜 발행` 버튼)과 `/research/new` 두 곳뿐이다.

| # | 약점 | 왜 문제인가 |
|---|---|---|

## 5. 차별점 7가지 (이 기능의 존재 이유)

### 5.1 근거 카드는 서버가 박제한다 (약점 C)

발행 버튼을 누르면 **서버가** 그 시각의 시세·5축 점수·피어 백분위·커버리지·기술지표·뉴스·공시·지수를
수집해 불변 스냅샷으로 굳힌다. 클라이언트가 보낸 값은 신뢰하지 않는다.

화면은 **"작성자 주장"과 "기계 측정"을 나란히** 놓는다.

```
작성자: 매수 · 목표 $128 (+102%) · 12개월 · 확신도 70%
기계  : 종합 41점(C) · 가치 68 / 수익성 22 / 성장 55 / 추세 31 / 심리 47 · 커버리지 62%
        → 점수 대비 역발상 콜
```

독자는 3초 만에 "이 사람은 지표를 알고도 반대로 가는 사람인가, 모르고 쓰는 사람인가"를 판단한다.

### 5.2 순위는 알파로 매긴다 (약점 A)

기본 정렬·리더보드 1급 지표는 **벤치마크 초과수익(알파)**. 원수익률은 병기하되 정렬 키가 아니다.
벤치마크는 `asset_type`으로 자동 배정한 뒤 발행 시 고정한다(kospi/kosdaq/sp500/nasdaq100).

2단계로 확장 가능: **피어그룹 초과수익**(시총 3분위 × asset_type) — 반도체 랠리에서 반도체를 산 것과
반도체 안에서 남들보다 나은 걸 고른 것을 구분한다.

> 요지: *"목표 달성"이 아니라 "시장을 이겼는가"* 가 우리 서비스의 1급 질문이다.

### 5.3 콜 값은 불변, 본문 수정은 이력 공개, 삭제해도 통계에 남는다 (약점 B)

| 필드 | 발행 후 |
|---|---|
| 종목·방향·기준가·목표가·손절가·기간·확신도·발행시각·근거 스냅샷 | **UPDATE 금지** |
| 본문(논거)·태그 | 수정 가능. **`research_revisions`에 diff 저장, 상세 화면에 "수정 3회" 노출** |
| 공개 범위 | 공개 → 비공개 전환 가능하되 **통계에서 빠지지 않는다** |
| 삭제 | soft delete(`retracted`). 리더보드에 **철회율**로 반영 |

이것 하나가 Valley AI 대비 가장 큰 신뢰 격차를 만든다.
*지울 수 있으면 그 리더보드는 광고판이고, 못 지우면 성적표다.*

### 5.4 빈 화면에서 시작하지 않는다 (약점 F)

`stock_briefing.go`가 **LLM 없이** 이미 만들어내는 것:
투자포인트 최대 4개(우선순위·톤 색상), 상승/하락 시나리오, **실제 지표에서 유래한 주요 가격대**
(SMA20/50/200 · 최근 스윙 고저 · 52주 범위).

이걸 작성 화면의 초안으로 주입한다. 작성자는 **왜 그렇게 보는지만** 쓴다.

```
[자동] 상승 시나리오 — 50일선 258,260(+9.9%) 회복 시 200일선 261,002
[자동] 하락 시나리오 — 20일선 234,200(-0.34%) 이탈 시 스윙저점 189,200
[작성자] 나는 왜 상승 쪽에 거는가 ...
```

Valley AI가 요구하는 장문 + 배너 이미지 대비 **참여 funnel이 근본적으로 넓다.**
배너 이미지는 선택이며, 기본 썸네일은 종목 미니차트 + 5축 미니 레이더로 자동 생성한다(LLM/이미지 API 0회).

### 5.5 목표가를 지어내게 두지 않는다 (약점 G)

목표가 입력란 옆에 **실측 분포**를 실시간으로 붙인다. `candle_bars` 일봉으로 계산:

```
목표 +135% / 12개월
→ 이 종목이 과거 12개월 구간에서 +135% 이상 간 경우: 673개 구간 중 4회 (0.6%)
→ 같은 피어그룹 상위 5% 12개월 수익률: +48%
```

허풍에 즉시 비용이 붙는다. 차단하지는 않는다 — **보여주기만 한다.**
(0.6%짜리 콜을 맞히면 그건 진짜 인사이트이고, 리더보드가 그걸 크게 보상해야 한다.)

목표가·손절가는 자동 계산된 주요 가격대 위에 스냅되도록 제안하되 자유 입력을 막지 않는다.

### 5.6 확신도를 진짜로 채점한다 (약점 E)

- **기대값 표시**: `(목표가-기준가)×P − (기준가-손절가)×(1−P)`, 여기서 P는 작성자가 적은 확신도.
  추가로 **작성자의 과거 실측 적중률**을 P에 대입한 값을 나란히 보여준다.
- **캘리브레이션 점수**(Brier score 계열)를 리더보드 지표에 포함:
  확신도 90%짜리 콜의 실제 적중률이 50%면 점수가 깎인다.
- 확신도 100% 남발이 손해가 되는 구조. 이게 "확신도"라는 필드를 장식에서 지표로 바꾼다.

### 5.7 역발상 집계 — 우리 점수의 예측력 검증과 같은 축

발행 시 5축 점수와 콜 방향이 어긋나면 `역발상` 태그가 자동 부여된다(점수 ≤ 40 + 매수, 점수 ≥ 70 + 매도 등).

- **역발상 콜의 적중률을 별도 집계**한다. 기계와 같은 방향으로 이겨봐야 기계가 이긴 것이다.
- 반대로 이 집계는 `AGENT_STATE.md` TODO의 **"점수 예측력 검증(score(D) vs return(D+1) IC)"** 에
  그대로 입력이 된다. 사용자 콜 데이터 → 점수 모델 개선 → 더 나은 근거 카드 → 더 좋은 콜.
  **콜 기능이 우리 점수 엔진의 학습 루프가 된다.** 이건 Valley AI에는 대응 개념 자체가 없다.

| `/reports/new` | 작성 (종목 화면에서 진입) |
| `/reports/authors/[userId]` | 작성자 성적표 + 공개 리포트 |
| ~~`/research/leaderboard`~~ | **삭제 (2026-08-10)** — 상단 개편 노트 참고 |

**종목 화면과 양방향 연결**: `/stocks/[symbol]` 워크스페이스와 `종목 분석` 탭에
`이 종목 콜 N건 (강세 7 · 약세 2)` 섹션 추가. 콜이 종목 화면의 트래픽을 받고,
종목 화면이 콜의 근거 데이터를 받는다.

### 6.1 피드 카드

Valley 카드와 유사한 골격에 우리 데이터를 얹는다.

```
┌──────────────────────────────────┐
│ [자동 썸네일: 미니차트 + 5축 레이더]      │
│ 🇺🇸 CRCL  Circle Internet Group        │
│ AI 에이전트를 위한 VISA, Circle          │
├──────────────────────────────────┤
│ 판정 진행  ████████░░ 62%  D+142/365     │
│ 매수 · 목표 +102%  │  현재 +38%          │
│ 알파 +11.2%p (S&P500 대비)  ← 1급 지표   │
│ 발행시 점수 41(C) · 역발상               │
│ 👁 7,624  💬 23  👍 58   @author 알파 +4.1%p│
└──────────────────────────────────┘
```

정렬 탭: `최신 / 알파순 / 판정임박 / 역발상 / 내 관심종목`. **원수익률 정렬은 두지 않는다.**

### 6.2 상세

- **좌**: 논거 본문(마크다운) + 자동 생성 시나리오 블록 + 수정 이력
- **우 고정 사이드**: ① 콜 카드(방향·목표·손절·기간·확신도·기대값) ② **발행 시점 근거 카드**
  (5축 막대·백분위·커버리지·PER/PBR·52주 위치) ③ **당시 → 현재 2열 대조** ④ 판정 진행 바
  ⑤ 목표/손절선이 그려진 차트(발행 시점 마커 + 이후 경로) ⑥ 당시 뉴스·공시 ⑦ `dataGaps` 명시
- 375px에서는 세로 스택

## 7. 작성 플로우 (3분 콜)

```
① 진입: 종목 화면 [콜 발행] · /research/new
   ↓ (서버가 근거 스냅샷 수집 — 외부 호출 0)
② 콜 값: 방향 / 목표가 / 손절가 / 기간 / 확신도
   → 옆에 실시간으로: 주요 가격대 스냅 제안, 과거 도달 확률(§5.6), 기대값(§5.7)
   ↓
③ 논거: 자동 초안(투자포인트·시나리오·가격대)이 이미 채워진 에디터. 작성자는 이유만 추가
   ↓
④ 발행: 공개 범위 선택 + 면책 확인
   ↓
⑤ 발행 후: 콜 값 잠김. 본문만 수정 가능(이력 공개)
```

**모달 3단 마법사를 만들지 않는다** — 마찰이 사용률을 좌우한다.
한 화면 안에서 좌(콜 값) / 우(논거)로 배치하고, 논거가 비어도 발행 가능하게 한다(근거 카드는 항상 붙으므로).

## 8. 판정 엔진

판정은 `research_performance.go`가 전담하고, 일별 종가 시계열 원시 연산만 `close_series.go`에서 공유한다.

- **기준가** = 발행 시 `price`. 비교값은 `stock_daily_closes` 종가.
- **구간 경계**: 캘린더 기준 + 거래일 보정, 미도래 구간은 `null` → `—`.
  (금요일 발행의 1D 목표일이 토요일인 문제와, 거래가 끊긴 종목의 몇 달 뒤 종가가 짧은 구간을 채우는 문제를 함께 막는다)
- **판정 상태**:

| 상태 | 조건 |
|---|---|
| `open` | 기간 내, 목표·손절 모두 미도달 |
| `target_hit` | 종가 기준 목표가 도달 (**도달일 기록**) |
| `stop_hit` | 종가 기준 손절가 도달 |
| `expired_hit` | 만기 시 방향 일치 (강세 → 수익률 > 0) |
| `expired_miss` | 만기 시 방향 불일치 |
| `retracted` | 작성자 철회 (통계에는 남음) |

- **종가 기준으로만 판정한다.** 장중 고가 터치로 판정하면 유동성 낮은 종목의 순간 스파이크가
  목표 달성이 된다.
- **알파** = 종목 수익률 − 벤치마크 수익률(`index_daily_closes`). 판정과 함께 항상 계산.
- **기간 정규화 수익률**: 6개월 콜과 12개월 콜을 같은 표에 세우려면 연율화가 필요하다.
  단 짧은 기간의 연율화는 과장되므로 **최소 30일 미만 콜은 연율화하지 않고 별도 표기**.

### 8.1 배치

기존 `batch_job_runs` 큐 + 전용 워커 패턴을 그대로 따른다.

- 신규 잡 `research_verdict` → `worker-research`
- 트리거: 일별 종가 워커(`worker-close-domestic` / `worker-close-overseas`) **완료 이후**.
  종가가 없는데 판정하면 전일 값으로 오판한다.
- 하는 일: ① 만기·목표·손절 도달 콜 판정 ② 알파 재계산 ③ `research_author_stats` 재계산
- **DB 전용 잡** — 배치 관리 화면에서 `외부 API 호출 없음` 배지로 표시.

## 9. ~~리더보드~~ — 삭제됨 (2026-08-10)

> **이 절은 구현되었다가 제거됐다.** 남겨두는 이유는 "왜 안 만들었나"가 아니라 "왜
> 걷어냈나"를 기록하기 위해서다. 순위표 자체의 설계 결함이 아니라 **줄 세우기가 필요로
> 하는 것**이 문제였다: 순위는 계속 볼 이유가 있어야 하고, 그 이유가 결국 보상(상금·
> 시즌 대회)이며, 보상은 유사투자자문 규제선을 건드린다(§15-1). 아래 표는 삭제 시점의
> 최종 규칙이다. 작성자 개인 성적표(표본 수·철회율 포함)는 그대로 유지된다.

| 규칙 | 이유 |
|---|---|
| **최소 표본 10건** 미만은 `관찰 중` 별도 섹션 | 1건 100%가 1위가 되는 걸 막는다 |
| 기본 지표 = **평균 알파(기간 정규화)** | §5.2 |
| 보조 지표 = 적중률 · 캘리브레이션 · **철회율** | §5.3 / §5.6 |
| **발행 빈도 페널티** | 같은 종목 30일 내 다수 콜, 하루 N건 초과는 가중 축소 |
| 기간 탭 3개월 / 12개월 / 전체, 시장 탭 국내 / 해외 | 한 시즌 운으로 영구 상위 고정되는 것 방지 |
| 종목 게이트: 시총·평균 거래대금 하한 미달 종목은 리더보드 집계 제외 | 소형주 펌핑 유인 차단 (§12) |

작성자 카드에는 항상 **표본 수와 철회율을 함께** 표시한다. 승률만 보이는 순간 그건 광고다.

## 11. 데이터 모델 (스케치)

> `insights` 라는 이름은 이미 `service/insights.go`(대시보드 인사이트)가 점유 중이다.
> 테이블·서비스 접두어는 `research_` 를 쓴다.

```sql
-- 037_research_calls.sql
CREATE TABLE IF NOT EXISTS research_calls (
  id             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
  user_id        BIGINT UNSIGNED NOT NULL,
  symbol         VARCHAR(32)  NOT NULL,
  symbol_name    VARCHAR(100) NOT NULL DEFAULT '',
  asset_type     VARCHAR(16)  NOT NULL DEFAULT '',
  currency       CHAR(3)      NOT NULL DEFAULT 'KRW',
  title          VARCHAR(200) NOT NULL,
  -- ── 불변 콜 값 (발행 후 UPDATE 금지) ──────────────────
  published_at   TIMESTAMP(3) NOT NULL,
  trade_date     DATE         NOT NULL,
  benchmark_id   VARCHAR(32)  NOT NULL DEFAULT '',
  direction      VARCHAR(8)   NOT NULL,          -- buy | sell | hold
  base_price     DOUBLE       NOT NULL,
  target_price   DOUBLE       NULL,
  stop_price     DOUBLE       NULL,
  horizon_days   SMALLINT     NOT NULL,          -- 30 | 90 | 180 | 365
  conviction     TINYINT      NOT NULL,          -- 0~100 (%)
  score_at_pub   TINYINT      NULL,
  grade_at_pub   VARCHAR(2)   NULL,
  contrarian     TINYINT(1)   NOT NULL DEFAULT 0,
  evidence       JSON         NOT NULL,  -- 시세·5축 breakdown·백분위·커버리지·밸류에이션
  context        JSON         NOT NULL,  -- 뉴스·공시·지수·AI요약·룰기반 브리핑·dataGaps
  chart          JSON         NOT NULL,  -- { interval, bars: [...최대 200] }
  -- ── 가변 ─────────────────────────────────────────
  body_md        MEDIUMTEXT   NOT NULL,
  body_rev       INT          NOT NULL DEFAULT 1,
  visibility     VARCHAR(12)  NOT NULL DEFAULT 'public', -- public | unlisted | private
  status         VARCHAR(16)  NOT NULL DEFAULT 'open',
  verdict_at     TIMESTAMP(3) NULL,
  verdict_return DOUBLE       NULL,
  verdict_alpha  DOUBLE       NULL,
  view_count     INT UNSIGNED NOT NULL DEFAULT 0,
  like_count     INT UNSIGNED NOT NULL DEFAULT 0,
  comment_count  INT UNSIGNED NOT NULL DEFAULT 0,
  retracted_at   TIMESTAMP(3) NULL,
  created_at     TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at     TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
                   ON UPDATE CURRENT_TIMESTAMP(3),
  KEY idx_rc_pub      (visibility, status, published_at DESC),
  KEY idx_rc_symbol   (symbol, published_at DESC),
  KEY idx_rc_user     (user_id, published_at DESC),
  KEY idx_rc_verdict  (status, horizon_days, published_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

부속 테이블:

| 테이블 | 용도 | 비고 |
|---|---|---|
| `research_revisions` | 본문 수정 이력(diff) | append-only, read-only |
| `research_reactions` | 좋아요·북마크 | `(call_id, user_id, kind)` UNIQUE |
| `research_comments` | 댓글 | 1단계 대댓글, soft delete |
| `research_ratings` | 3축 평가 | 결과 확정 전만 |
| `research_author_stats` | 작성자 집계 | 배치 산출물, read-only |
| `research_views` | 조회 중복 제거 | TTL 정리 대상 |

정렬·필터에 쓰는 값만 컬럼, 나머지는 JSON — `stock_scores`와 같은 패턴.

> ⚠️ `036` 세션에서 확인된 함정: `splitSQLStatements`가 `;`로 단순 분할하므로

## 13. LLM 예산 영향 (중요)

현재 Gemini 무료 티어에서 **일 500콜 중 배치가 241콜**을 쓴다(`apibudget` TPM/TPD 가드 존재).
콜 발행마다 LLM을 붙이면 사용자가 조금만 늘어도 즉시 초과한다.

| 경로 | LLM |
|---|---|
| 근거 카드·자동 초안·시나리오·가격대 | **0콜** (`stock_briefing.go` 룰 기반) |
| 자동 썸네일 | **0콜** (미니차트 + 5축 레이더 SVG 생성) |
| 본문 다듬기 / 요약 | **선택** — 사용자당 일 N회 상한, `apibudget` reserve에서 차감 |
| 해외 콜 번역 | 기존 번역 예산 공유, 요청 시에만 |

**온디맨드 LLM 호출을 기본 경로에 넣지 않는다** — 08-09 세션에서 이미 같은 이유로
온디맨드 요약 호출을 제거했다. 같은 실수를 반복하지 않는다.

## 15. 규제·컴플라이언스 (설계 제약으로 먼저 반영할 것)

이건 기능 설계보다 먼저 확인해야 하는 항목이다. **법률 자문이 아니라 설계 시 고려사항**이다.

1. **유사투자자문업 이슈** — 국내에서 불특정 다수를 상대로 대가를 받고 투자조언을 제공하는 것은
   신고 대상이다. Valley AI처럼 **예측대회 + 상금/수익배분**을 붙이는 순간 성격이 달라진다.
   Phase 1은 **금전 보상 없는 평판 시스템**으로 시작하고, 보상 구조는 별도 검토 후 결정한다.
2. **서비스의 추천으로 읽히지 않게** — 콜은 작성자 개인 의견이고 서비스는 채점만 한다.
   홈·푸시에서 특정 콜을 서비스가 선별해 밀면 서비스의 투자권유로 해석될 여지가 생긴다.
   → 피드 기본은 알고리즘 추천이 아니라 사용자 정렬(§10).
   (콜에는 작성자의 실제 보유·계좌 정보가 일절 포함되지 않으므로 그 축의 개인정보 이슈는 없다.)
3. **문구 규칙** — "적중/빗나감"까지만 쓰고 "매수하세요"로 넘어가지 않는다.
   상세·피드 하단에 고정 면책 문구.
4. **시세조종성 게시물 방지** — 소형주 펌핑 유인이 구조적으로 생긴다.
   종목 게이트(§14) + 동일 종목 단시간 다수 콜 탐지 + 신고 기능 + 관리자 숨김 경로를 **Phase 1에 포함**한다.
   (소셜 기능보다 먼저 들어가야 한다.)

## 16. 단계별 로드맵

### Phase 1 — 검증 가능한 콜 (소셜 없음) ✅ 2026-08-09
공개 없이도 단독으로 가치가 있다.

- ✅ `research_calls`/`research_revisions`/`research_reports` + 발행 API + 서버측 근거 스냅샷
- ✅ 발행 전 미리보기(도달 분포·기대값·근거 카드·자동 초안)
- ✅ 판정 엔진(`research_performance.go`) + `worker-research`
- ✅ `/research`(내 콜 + 성적표 + 공개 피드 토글), `/research/new`, `/research/[id]`
- ✅ 종목 헤더 `콜 발행` 버튼
- ✅ 신고·관리자 숨김·종목 게이트 (§15-4)

**구현 중 확정된 사항**

- **동일 종목 30일은 경고가 아니라 409**로 막았다. Phase 1엔 리더보드 가중 축소라는
  적용 대상이 없어서 "경고만"이 곧 무제한 발행이 된다.
- **모순된 목표/손절 쌍은 400으로 거부한다.** 방향과 어긋난 쌍은 기대값·손익비의 부호를
  뒤집는데, 그 숫자는 서버가 보증한 것처럼 화면에 나간다.
- **목표 도달 확률은 `stock_daily_closes`가 아니라 `candle_bars` 일봉**으로 계산한다
  (실측: 005930의 `stock_daily_closes`는 27행뿐, `candle_bars`는 1,938개 90일 구간).
  겹치는 구간이 30개 미만이면 확률 대신 `insufficient`를 반환한다 — 표본이 없다는 뜻의 0%가
  가장 위험한 숫자다.
- **`expired_unknown` 신설**: 만기가 지났는데 판정할 종가가 없는 경우. 적중도 빗나감도 아니고
  적중률 분모에 들어가지 않는다(우리 데이터 결손을 작성자 책임으로 돌리지 않는다).
- **판정 배치는 07:00 KST**. KRX 마감+20분(전날 15:50)과 US 마감+20분(당일 05:20~06:20 KST)
  둘 다 지난 시각이어야 한다.
- **레이아웃**: 최초엔 `/research/new`·`/research/[id]`를 2단 작업 화면(`wide` 아케타입)으로
  뒀다 — `reading`(뷰포트 68%)에 2단을 넣으니 1280px에서 본문 입력칸이 236px까지 눌렸기
  때문. **2026-08-10에 2단 자체를 버리고 한 컬럼 중앙 정렬(`reading`)로 통일**했다.
  에디터가 컬럼 전체 폭을 쓰므로 눌릴 일이 없고, 모바일에서 어차피 세로로 쌓이며 순서가
  뒤엉키던 문제도 함께 사라진다.

### Phase 2 — 공개 피드 ✅ 2026-08-10
- ✅ `/reports` 목록(공개 리포트 토글), 공개 범위
- ✅ 조회수(30분 중복 제거)·좋아요·북마크
- ❌ 리더보드 — 구현했다가 **2026-08-10 제거**(상단 개편 노트 · §9)
- ⏸ 자동 썸네일, 종목 화면 `이 종목 리포트 N건` 섹션 —
  API(`/research/symbols/{symbol}/summary`)는 있으나 화면 삽입은 미착수

### Phase 3 — 커뮤니티 + 심화 지표 ✅ 2026-08-10 (일부)
- ✅ 댓글(1단계 대댓글, soft delete)·3축 평가·작성자 프로필(`/reports/authors/[userId]`)
- ✅ 캘리브레이션 점수(Brier), 역발상 적중률 집계
- ⏸ 팔로우·`@handle` — 미착수
- ⏸ 리포트 데이터 → `stock_scores` 예측력 검증 루프 (§5.7) — 판정 표본이 쌓인 뒤
- ❌ 시즌제 대회·보상 구조 — **도입하지 않음**(2026-08-10 사용자 결정)

**Phase 2~3 구현 중 확정된 사항**

- **리더보드 순위 키는 "연율화 알파 × 페널티"**다. 30일 콜과 365일 콜을 한 표에 세우려면
  연율화가 필요하고, 연율화는 **±200%p로 클램프**한다 — 30일 +40%를 12배 하면 그 숫자는
  작성자가 아니라 지수를 재는 것이 된다. 30일 미만은 아예 연율화하지 않는다.
- **페널티 2종**(§9): 월 8건 초과 발행은 초과분에 비례해 축소, 동일 종목 반복은 1건당 3%p
  축소. 하한 0.5. 차단이 아니라 **공짜가 아니게** 만드는 것이 목적.
- **철회 콜은 성과 평균에서 빠지되 발행 수·철회율에는 남는다.** 이 짝이 없으면 적중률은
  "지고 있는 콜을 지우면" 만들어낼 수 있다.
- **평가는 판정 전에만 가능**하고 자기 콜은 평가할 수 없다. 결과를 보고 매기는 평가는 논거
  평가가 아니라 성과 재측정이고, 그건 알파 숫자가 이미 더 잘한다.
- **대댓글은 1단계로 강제**한다. 대댓글의 대댓글은 서버가 조부모에 붙인다(실측 확인).
- **조회수는 상세 조회의 부수효과가 아니라 별도 엔드포인트**(`POST .../view`)다. 상세 fetch에
  얹으면 리렌더·폴링마다 올라 조회수가 아니라 렌더 카운터가 된다. 뷰어 키는
  로그인=user id 해시 / 비로그인=IP+UA 해시(SHA-256)이고 **원문은 저장하지 않는다**.
- **소셜 카운트는 비정규화하지 않는다.** 좋아요/댓글 수는 매번 집계한다 — 행과 어긋날 수 있는
  카운터가 쿼리 하나보다 나쁘다. 피드에서는 페이지 크기와 무관하게 고정 쿼리 수로 붙인다.

## 18. 이미지 업로드 (2026-08-10 신설)

리포트 본문의 사진이 첫 사용처지만, **리포트 기능이 아니다.** 메모장 첨부·프로필
사진·향후 어떤 화면이든 같은 경로를 쓴다.

### 구조

| 층 | 위치 | 책임 |
|---|---|---|
| `media.Store` (interface) | `be/internal/media/store.go` | 바이트 저장/조회/삭제. **여기가 교체 지점** |
| `media.LocalStore` | `be/internal/media/local.go` | 첫 구현(파일시스템). S3/GCS는 같은 인터페이스로 추가 |
| `MediaService` | `be/internal/service/media.go` | 정책(허용 타입·크기·URL 생성). 다른 기능은 이 서비스를 부른다 |
| `MediaHandler` | `be/internal/handler/media.go` | `POST /api/v1/media/images`(인증) · `GET /api/v1/media/*`(공개) |
| `lib/media-api.ts` | FE | `uploadImageClient(file)` — 리포트 전용 아님 |
| `MarkdownEditor` | FE | 버튼·붙여넣기·끌어놓기 → 업로드 → `![alt](url)` 삽입. 업로더는 prop으로 주입 가능 |

### 규칙과 이유

- **키는 내용 해시**(`sha256`, `ab/cd/<hash>.png`). 같은 파일을 두 번 올려도 한 개이고,
  객체가 불변이라 `Cache-Control: immutable`이 성립한다. 2단 프리픽스는 파일시스템에서
  한 디렉터리에 수십만 개가 쌓이는 걸 막고, 객체 스토리지에선 평범한 prefix다.
- **타입은 서버가 스니핑해서 결정한다.** 업로드가 주장한 Content-Type·파일명은 근거가
  아니다. `image/png`이라고 선언한 HTML은 415로 거부된다(테스트로 고정).
- **SVG는 이미지로 취급하지 않는다.** 스크립트를 담을 수 있는 문서다.
- 서빙 응답에 `X-Content-Type-Options: nosniff` + `Content-Security-Policy: default-src
  'none'; sandbox`. 사용자 업로드 바이트가 실행 가능한 무언가로 재해석되지 않게 한다.
- **키 형식 검증이 곧 경로 탈출 방지**다. `ValidKey` 정규식(2/2/64hex+확장자)을 통과하지
  못하면 백엔드에 도달하지 못한다.
- 업로드는 로그인 필요, 조회는 공개. 리포트 본문이 공개물이라 비로그인 독자도 이미지를
  볼 수 있어야 한다. URL(=해시)을 모르면 열거할 수 없다.
- Docker에서 `MEDIA_DIR`은 **named volume**(`quant_port_media`)이어야 한다. writable
  layer에 두면 재기동마다 사라진다 — import temp와 정반대 성격이다.
- CDN/객체 스토리지가 붙으면 `MEDIA_PUBLIC_BASE_URL`만 채우면 URL이 그쪽을 가리킨다.

### 아직 없는 것

- **참조 해제된 이미지 GC 없음.** 발행하지 않고 떠난 초안의 업로드는 남는다. 내용 해시라
  중복은 안 쌓이지만, 정리 잡이 필요해지는 시점이 온다.
- 사용자별 업로드 쿼터 없음(파일당 5MB 상한만 있음).
- 리사이즈·썸네일 없음. 원본을 그대로 저장/서빙한다.
