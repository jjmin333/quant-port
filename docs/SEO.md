## 문구

전역 메타는 실제 기능과 어긋나 있었다 — `"여러 증권사 계좌를 하나로 통합하는 투자 플랫폼"`.
토스 계좌 연동은 제거됐고 지금은 **직접 입력 + 잔고 화면 OCR**이다. 즉 **없는 기능을
검색 결과에 광고하고 있었다.**

세 안을 놓고 B를 적용했다.

| 안 | title | 성격 |
|----|-------|------|
| A | Quant Port — 보유·관심·목표가 투자 기록 관리 | 기능 나열 |
| **B (적용)** | **Quant Port — 흩어진 투자 기록을 한곳에** | 사용자 문제 |
| C | Quant Port — 주식 포트폴리오 관리 서비스 | 카테고리 |

**B를 고른 이유**: 기능 이름이 아니라 사용자가 겪는 상태("흩어져 있다")를 말한다 —
`lib/menu-copy.ts`의 emptyDescription이 이미 쓰는 톤이고, 이 서비스가 실제로 해결하는
것이 통합이 아니라 **모으기**다.

## 이번에 잡은 함정 둘 (Next 메타 병합)

Next의 메타 병합은 **얕은 병합이고 같은 키는 통째로 덮인다.** 여기서 두 번 물렸다.

1. **루트에 `alternates.canonical: "/"`를 두면 안 된다.** 자기 canonical을 적지 않은
   모든 화면이 홈을 정규 주소라고 말하게 된다 — 구글에게 "이 사이트엔 문서가 하나뿐"이라고
   말하는 것과 같다. canonical은 화면마다 `pageMetadata({ path })`로 붙인다.
2. **`opengraph-image.tsx`(파일 규칙)가 붙여 주는 og:image는 화면이 `openGraph`를
   직접 적는 순간 같이 지워진다.** 실측으로 확인했다 — 처음 구현에서 `/news/domestic`과
   `/market`에 og:image가 통째로 없었다(홈만 있었다). 그래서 `OG_BASE`/`TWITTER_BASE`에
   `images`를 넣고 화면마다 펼쳐 넣는다.

# 2차 — 노출 개선 (2026-09-08)

0~4번(Cloudflare 301 · 네이버 인증 · GSC 도메인 속성 · 사이트맵 제출)을 마친 뒤,
**실제로 색인될 수 있는 상태인지 실측**한 결과에서 출발했다.

## 출발점 — 크롤러가 보던 것은 사이드바뿐이었다

Googlebot UA로 받아 태그를 걷어낸 `/news/domestic` 전문이 이랬다.

```
◆ QUANT PORT 순위 실시간 차트 … 커뮤니티 리포트 투자 리포트   ← 사이드바(2번 반복)
⭐ 내 종목  🕐 최신순  🔥 인기순  🚨 속보 0
국내 뉴스 불러오는 중…   표시할 뉴스가 없습니다.
```

색인 대상 8페이지가 전부 이 상태였고, 텍스트의 대부분이 **모든 페이지에 똑같이
들어가는 내비게이션**이었다 — 구글이 보기엔 거의 같은 문서 8장.

**그리고 1차에서 넣은 `Disallow: /api/`가 이걸 고착시키고 있었다.** 구글은
렌더링 중 페이지가 부르는 fetch에도 robots.txt를 적용한다. 화면 내용을 전부
`/api/v1/...`에서 받아오는 이 앱에서 그 경로를 막으면, **구글 렌더러가 페이지를
열어도 데이터를 못 받아 영원히 「불러오는 중…」을 본다.** BE 레이트 리밋을
아끼려던 판단이 콘텐츠 색인 전체와 맞바꾼 셈이라 되돌렸다.

**네이버는 그것만으로도 부족하다** — Yeti는 자바스크립트를 사실상 돌리지 않는다.
국내 검색 노출을 원하면 서버가 글자를 찍어 내보내는 수밖에 없다.

## 한 일

1. **robots.txt** — 공개 조회 API 9개 접두어를 `Allow`로 되살렸다. 나머지
   `/api/`는 계속 막는다(Google은 Disallow/Allow 중 **더 긴 쪽**을 따른다).
2. **서버 렌더링** — `research-api.server.ts` · `news-api.server.ts`.
   - 쿠키를 **일부러 안 보낸다**. 보내면 응답이 사용자마다 달라져 캐시가 쪼개지고,
     개인화된 응답이 공용 캐시에 앉아 남에게 나갈 위험이 생긴다. 필요한 것은
     비로그인 방문자가 보는 화면 — 크롤러가 보는 것과 정확히 같다.
   - `revalidate`로 접어 크롤러가 몇 번을 오든 BE 호출은 주기당 한 번이다
     (뉴스 300초 · 리포트 목록 60초 · 상세 300초 · 사이트맵 600초).
   - 실패는 삼킨다 — **SEO용 선반입 때문에 화면이 죽으면 안 된다.**
   - 클라이언트는 마운트 뒤 자기 세션으로 한 번 더 받아 덮되, **화면을 비우지
     않는다**(`background` 모드). 그냥 `setLoading(true)`를 하면 서버가 찍어 준
     글이 스피너로 지워졌다가 돌아와 미리 그린 보람이 없다.
   - 뉴스는 **주소에 정렬·검색 파라미터가 없을 때만** 미리 받는다(`lib/news-ssr.ts`).
     파라미터가 붙으면 서버가 받아 둔 목록은 틀린 목록이다. 크롤러는 언제나 맨
     주소로 오므로 이 조건 때문에 크롤러를 놓치지 않는다.
3. **`/reports/[id]` 리포트별 메타** — 제목·본문 발췌·canonical.
   **`visibility !== "public"`이거나 철회·숨김이면 `noindex`**. 「링크 공개
   (unlisted)」를 색인하면 작성자가 고른 설정을 우리가 뒤집는 것이 된다.
4. **사이트맵에 리포트 상세 포함** — 공개·비철회·비숨김만. 여기서는 진짜
   `updatedAt`을 알아 `lastmod`가 거짓말이 아니다.
5. **JSON-LD** — 리포트 상세에 `Article`(작성자가 없으면 `author`를 아예 뺀다 —
   사이트 이름을 넣으면 저자를 지어내는 셈), 공개 페이지에 `BreadcrumbList`.
6. **약관·개인정보처리방침** (`/legal/terms`, `/legal/privacy`) — 투자 정보는
   **YMYL**이라 운영 주체와 약관이 보이는 사이트인지가 품질 평가에 직접 들어간다.

## 안 한 것과 그 이유

- **실적 페이지 SSR** — 하지 않았다. 이 화면의 기본 조회 구간은 `오늘..오늘`인데
  **오늘(09-08) 국내 실적은 0건**이다(실측). 국내 실적은 2·5·8·11월에 몰려서
  1년의 대부분이 비어 있고, 클라이언트의 초기 키에 맞춰 SSR하면 크롤러에게
  **빈 표**를 내보내게 된다. 실적의 진짜 노출 수단은 SSR 배관이 아니라
  **종목별·월별 URL**(예: `/earnings/005930`)이라는 별개의 화면 설계다.
- **홈(`/`) SSR** — 지수 티커와 대시보드는 실시간 값이라 서버가 찍어도 금방
  낡는다. 홈이 노리는 것은 브랜드 검색이고 거기서는 title·description·JSON-LD가
  본문보다 크게 작용한다.
